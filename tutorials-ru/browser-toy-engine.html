Игрушечный браузерный движок на Rust

Что такое браузерный движок?

Первая статья серии начинается с важного определения: браузерный движок (browser engine) — та часть браузера, которая получает (fetch) веб-страницы, переводит их и выводит на экран. Движок не следует путать с «chrome» браузера: chrome — это «рама» браузера — вкладки, адресная строка, кнопки и всё вокруг веб-страницы. Firefox и SeaMonkey используют один движок Gecko с двумя разными chrome.

Серия Брубека строит небольшой движок, поддерживающий только HTML и CSS, — «игрушку» для учёбы, а не конкурента Blink/Gecko/WebKit/Servo с миллионами строк кода (даже простая версия Servo тогда насчитывала десятки тысяч строк). Но структура та же, и понять её просто:

text   HTML ──> Parse ──> DOM
   CSS  ──> Parse ──> Style Rules        ──> Style ──> Layout ──> Paint ──> пиксели
                    DOM + Style Rules ──/

Карта из 7 частей

Серия проходит по по-настоящему настоящему маршруту этапов рендера, каждая часть — новый этап конвейера рендеринга (rendering pipeline):

  • HTML и CSS: пишутся две маленькие грамматики, превращающие текстовый ввод в древовидные структуры. HTML-парсер — в структуру DOM; CSS-парсер — в набор правил из selectors + declarations.
  • Style и сопоставление селекторов: правила CSS сочетаются с DOM, чтобы у каждого узла появился «свой стиль» — начальный cascade и логика сопоставления селекторов.
  • Boxes и блочная модель: узлы DOM превращаются в прямоугольные «боксы»; блочная модель (margin/border/padding/content) — как она определена в CSS.
  • Layout: алгоритм блочной раскладки наподобие того, что есть в настоящих движках, — вычисление позиции и размера каждого бокса в двумерном пространстве.
  • Paint: в конце вычисленные боксы «раскрашиваются» на простой поверхности рисования (без поддержки изображений, только сплошные фоновые цвета).

Седьмая часть перечисляет «дальнейшую работу»: текст, изображения, формы и интерактивность — то есть место, где игрушка заканчивается и начинается настоящая работа.

Дизайн-решения

У Брубека есть несколько умных выборов, дающих взгляд «человека движков»:

  • Разделение (splitting): когда селектор применяется к узлу, но часть дочерних узлов попадает под другие стили, конвейер вместо усложнения разбивает узел на несколько «виртуальных боксов» (например, для display: block с первым inline-ребёнком).
  • Опора на CSS 2.1: модель раскладки строится на спецификации CSS 2.1, а не на фантазии — применяются даже формулы схлопывания полей (margin collapse).
  • Логика стыковки этапов: выходные данные каждого этапа — входные данные следующего; всё на простых структурах данных (struct в Rust), которые можно отлаживать до конца.
rust// Раскладка: каждый бокс получает абсолютную прямоугольную позицию
pub fn layout(&self, containing_block: Dimensions) -> LayoutBox {
    let mut layout_box = self.build_layout_tree();
    layout_box.layout(containing_block);
    layout_box
}

fn layout(&mut self, containing_block: Dimensions) {
    match self.box_type {
        BlockNode(_) => self.layout_block(containing_block),
        InlineNode(_) => self.layout_inline(containing_block),
        AnonymousBlock => self.layout_block(containing_block),
    }
}

Практический сценарий

Чтобы показать работу, каждая часть сопровождается маленьким примером. Так понимаешь, что нужно для «рендера» двух веб-страниц: страница без CSS — почти «потоп», а с одним простым style всё встаёт на места. Построенный движок выдаёт текстовый/простой вывод, но для инструмента исследования алгоритмов рендера его вполне достаточно.

О «браузере» и «движке»: эта серия — лучшая точка входа в то, как работают современные браузеры, — от понимания конвейера рендера до роли моста между HTML и CSS. Продолжения этого пути: книга Web Browser Engineering и проекты вроде Servo, либо более короткие туториалы по созданию браузера на Python.

Чему вы научитесь

  • Различие движка браузера и chrome, и место конвейера рендера в настоящих браузерах.
  • Реализацию простого парсера HTML и CSS без зависимостей.
  • Блочную модель и блочную раскладку по спецификации CSS 2.1.
  • Полный конвейер рендера: parse → style → layout → paint.

Итог

Поразительно и поучительно, что примерно с тысячей строк кода можно написать движок, рендерящий HTML и CSS. Эта серия отлично показывает: в браузере нет особой «магии» — лишь несколько маленьких аккуратных слоёв, каждый из которых можно построить самому.

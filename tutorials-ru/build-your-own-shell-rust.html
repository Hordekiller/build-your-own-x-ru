Собственный шелл на Rust

Что такое шелл?

Шелл — это программа, которая позволяет управлять компьютером; в основном это делается путём упрощения запуска других программ. Но сам по себе шелл — не интерактивная программа! Большинство пользователей взаимодействует с шеллом через «эмулятор терминала»:

Эмулятор терминала (который обычно называют просто «терминал») — «это просто окно». Он запускает текстовую программу, которой по умолчанию является ваш шелл входа. Когда вы печатаете в окне, терминал рисует символы в окне и точно так же отправляет их в stdin шелла; а вывод stdout и stderr шелла идёт в терминал, и терминал рисует его в окне. — пользователь geirha

В этом уроке мы напишем собственный шелл и запустим его в обычном терминале. (Примеры не работают в Rust Playground, так как там нет поддержки stdin или длительных процессов.)

Точка старта — простейший возможный шелл

Достаточно нескольких строк Rust: stdin().read_line блокируется, пока пользователь не нажмёт Enter, и затем записывает весь ввод (вместе с новой строкой) в нашу строку; через input.trim() убираем новую строку и выполняем команду:

rustfn main() {
    let mut input = String::new();
    stdin().read_line(&mut input).unwrap();

    let command = input.trim();   // read_line добавляет завершающую новую строку

    Command::new(command)
        .spawn()
        .unwrap();
}

После cargo run вы увидите курсор, ждущий ввода; наберите ls — содержимое папки будет выведено, и шелл завершится.

Несколько команд и аргументы

Чтобы шелл не завершался после одной команды, помещаем код в loop и вызываем wait для каждого дочернего процесса, чтобы новое приглашение не печаталось до завершения текущего процесса (а чтобы отличать ввод пользователя от вывода процессов, печатаем >, который нужно явно сбросить через stdout().flush()):

rustfn main() {
    loop {
        print!("> ");
        stdout().flush();

        let mut input = String::new();
        stdin().read_line(&mut input).unwrap();

        let command = input.trim();

        let mut child = Command::new(command).spawn().unwrap();
        child.wait();   // пока эта команда не завершится, следующую не принимай
    }
}

Теперь ls -a падает, потому что наш шелл не знает об аргументах и пытается запустить программу с именем ls -a. Решение: разбиваем ввод по пробелам; всё до первого пробела — имя команды, остальное — аргументы:

rustlet mut parts = input.trim().split_whitespace();
let command = parts.next().unwrap();
let args = parts;

let mut child = Command::new(command)
    .args(args)
    .spawn()
    .unwrap();
child.wait();

Встроенные команды — почему cd нужно реализовывать в шелле

Есть команды, которые шелл не может поручить другому процессу: они касаются внутреннего состояния самого шелла и должны быть реализованы им. Самый известный пример — cd (вот две ссылки с объяснением: почему cd должна быть встроенной и почему тем не менее существует программа cd). Реализация:

rustmatch command {
    "cd" => {
        // если путь не задан, по умолчанию '/'
        let new_dir = args.peekable().peek().map_or("/", |x| *x);
        let root = Path::new(new_dir);
        if let Err(e) = env::set_current_dir(&root) {
            eprintln!("{}", e);
        }
    },
    command => {
        let mut child = Command::new(command).args(args).spawn().unwrap();
        child.wait();
    }
}

Обработка ошибок и команда exit

Если ввести несуществующую команду, прежние шеллы падали. Здесь ошибка печатается достойно, и пользователю разрешается ввести другую команду. Поскольку «плохая команда» до этого была лёгким способом закрыть шелл, добавляем ещё одну встроенную команду — exit:

rust"exit" => return,
command => {
    let child = Command::new(command).args(args).spawn();
    match child {
        Ok(mut child) => { child.wait(); },
        Err(e) => eprintln!("{}", e),  // достойная обработка неудачного ввода
    };
}

Каналы (пайпы)

Работать в шелле без каналов трудно. | говорит шеллу направить вывод первой команды во ввод второй; например, ls | grep Cargo: (1) ls выдаёт список файлов, (2) шелл передаёт этот список в grep, (3) grep фильтрует и печатает только файлы, содержащие «Cargo». Базовая реализация: разбиваем ввод по " | " (с peekable, чтобы знать, что мы на последней команде), и вывод каждого процесса становится stdin следующего:

rustlet mut commands = input.trim().split(" | ").peekable();
let mut previous_command = None;

while let Some(command) = commands.next() {
    let mut parts = command.trim().split_whitespace();
    let command = parts.next().unwrap();
    let args = parts;

    match command {
        "cd" => { /* ... */ previous_command = None; },
        "exit" => return,
        command => {
            let stdin = previous_command
                .map_or(Stdio::inherit(),
                        |output: Child| Stdio::from(output.stdout.unwrap()));

            let stdout = if commands.peek().is_some() {
                Stdio::piped()       // за этой командой есть ещё одна
            } else {
                Stdio::inherit()     // последняя команда; в stdout шелла
            };

            let output = Command::new(command)
                .args(args).stdin(stdin).stdout(stdout).spawn();

            match output {
                Ok(output) => { previous_command = Some(output); },
                Err(e) => { previous_command = None; eprintln!("{}", e); },
            };
        }
    }
}

if let Some(mut final_command) = previous_command {
    final_command.wait();  // дождаться завершения последней команды
}

Итоги

Меньше чем за 100 строк Rust мы построили шелл, пригодный для многих повседневных задач, но у настоящего шелла возможностей гораздо больше. Онлайн-руководство bash от GNU со списком возможностей шелла — отличная отправная точка. Автор подчёркивает, что это учебный проект, и везде, где простота конфликтовала с надёжностью, он выбирал простоту. Код этого шелла (bubble-shell) доступен на github.com/JoshMcguigan/bubble-shell.

Создание системы, похожей на Kafka, с нуля — пошаговое руководство

Если вы хотите по-настоящему понять архитектуру Kafka и готовы сделать это, реализовав её упрощённую версию, вы попали по адресу. Вместо того чтобы просто копировать код, мы будем постепенно строить «SimpleKafka» и на каждом шаге разбираться в каждом компоненте. Такой подход даёт глубокое понимание распределённых систем обмена сообщениями.

Краткое описание рабочего процесса

Этот пошаговый подход позволяет вам детально собрать и понять каждый компонент Kafka-подобной системы — с этапа 1 по этап 7:

  • Настройка структуры проекта
  • Создание основного протокольного слоя
  • Реализация интеграции с ZooKeeper
  • Построение слоя хранения
  • Построение брокера (Broker)
  • Разработка клиентской библиотеки
  • Создание API высокого уровня для производителя и потребителя
  • Тестирование системы

Этапы с 1 по 7

Для этапов с 1 по 7 следуйте подробной пошаговой статье на Medium и параллельно держите под рукой GitHub-репозиторий. Такое сочетание поможет вам планомерно продвигаться по каждому разделу.

Собирая каждый компонент вручную, вы получите глубокое понимание архитектуры Kafka и дизайнерских решений, стоящих за ней. Эти знания будут бесценны при работе с настоящей Kafka или при проектировании собственных распределённых систем.

Тестирование системы

1. Сборка проекта с Maven:

bashmvn clean package

2. Запуск ZooKeeper

bash# Запуск ZooKeeper с конфигурацией по умолчанию
zkServer start

# Если не сработало — попробуйте так:
zookeeper-server-start /usr/local/etc/kafka/zookeeper.properties

# Или создайте простой файл конфигурации:
echo "tickTime=2000" > zk.cfg
echo "dataDir=/tmp/zookeeper" >> zk.cfg
echo "clientPort=2181" >> zk.cfg
zookeeper-server-start zk.cfg

3. Запуск нескольких экземпляров брокера

bash# Терминал 1 — брокер 1
java -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.broker.SimpleKafkaBroker 1 localhost 9091 2181

# Терминал 2 — брокер 2
java -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.broker.SimpleKafkaBroker 2 localhost 9092 2181

# Терминал 3 — брокер 3
java -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.broker.SimpleKafkaBroker 3 localhost 9093 2181

4. Производство сообщений

bashjava -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.client.SimpleKafkaProducer localhost 9091 test-topic

5. Потребление сообщений

bashjava -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.client.SimpleKafkaConsumer localhost 9091 test-topic 0

Ключевые концепции, на которые стоит обратить внимание при тестировании

1. Партиционирование топиков и репликация (Replication)

Наблюдайте, как топик разбивается на партиции и как эти партиции распределяются между брокерами.

2. Механика лидера и ведомых

  • Как брокер становится лидером
  • Как ведомые реплицируют данные от лидера
  • Что происходит, когда лидер выходит из строя и выбирается новый

3. Роль контроллера (Controller)

  • Контроллер выбирается через ZooKeeper
  • Отвечает за управление распределением партиций
  • Управляет отказами брокеров
  • Если текущий контроллер выходит из строя, выбирается новый

4. Постоянство сообщений (Message Persistence)

  • Структура сегмента журнала (Log Segment)
  • Как сообщения добавляются последовательно (append)
  • Как индексы сопоставляют смещения (offset) с позициями в файле

5. Протокол «клиент–брокер»

  • Формат бинарного протокола
  • Паттерны запрос/ответ (Request/Response)
  • Как клиенты находят нужных брокеров и подключаются к ним

О проекте

Проект «SimpleKafka» — учебная упрощённая реализация распределённой системы обмена сообщениями, похожей на Kafka, написанная на Java с Maven. В его структуру входят пакеты для брокера, клиента и слоёв хранения; он интегрируется с ZooKeeper для выбора лидера и управления контроллером. Репозиторий опубликован под лицензией MIT.

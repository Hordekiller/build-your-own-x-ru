Angular Scopes: скоупы в своём фреймворке

1. Зачем Scope и Digest?

В AngularJS всё вращается вокруг двух концепций: Scope (модель, к которой привязан DOM) и Digest (механизм, который находит изменения модели и переносит их в DOM). В этой части мы строим их с нуля — с той же тщательностью и подходом, что и настоящий Angular, но в среде тестирования чистого JavaScript (без DOM).

Метод обучения: статья написана в стиле TDD: сначала описывается поведение (тест), затем приводится его реализация. Если будете следовать за кодом, тесты запустите на Mocha/Jasmine.

2. Watcher'ы: подписка на изменения

Через $watch регистрируется функция-«наблюдатель», возвращающая текущее значение. Через $digest мы вызываем этих наблюдателей и, если значение изменилось, уведомляем слушателей:

jsScope.prototype.$watch = function(watchFn, listenerFn) {
  const watcher = {
    watchFn: watchFn,
    listenerFn: listenerFn || function() {},
    last: initWatchVal, // специальное значение «ещё не вычислено»
  };
  this.$$watchers.push(watcher);
};

Scope.prototype.$digest = function() {
  let dirty;
  do {
    dirty = this.$$digestOnce();
  } while (dirty);
};

Scope.prototype.$$digestOnce = function() {
  let self = this;
  let dirty = false;
  this.$$watchers.forEach(function(watcher) {
    const newValue = watcher.watchFn(self);
    const oldValue = watcher.last;
    // уведомляем только если изменилось
    if (newValue !== oldValue) {
      watcher.last = newValue;
      watcher.listenerFn(newValue, oldValue, self);
      dirty = true;
    }
  });
  return dirty;
};

Важный момент: цикл do…while означает «пока найдено изменение, проверяй снова» — потому что слушатель сам может изменить scope. Это поведение называется dirty checking.

3. Предупреждение о цикле: защита от бесконечности

Если слушатель постоянно меняет значение, digest никогда не закончится. В Angular есть ограничение TTL ($digestTtl):

jsScope.prototype.$digest = function() {
  let ttl = 10; // максимум проходов
  let dirty;
  do {
    dirty = this.$$digestOnce();
    if (dirty && !(ttl--)) {
      throw 'Десять проходов digest без достижения стабильности!';
    }
  } while (dirty);
};

4. Сравнение по значению (Value-based) и глубокое (Deep)

В Angular можно указать, будет ли сравнение «по значению» (по умолчанию для чисел и строк) или «по ссылке» (для объектов), или даже глубоким (рекурсивное сравнение структуры объекта). Статья реализует все три режима с помощью $$watchValueFn и алгоритма $$areEqual:

jsScope.prototype.$watch = function(watchFn, listenerFn, valueEq) {
  const watcher = {
    watchFn: watchFn,
    listenerFn: listenerFn || function() {},
    valueEq: !!valueEq, // глубокое или ссылочное сравнение
    last: initWatchVal,
  };
  this.$$watchers.push(watcher);
};

Scope.prototype.$$digestOnce = function() {
  let self = this;
  let dirty = false;
  this.$$watchers.forEach(function(watcher) {
    const newValue = watcher.watchFn(self);
    const oldValue = watcher.last;
    // сравнение по подходящему критерию
    if (!self.$$areEqual(newValue, oldValue, watcher.valueEq)) {
      watcher.last = (watcher.valueEq ? _.cloneDeep(newValue) : newValue);
      watcher.listenerFn(newValue, oldValue, self);
      dirty = true;
    }
  });
  return dirty;
};

Scope.prototype.$$areEqual = function(newValue, oldValue, valueEq) {
  if (valueEq) {
    return _.isEqual(newValue, oldValue); // глубокое сравнение
  }
  return newValue === oldValue; // ссылочное сравнение
};

Почему deep watch опасен? Потому что глубокое сравнение для каждого watcher'а дорого, и с большими структурами digest замедляется, — Angular платит эту цену только если вы его используете.

5. Невычисленные значения и NaN: хранение «беззначного» значения

Важная деталь: при первом digest слушатель должен обязательно вызваться, даже если начальное значение watchFn равно undefined. Angular решает это специальным значением initWatchVal (тот же приём заставляет корректно работать и NaN, потому что NaN не равен сам себе):

jsfunction initWatchVal() {} // значение-«маркер», не равное ничему

6. $eval, $evalAsync и $apply

Заключительная часть статьи добавляет три важных способа выполнения кода в scope:

jsScope.prototype.$eval = function(expr, locals) {
  // немедленное выполнение функции/выражения в контексте scope
  return expr(this, locals);
};

Scope.prototype.$evalAsync = function(expr) {
  // отложенное выполнение: в очереди $applyAsyncQueue, до следующего digest
  if (!this.$$phase && !this.$$asyncQueue.length) {
    setTimeout(function() {
      // когда очередь пуста, выполняем digest
      if (scope.$$asyncQueue.length) scope.$digest();
    }, 0);
  }
  this.$$asyncQueue.push({ scope: this, expr: expr });
};

Scope.prototype.$apply = function(expr) {
  // выполнение кода «вне цикла Angular» (например, в событии браузера)
  try {
    this.$eval(expr);
  } finally {
    this.$digest(); // digest выполняется всегда
  }
};

Причина существования $apply: любое изменение, происходящее вне «зоны» Angular (например, в setTimeout или внешней библиотеке), не видно digest'у; $apply вводит его в цикл.

7. Итоги

  • Scope — простая модель + механизм watch/digest, который можно расширять; вся «магия» Angular исходит из этого цикла dirty checking.
  • Ссылочное сравнение против глубокого — это баланс между точностью и скоростью.
  • Следующие части серии посвящены дочерним scope, событиям и директивам (directives).

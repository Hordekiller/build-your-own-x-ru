Custom Renderer для React

Оригинальный источник: «Building a Custom React Renderer»

1. О докладе

Софи Альперт в этом докладе с React Conf 2019 показывает, как с помощью официального пакета react-reconciler построить собственный React-рендерер. Она оставляет «мозг» React (алгоритм сравнения и планирования) как есть и меняет только «руки»: HostConfig, который говорит, как узлы создаются, обновляются и удаляются. Результат её работы — React DOM Mini: полноценный рендерер для DOM, запускающий настоящие React-компоненты.

Совет: код доклада и учебный проект доступны в репозитории zaki-yama-labs, а похожие примеры (такие как react-dom-mini) — на GitHub; отлично подходит для практики.

3. Главная идея: что такое HostConfig?

Каждый React-рендерер состоит из двух частей: reconciler (решает, «что изменить») и renderer («применяет» решение). Интерфейс между ними — именно HostConfig. В докладе Софи создаёт рендерер, передавая объект с функциями в react-reconciler:

js// точка входа: создание reconciler с нашими функциями платформы
let reconciler = ReactReconciler({
  // «мутационный режим»: наша среда похожа на DOM (есть appendChild и removeChild)
  supportsMutation: true,

  // создание узла в целевой среде
  createInstance(type, props, rootContainerInstance, hostContext, internalInstanceHandle) {
    const el = document.createElement(type);
    return el;
  },

  // создание текстового узла
  createTextInstance(text) {
    return document.createTextNode(text);
  },

  // присоединение узлов
  appendChildToContainer(container, child) {
    container.appendChild(child);
  },
  appendChild(parent, child) {
    parent.appendChild(child);
  },
  appendInitialChild(parent, child) {
    parent.appendChild(child);
  },

  // удаление и перемещение
  removeChildFromContainer(container, child) {
    container.removeChild(child);
  },
  removeChild(parent, child) {
    parent.removeChild(child);
  },
  insertInContainerBefore(container, child, before) {
    container.insertBefore(child, before);
  },
  insertBefore(parent, child, before) {
    parent.insertBefore(child, before);
  },

  // обновление: вычисление и применение изменений props
  prepareUpdate(instance, type, oldProps, newProps) {
    // вычисли разницу; если её нет — верни null
    return computeDiff(oldProps, newProps);
  },
  commitUpdate(instance, updatePayload, type, oldProps, newProps) {
    applyUpdatePayload(instance, updatePayload);
  },

  // контрактные вспомогательные функции
  shouldSetTextContent() { return false; },
  getChildHostContext() { return {}; },
  getPublicInstance(instance) { return instance; },
  getRootHostContext() { return {}; },
  prepareForCommit() {},
  resetAfterCommit() {},
  finalizeInitialChildren() {},
});

Когда эти функции готовы, рендерер запускается двумя вызовами: createContainer (создание корня) и updateContainer (начало рендера):

jsconst root = reconciler.createContainer(domElement, false);
reconciler.updateContainer(<App />, root, null, () => console.log('рендер завершён'));

4. Почему этот доклад важен?

  • Вы поймёте, как React Native, React Three Fiber и десятки других рендереров работают с одним общим «мозгом».
  • Настоящий код продакшен-рендереров (например, react-dom) очень сложен; минимальная версия сохраняет только концептуальный слой.
  • После этого видео прочитайте статью «Learn you some custom React renderers» с HackerNoon, чтобы увидеть ту же работу в письменном виде.

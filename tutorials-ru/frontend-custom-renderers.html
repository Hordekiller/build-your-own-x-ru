Нестандартные рендереры: React за пределами DOM

1. Архитектура рендереров React

React состоит из двух полностью раздельных слоёв: reconciler (мозг: сравнение виртуального дерева и обнаружение изменений — тот самый алгоритм diff и построение Fiber) и renderer (руки: применение этих изменений в целевой среде; DOM, native, canvas и т. д.). По сути,

js// пакет react-reconciler — это фабрика:
// если передать host config конкретной платформы, получается рендерер
const Reconciler = require('react-reconciler');
const reconciler = Reconciler(HostConfig);

HostConfig — мост: набор функций, задающих контракт «как разговаривать с целевой средой» — например, createInstance, appendChild и commitUpdate. Именно этот интерфейс включает React DOM для браузера, React Native для мобильных устройств и React ART для SVG.

2. Начальная структура рендерера

Статья запускает проект через create-react-app, затем создаёт собственный рендерер в src/renderer/index.js и использует его в index.js вместо react-dom. Сначала — просто пустой корпус:

jsconst CustomRenderer = {
  render(element, renderDom, callback) {
    // element: корневой элемент (компонент App)
    // renderDom: DOM-элемент хоста
    // callback: вызывается после окончания рендера
    console.log('render called', element, renderDom, callback);
  },
};

export default CustomRenderer;

Теперь установим react-reconciler и создадим экземпляр reconciler с HostConfig. Сначала createContainer для создания корневого fiber, затем updateContainer для начала сравнения и рендера:

jsconst Reconciler = require('react-reconciler');
const HostConfig = {
  /* функции платформы определяются здесь */
};

const reconcilerInstance = Reconciler(HostConfig);

const CustomRenderer = {
  render(element, renderDom, callback) {
    const isAsync = false; // синхронный режим рендера
    const container = reconcilerInstance.createContainer(renderDom, isAsync);
    const parentComponent = null; // у корневого fiber нет родителя
    reconcilerInstance.updateContainer(element, container, parentComponent, callback);
  },
};

export default CustomRenderer;

3. Реализация HostConfig

Сердце учебника — реализация функций HostConfig для DOM. Полная версия статьи делает это в трёх частях; краткое изложение основных функций:

jsconst HostConfig = {
  createInstance(type, props, rootContainerInstance, hostContext, internalInstanceHandle) {
    // создание DOM-элемента по типу
    const el = document.createElement(type);
    return el;
  },

  createTextInstance(text, rootContainerInstance, hostContext, internalInstanceHandle) {
    return document.createTextNode(text);
  },

  appendChildToContainer(container, child) {
    container.appendChild(child);
  },

  appendChild(parent, child) {
    parent.appendChild(child);
  },

  appendInitialChild(parent, child) {
    parent.appendChild(child);
  },

  removeChildFromContainer(container, child) {
    container.removeChild(child);
  },

  removeChild(parent, child) {
    parent.removeChild(child);
  },

  insertInContainerBefore(container, child, before) {
    container.insertBefore(child, before);
  },

  insertBefore(parent, child, before) {
    parent.insertBefore(child, before);
  },

  prepareUpdate(instance, type, oldProps, newProps, rootContainerInstance, currentHostContext) {
    // вычисляет разницу props и возвращает её
    const changedProps = {};
    for (const key in Object.assign({}, oldProps, newProps)) {
      if (oldProps[key] !== newProps[key]) changedProps[key] = newProps[key];
    }
    return Object.keys(changedProps).length > 0 ? changedProps : null;
  },

  commitUpdate(instance, updatePayload, type, oldProps, newProps, finishedWork) {
    // применяет изменения на реальном узле
    for (const key in updatePayload) {
      if (key === 'children') continue;
      instance[key] = updatePayload[key];
    }
  },

  commitTextUpdate(textInstance, oldText, newText) {
    textInstance.nodeValue = newText;
  },

  shouldSetTextContent(type, props) {
    return false;
  },

  getChildHostContext() { return {}; },
  getPublicInstance(instance) { return instance; },
  getRootHostContext() { return {}; },
  prepareForCommit() {},
  resetAfterCommit() {},
  finalizeInitialChildren() {},
};

Процесс построения в статье идёт шаг за шагом: сначала работает первоначальный рендер, затем обновление props (требующее prepareUpdate + commitUpdate) и в конце добавляется управление удалением и перемещением узлов. На каждом шаге вы получаете характерную ошибку от reconciler — и она же служит вашей подсказкой.

4. Результат: вот и всё!

После завершения HostConfig наше React-приложение запускается с собственным рендерером: компоненты управляют своим state, reconciler вычисляет изменения, а наши функции применяют их в DOM.

Дополнительно: теперь понятно, почему React Native работает, не меняя мозг React: тот же reconciler с другим HostConfig (нативный мост). И почему существуют такие рендереры, как React Three Fiber для WebGL: нужен лишь новый HostConfig.

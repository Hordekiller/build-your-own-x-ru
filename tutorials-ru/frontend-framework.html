Пишем свой front-end фреймворк

Оригинальный источник: «Create Your Own Frontend Framework»

1. О книге

Эта обучающая книга шаг за шагом показывает, как строится front-end фреймворк (вроде Vue или React). В конце книги у нас есть фреймворк под названием «Кодоминар» с тремя основными возможностями:

  • Шаблонизация (Templating): поглощение декларативного HTML вместе с директивами;
  • Управление state: автоматическое обновление интерфейса при изменении модели;
  • Virtual DOM: эффективное обновление DOM с diff.

Любопытная деталь: каждая глава книги — объяснение концепции + полный код + интерактивное упражнение, а в конце итоговый код можно взять из репозитория GitHub.

2. Первый шаг: проектирование движка шаблонов (Templating)

Наш фреймворк должен «компилировать» HTML. Сначала определим понятие «компонент»: функция, принимающая props и возвращающая виртуальное дерево; затем работа движка шаблонов — превращение этого дерева в DOM:

js// компонент: функция, принимающая props и возвращающая виртуальное дерево
function HelloWorld({ name }) {
  return {
    type: 'h1',
    props: { class: 'title' },
    children: ['Привет, ' + name + '!'],
  };
}

// компиляция виртуального дерева в DOM
function compileTree(vnode) {
  if (typeof vnode === 'string') {
    return document.createTextNode(vnode);
  }

  const el = document.createElement(vnode.type);

  for (const key in vnode.props) {
    // наши директивы (события) начинаются с префикса on
    if (key.startsWith('on')) {
      el.addEventListener(key.slice(2).toLowerCase(), vnode.props[key]);
    } else {
      el.setAttribute(key, vnode.props[key]);
    }
  }

  vnode.children.forEach((child) => el.appendChild(compileTree(child)));
  return el;
}

const root = document.getElementById('app');
root.appendChild(compileTree(HelloWorld({ name: 'мир' })));

Этот движок шаблонов может поддерживать и простые HTML-директивы (циклы и условия): в книге вы познакомитесь с «директивами шаблонов», которые добавляются к сырому HTML.

3. Второй шаг: управление state и перерисовка

Чтобы интерфейс обновлялся при изменении state, нужны «центральное состояние» и механизм подписки. Книга выбирает простой подход, похожий на Vue, — реактивный объект:

jsfunction createReactiveState(initialState, listeners = []) {
  return new Proxy(initialState, {
    set(target, key, value) {
      target[key] = value;
      // любое изменение = уведомление всех слушателей (перерисовка)
      listeners.forEach((listener) => listener());
      return true;
    },
  });
}

// пример: каждое изменение state вызывает перерисовку дерева
const state = createReactiveState({ count: 0 }, () => renderApp());

function renderApp() {
  const vnode = Counter();
  diff(previousVnode, vnode, root); // diff и patch (следующий шаг)
}

Обратите внимание: использование Proxy означает, что каждый доступ к state отслеживается, и фреймворк знает, какие компоненты зависят от какой части state, — та же идея реактивности во Vue 3.

4. Третий шаг: Virtual DOM и diff

Заключительная часть книги реализует алгоритм diff, чтобы между рендерами применялись только реальные изменения. Книга вводит три главные функции:

js// 1) построение прежнего и нового виртуальных деревьев
// 2) их сравнение (diff) → результат: список изменений
// 3) применение изменений в DOM (patch)

function diff(oldVnode, newVnode, parentDom) {
  if (oldVnode === undefined) {
    // новый узел — создаём и добавляем
    parentDom.appendChild(compileTree(newVnode));
  } else if (oldVnode.type === newVnode.type) {
    // тот же тип — обновляем атрибуты и детей (рекурсивно)
    updateProps(parentDom.childNodes[0], oldVnode, newVnode);
    const max = Math.max(oldVnode.children.length, newVnode.children.length);
    for (let i = 0; i < max; i++) {
      diff(oldVnode.children[i], newVnode.children[i], parentDom.childNodes[0]);
    }
  } else {
    // другой тип — полная замена узла
    parentDom.replaceChild(compileTree(newVnode), parentDom.childNodes[0]);
  }
}

5. Итоги книги

  • Фреймворк состоит из трёх независимых слоёв: движок шаблонов, система state и Virtual DOM.
  • Реактивность через Proxy проще и точнее dirty checking; именно поэтому новые фреймворки (Vue 3, MobX) пошли этим путём.
  • В конце книги вы можете расширить свой фреймворк: добавить события, локальные компоненты и серверный рендер.
Дополнительно: книга полностью интерактивна — примеры редактируются и запускаются прямо в браузере. Для старта достаточно начального знакомства с JavaScript.

Понимаем JSX: как он устроен

1. Введение: JSX — это не магия

Многие разработчики считают JSX «новым языком», но на самом деле JSX — всего лишь синтаксический сахар (syntax sugar) для вызова функции. Когда вы пишете:

jsconst el = <div className="foo">Привет, мир!</div>;

Транспилятор (Babel или TypeScript) превращает это ровно в такой простой вызов:

jsconst el = createElement("div", { className: "foo" }, "Привет, мир!");

Вся работа JSX — это вызов функции с упорядоченными аргументами. Поэтому, чтобы «построить JSX», достаточно реализовать собственный createElement.

Примечание: секрет успеха этой конструкции в том, что JSX не привязан к DOM; именно единый формат позволяет React Native, Preact, Vue и десяткам других фреймворков использовать один и тот же синтаксис.

2. Создаём свой createElement

Автор опубликовал полную реализацию вместе с учебным проектом на GitHub. Сначала мы пишем фабрику узлов (древовидной структуры):

jsfunction createElement(type, props, ...children) {
  // итоговое значение children может быть массивом узлов и строк
  const el = document.createElement(type);
  // копирование props на элемент
  for (const key in props) {
    ...
  }
  return el;
}

С этой функцией работает любой JSX-код, даже компоненты! Ведь createElement сам может решить, что делать, если тип — функция:

jsfunction createElement(type, props, ...children) {
  // если type — функция (компонент), вызываем её с props
  if (typeof type === "function") {
    return type({ ...props, children });
  }
  // в противном случае создаём обычный элемент
  ...
}

3. Обновление: сравнение и patch

Пока что мы умеем рендерить один раз. Для обновления проще всего удалить старое дерево и построить новое, но это неэффективно. Лучший путь — повторный рендер и сравнение узлов (diff):

jsfunction update(oldNode, newNode) {
  if (!oldNode || oldNode.nodeName !== newNode.nodeName) {
    // тип узла изменился: полная замена
    oldNode.replaceWith(newNode);
    return newNode;
  }
  // построить новых детей и сравнить с прежними
  ...
}

Это главная идея всех фреймворков; React и Preact лишь делают алгоритм diff умнее (например, используют ключи/key и сравнивают только изменившиеся атрибуты).

4. Итоги

  • JSX = синтаксический сахар: каждое JSX-выражение превращается в вызов функции; чтобы его использовать, достаточно реализовать эту функцию.
  • Компонент = функция: когда typeof type === "function", рендерер вызывает компонент, а не создаёт DOM-элемент.
Дополнительно: Джейсон Миллер — автор Preact, построенного на той же идее (лёгкий React без привязки к спецификации); изучение исходников Preact — отличное продолжение этого пути.

Давай напишем Redux сами

1. Подход статьи: разработка через тесты (TDD)

Отличительная черта этого учебника — Redux строится тест-ориентированным методом: для каждой API-функции сначала пишется тест (который падает), затем реализация, пока тест не станет зелёным. Этот подход и проясняет логику Redux, и укрепляет правильную привычку писать код. Инструменты: Jest для тестов и Babel для модулей.

Совет: если вы не знакомы с TDD, эта статья — отличный учебный пример: цикл «красный ← зелёный ← рефакторинг» практикуется на реальном проекте.

2. Проектирование API глазами потребителя

Прежде чем писать код, определим, какой API видит потребитель Redux, — это настоящий API Redux:

jsconst store = createStore(reducer, initialState);

store.getState();              // чтение текущего state
store.dispatch(action);        // отправка action (обязательно объекта с type)
store.subscribe(listener);     // подписка на изменения; возвращает функцию отписки

Затем тесты закрепляют именно этот контракт. Например, первые тесты:

jsdescribe('createStore', () => {
  it('возвращает начальное состояние', () => {
    const reducer = (state = {}, action) => state;
    const store = createStore(reducer, { count: 0 });
    expect(store.getState()).toEqual({ count: 0 });
  });

  it('обновляет state при dispatch action', () => {
    const reducer = (state = { count: 0 }, action) => {
      if (action.type === 'ADD') return { count: state.count + action.payload };
      return state;
    };
    const store = createStore(reducer);
    store.dispatch({ type: 'ADD', payload: 5 });
    expect(store.getState()).toEqual({ count: 5 });
  });
});

3. Реализация createStore

Чтобы тесты стали зелёными, реализуем createStore — классическое исполнение с замыканием:

jsexport function createStore(reducer, initialState) {
  let state = initialState;
  const listeners = [];

  function getState() {
    return state;
  }

  function dispatch(action) {
    // reducer должен быть чистой функцией: возвращает новый state, не мутирует
    state = reducer(state, action);
    listeners.forEach((listener) => listener());
    return action;
  }

  function subscribe(listener) {
    listeners.push(listener);
    return function unsubscribe() {
      const index = listeners.indexOf(listener);
      if (index > -1) listeners.splice(index, 1);
    };
  }

  return { getState, dispatch, subscribe };
}

Обратите внимание: dispatch не возвращает значение, от которого кто-то зависит; все потребители должны читать state через getState и узнавать об изменениях через subscribe.

4. Тест subscribe и отписки

jsit('слушатели вызываются при dispatch', () => {
  const store = createStore((s = 0, a) => (a.type === 'INC' ? s + 1 : s));
  const spy = jest.fn();
  store.subscribe(spy);
  store.dispatch({ type: 'INC' });
  expect(spy).toHaveBeenCalledTimes(1);
});

it('unsubscribe удаляет слушателя', () => {
  const store = createStore((s = 0, a) => (a.type === 'INC' ? s + 1 : s));
  const spy = jest.fn();
  const unsubscribe = store.subscribe(spy);
  unsubscribe();
  store.dispatch({ type: 'INC' });
  expect(spy).not.toHaveBeenCalled();
});

5. Комбинирование reducer'ов

Следующая часть статьи — combineReducers, снова начинающаяся с теста: каждый ключ state управляется независимым reducer'ом, и вместе они образуют дерево state. Деталь реализации: при выполнении каждому reducer'у передаётся только его часть state (не весь state), чтобы никакой reducer не знал о других частях:

jsexport function combineReducers(reducers) {
  return function combinedReducer(state = {}, action) {
    const nextState = {};
    for (const key of Object.keys(reducers)) {
      nextState[key] = reducers[key](state[key], action);
    }
    return nextState;
  };
}

6. Итоги и уроки

  • Весь Redux сводится к функции createStore и функции combineReducers — остальные инструменты это удобство, а не необходимость.
  • Метод TDD отлично подходит этому проекту, потому что контракты (contract) с самого начала ясны: state, action и reducer.
  • После этого учебника откройте настоящий код Redux на GitHub: его createStore.js лишь немного полнее нашей версии (например, валидаторы для защиты от ошибочного использования).

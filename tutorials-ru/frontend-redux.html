Redux: понимание и реализация

Оригинальный источник: «How to Build Redux»

1. Зачем строить Redux с нуля?

В своей основе Redux содержит всего три концепции: единый объект state, чистую функцию (reducer), изменяющую state, и функцию dispatch, доставляющую actions в reducer. Весь его API (getState, subscribe, combineReducers, createStore и т. д.) лишь обслуживает эти три идеи. Построив его сами, мы поймём, что в нём нет ни магии, ни особой сложности.

2. Первая реализация: ручной магазин

Статья начинается с «магазина» (store) ручной работы: объекта state и функции, которая его меняет. Затем мы хотим, чтобы все изменения state проходили только одним путём — это и есть dispatch:

js// сначала без Redux: разрозненный и беспорядочный state
let state = { count: 0 };
function increment() { state = { ...state, count: state.count + 1 }; }

// теперь с actions: каждое изменение state имеет описательный объект
function dispatch(action) {
  state = reducer(state, action);
}

// а reducer — чистая функция: (предыдущий state + action) → новый state
function reducer(state = { count: 0 }, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + 1 };
    case 'DECREMENT':
      return { ...state, count: state.count - 1 };
    default:
      return state;
  }
}

dispatch({ type: 'INCREMENT' }); // state.count: 1
dispatch({ type: 'DECREMENT' }); // state.count: 0

Обратите внимание: reducer никогда не мутирует state (возвращает новый объект) и для одинакового входа всегда даёт одинаковый выход — именно эта «чистота» делает возможными тестируемость и воспроизводимость (time-travel).

3. Создаём createStore

Теперь упакуем эту идею: функция createStore, хранящая state в замыкании (closure) и возвращающая стандартный API Redux:

jsfunction createStore(reducer, initialState) {
  let state = initialState;
  const listeners = [];

  return {
    // чтение текущего state
    getState() {
      return state;
    },

    // отправка action: reducer выполняется, state меняется, слушатели уведомляются
    dispatch(action) {
      state = reducer(state, action);
      listeners.forEach((listener) => listener());
      return action;
    },

    // регистрация слушателя изменений; возвращается функция отписки
    subscribe(listener) {
      listeners.push(listener);
      return () => {
        const index = listeners.indexOf(listener);
        if (index > -1) listeners.splice(index, 1);
      };
    },
  };
}

// использование
const store = createStore(reducer);
store.subscribe(() => console.log('count:', store.getState().count));
store.dispatch({ type: 'INCREMENT' });

Это ровно то, чем является Redux, — вся библиотека сводится к этому; остальные инструменты (bindActionCreators, applyMiddleware и т. д.) — лишь удобство для разработчика.

4. Комбинирование reducer'ов

В реальном приложении state велик; вместо одного гигантского reducer'а у нас несколько маленьких, каждый из которых управляет только своей частью, а combineReducers собирает их вместе:

jsfunction combineReducers(reducers) {
  return (state = {}, action) => {
    const nextState = {};
    for (const key in reducers) {
      // каждый reducer обновляет только свой ключ
      nextState[key] = reducers[key](state[key], action);
    }
    return nextState;
  };
}

const appReducer = combineReducers({
  count: counterReducer,
  user: userReducer,
});

5. Связь с React

Заключительная часть статьи показывает, как подключить этот store к React-компоненту: через store.subscribe обновляется рендер, а через store.dispatch отправляются actions:

jsclass Counter extends React.Component {
  componentDidMount() {
    // любое изменение state → повторный рендер
    this.unsubscribe = store.subscribe(() => this.forceUpdate());
  }

  componentWillUnmount() {
    this.unsubscribe();
  }

  render() {
    return (
      <div>
        <span>{store.getState().count}</span>
        <button onClick={() => store.dispatch({ type: 'INCREMENT' })}>+</button>
      </div>
    );
  }
}

Пакет react-redux выполняет ровно это подключение (с оптимизацией выборок через селекторы) за вас.

6. Итоги

  • Redux = единый state + чистый reducer + dispatch; весь каркас укладывается в несколько десятков строк простого JavaScript.
  • Чистота reducer'а — самое важное свойство: она даёт предсказуемость, тестируемость и воспроизводимость (с инструментами вроде Redux DevTools).

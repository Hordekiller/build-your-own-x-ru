Virtual DOM: как React рисует быстро

⚙ Язык: JavaScript 📁 Front-end фреймворк / библиотека 🌐 Русская страница 🔗 Оригинальный источник
Оригинальный источник: «How to write your own Virtual DOM»
↗ Перейти к оригинальному уроку فارسی — Персидская версия EN — English version

1. Зачем Virtual DOM?

Прямая манипуляция DOM для обновления интерфейса и медленна, и дорога; идея Virtual DOM: сначала построй дерево UI в лёгком представлении данных (простых JavaScript-объектах, не DOM), затем вычисли разницу между старой и новой версией и примени в реальном DOM только эти различия. Именно это делают React и Vue.

2. Виртуальные узлы и h()

Каждый виртуальный узел — простой объект с тремя полями: тип элемента, свойства (props) и дети (children). Функция h() (вроде React.createElement) создаёт их:

js// структура виртуального узла
const vnode = {
  tag: 'div',             // имя тега
  props: { className: 'card' },  // атрибуты
  children: [/* виртуальные узлы или текст */],
};

// вспомогательная функция h — создание узла с упорядоченными аргументами
function h(tag, props, ...children) {
  return { tag, props, children: children.flat() };
}

const tree = h('div', { id: 'app' },
  h('h1', {}, 'Привет!'),
  h('p', {}, 'Это виртуальное дерево.'),
);

3. Рендер: превращение виртуального дерева в DOM

Функция render рекурсивно превращает узлы в настоящие элементы; строковые дети становятся текстовыми узлами:

jsfunction render(vnode) {
  if (typeof vnode === 'string') {
    return document.createTextNode(vnode);
  }

  const el = document.createElement(vnode.tag);

  // установка атрибутов (props)
  for (const key in vnode.props) {
    el.setAttribute(key, vnode.props[key]);
  }

  // рекурсивный рендер детей
  vnode.children.forEach((child) => el.appendChild(render(child)));

  return el;
}

4. diff и patch: сравнение и применение изменений

Сердце статьи — функция diff: она сравнивает прежнее виртуальное дерево с новым и применяет минимальные изменения в реальном DOM. Три главных случая:

jsfunction diff(oldVnode, newVnode, parentNode) {
  // случай 1: одно из деревьев — текст, другое — элемент: полная замена
  if (typeof oldVnode === 'string' || typeof newVnode === 'string') {
    if (oldVnode !== newVnode) {
      // простое обновление текста
      parentNode.childNodes[0].nodeValue = newVnode;
    }
    return;
  }

  // случай 2: теги разные — строим весь новый узел и заменяем
  if (oldVnode.tag !== newVnode.tag) {
    const newEl = render(newVnode);
    parentNode.replaceChild(newEl, parentNode.childNodes[0]);
    return;
  }

  // случай 3: тег тот же — обновляем атрибуты
  const domNode = parentNode.childNodes[0];
  updateProps(domNode, oldVnode.props, newVnode.props);

  // а затем сравниваем детей (рекурсивно)
  const max = Math.max(oldVnode.children.length, newVnode.children.length);
  for (let i = 0; i < max; i++) {
    // ... diff на каждой паре детей с childNodes[i]
  }
}

function updateProps(domNode, oldProps, newProps) {
  // удаление убранных атрибутов
  for (const key in oldProps) {
    if (!(key in newProps)) domNode.removeAttribute(key);
  }
  // обновление новых атрибутов
  for (const key in newProps) {
    if (oldProps[key] !== newProps[key]) {
      domNode.setAttribute(key, newProps[key]);
    }
  }
}

Деталь дизайна: сравнение идёт по индексу детей, а не по типу, — поэтому перемещение элементов для этого простого алгоритма «подозрительно»; именно здесь в React/Vue вступают key, делающие diff умнее.

5. Полный пример

jsconst app = document.getElementById('app');

// первоначальный рендер
const v1 = h('div', { className: 'box' },
  h('h2', {}, 'Заголовок'),
  h('button', { onclick: () => update() }, 'Нажми'),
);
app.appendChild(render(v1));

function update() {
  // новое виртуальное дерево (например, после изменения state)
  const v2 = h('div', { className: 'box big' },
    h('h2', {}, 'Новый заголовок'),
    h('button', { onclick: () => update() }, 'Нажми'),
  );
  // в DOM применяются только различия
  diff(v1, v2, app);
}

В этом примере меняется атрибут className и текст h2; остальные узлы (например, button) вообще не трогаются — вот та эффективность, которую даёт Virtual DOM.

6. Итоги

  • Virtual DOM — просто структура данных; её сила в алгоритме diff, который понимает, «что изменилось».
  • Вся реализация умещается примерно в 100 строк чистого JavaScript.
  • React и Vue используют ту же идею и вместо индекса выполняют более умное сравнение с key.

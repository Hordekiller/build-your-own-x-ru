Шелл на Go: свой Unix-шелл

Что такое шелл?

«Шелл — это основной интерфейс пользователя с операционной системой: вы даёте ему команды и получаете соответствующий вывод». Gnome и Windows тоже являются графическими шеллами, но когда технические люди говорят о шелле, обычно имеют в виду текстовый (например, Bash и Zsh). Работает всё просто: введите ls и получите список папки.

Юникс очень прост; только нужно быть гением, чтобы понять его простоту. — Деннис Ритчи

Шелл — лишь небольшая часть операционной системы (и по сравнению с ядром — лёгкая часть!); автор надеется, что в конце вы, как и он, удивитесь, как просто писать шелл, когда понимаешь лежащие в основе концепции.

Цикл ввода

Наша клавиатура — это устройство стандартного ввода (os.Stdin). Каждое нажатие Enter создаёт новую строку (\n), и мы читаем эту строку:

gofunc main() {
    reader := bufio.NewReader(os.Stdin)
    for {
        fmt.Print("> ")
        input, err := reader.ReadString('\n')
        if err != nil {
            fmt.Println(err)
        }
        err = execInput(input)
        if err != nil {
            fmt.Println(err)
        }
    }
}

Побочное замечание: ошибки лучше писать в os.Stderr (например, через log.Println), но это добавляет временные метки и выглядит многословно; можете исправить позже.

Выполнение команд

Сначала убираем символ новой строки с конца ввода, затем готовим команду через exec.Command и выполняем её через cmd.CombinedOutput() (успешный вывод идёт в stdout, ошибки — в stderr, но и то и другое собирается в переменную stdoutStderr):

gofunc execInput(input string) error {
    // удаление символа новой строки
    input = strings.TrimSuffix(input, "\n")

    // подготовка команды к выполнению
    cmd := exec.Command(input)

    // выполнение и получение вывода
    stdoutStderr, err := cmd.CombinedOutput()
    if err != nil {
        return err
    }
    fmt.Printf("%s", stdoutStderr)
    return nil
}

Первый тест: go run main.go, приглашение > и ls работает! Вывод берётся из программы, а CTRL-C, как и в любой другой программе, закрывает шелл.

Аргументы — история ls -l

text> ls -l
exec: "ls -l": executable file not found in $PATH

Провал! Потому что наш шелл пытается запустить программу с именем ls -l; на самом деле программа называется просто ls, а -l — это аргумент, который разбирает сама программа. Поэтому разбиваем ввод по каждому пробелу:

go// отделение команды от аргументов
args := strings.Split(input, " ")

// передача программы и аргументов по отдельности
cmd := exec.Command(args[0], args[1:]...)

Теперь имя программы находится в args[0], аргументы — в последующих индексах, и ls -l работает как ожидалось.

Встроенные команды — почему не работает cd?

Посмотрите на cd /, а затем на ls, который выдаёт список текущей папки! Ответ прост: «настоящей» программы cd не существует — это возможность, встроенная в шелл (чтобы он мог менять состояние самого себя). Поэтому добавляем switch по первому аргументу:

go// проверка встроенных команд
switch args[0] {
case "cd":
    // с пустым путём переход в домашнюю папку пока не поддерживается
    if len(args) < 2 {
        return errors.New("path required")
    }
    if err := os.Chdir(args[1]); err != nil {
        return err
    }
    return nil
case "exit":
    os.Exit(0)
}
text> cd /
> ls
Applications
Library
Network
System
...

«Да, этот вывод больше похож на содержимое моего корневого каталога» — и всё! Простой шелл написан.

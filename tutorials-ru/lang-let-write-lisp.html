Давай напишем Lisp на JavaScript

О статье

Эта старая, но золотая статья строит интерпретатор Lisp методом «снизу вверх» (bottom-up): сначала представление данных и примитивные функции, затем parser и только потом closures и окружение. По стилю она похожа на статью «Little Lisp» Мэри Роуз Кук, но с большими подробностями об окружении и closures.

Пошаговая структура

1) Определение структур данных (Number, Lambda, Symbol и т.д.); 2) примитивные функции глобального окружения (определение через define); 3) parser из двух функций tokenize/parse; 4) главный eval, поддерживающий и числа/имена, и определение lambda; 5) apply для вызова функции и построения локального окружения.

js// Построение локального окружения для вызова функции
function callLispFunction(closure, args) {
  var localEnv = cloneEnvironment(closure.env);   // дочернее окружение определения
  closure.params.forEach(function (param, i) {
    localEnv[param] = args[i];                    // связывание параметров
  });
  // тело функции вычисляется в локальном окружении
  return evalLisp(closure.body, localEnv);
}

Ключевые концепции, которые вы узнаете

1) closure: функция должна хранить своё окружение определения (Env in closure) — именно это придаёт Lisp смысл; 2) последовательное вычисление (begin) и условное (if); 3) рекурсия в функциях; 4) разница между eval и apply. Примеры в статье включают факториал и функцию map.

Сравнение с другими учебниками

По сравнению с «Little Lisp» эта статья показывает дочернее «вложенное» окружение (nested scope) более явно — то есть даёт лучшее понимание цепочечной области видимости, которая лежит в основе любого языка.

Итоги

Познавательный и весёлый день: построение интерпретатора Lisp с нуля на JavaScript с акцентом на окружение и closures. Позже можно добавить quote, макросы и GC, чтобы приблизить интерпретатор к «mal».

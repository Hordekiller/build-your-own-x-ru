Little Lisp на JavaScript

История: интерпретатор меньше чем в 150 строках

Мэри Роуз Кук этой статьёй доказала, что построить интерпретатор Lisp на JavaScript (языке браузеров) очень просто: весь проект — 4 функции: tokenize, parse, evaluate и apply. На выходе — язык с функциями, переменными, условиями и рекурсией.

Шаг первый: tokenize

Превращает входную строку в массив токенов — например, (begin (define r 10) (* pi (* r r))) превращается в ['(', 'begin', '(', 'define', 'r', '10', ')', '(', '*', 'pi', ...]. Используется простая потоковая обработка через объект memory.

Шаг второй: parse

Превращает токены в дерево (вложенные списки). Если токен «(» — рекурсивно строится внутренний список до «)»:

jsfunction parse(tokens, memory) {
  if (typeof memory === 'undefined') {
    memory = { index: 0 };
  }

  if (tokens[memory.index] === '(') {           // начало списка
    memory.index++;
    let list = [];
    while (tokens[memory.index] !== ')') {
      list.push(parse(tokens, memory));         // рекурсия для следующего элемента
    }
    memory.index++;                             // пропускаем ')'
    return list;
  } else if (tokens[memory.index] === ')') {
    throw new Error('лишняя скобка!');
  } else {
    const atomicToken = tokens[memory.index];
    memory.index++;
    return atomicToken;                         // атом: имя или число
  }
}

Шаг третий: evaluate

Теперь вычисляется дерево: если атом «число» — его значение; если «имя» — значение переменной из окружения; если «список» — первый элемент функция, остальные аргументы (apply). Понятия closure и вложенного окружения пишутся прямо здесь:

jsfunction evaluate(ast, environment) {
  if (typeof environment === 'undefined') {
    environment = globalEnvironment;
  }

  // атомы
  if (typeof ast === 'string') {
    if (parseInt(ast) === NaN) {
      return lookupVariable(ast, environment);   // имя переменной
    } else {
      return parseInt(ast);                       // число
    }
  }

  // список: оператор и аргументы
  const operator = ast[0];
  const operands = ast.slice(1);

  if (operator === 'define') {
    const variable = operands[0];
    const value = evaluate(operands[1], environment);
    environment[variable] = value;                // определение переменной
    return value;
  }

  if (operator === 'begin') {
    // последовательное выполнение всех выражений
    return operands.reduce((last, exp) => evaluate(exp, environment), undefined);
  }

  const closure = evaluate(operator, environment);
  const args = operands.map(o => evaluate(o, environment));
  return closure.apply(null, args);
}

Что вы узнаете?

1) Понятие AST и рекурсии; 2) окружение (environment) как таблицу имя→значение; 3) closure через apply; 4) что Lisp — это «рекурсивные правила», а не что-то магическое. Для определения функции lambda достаточно тех же паттернов.

Итоги

Лучшая отправная точка для построения интерпретатора на JavaScript: коротко, читаемо и полно (переменные + функции). Если захотите потом локальные переменные, closures и GC — смотрите «Crafting Interpreters» или «mal».

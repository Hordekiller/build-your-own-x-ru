О серии

Руслан Спивак серией «Давайте построим простой интерпретатор» (более 20 частей) написал один из самых популярных учебников по созданию интерпретаторов: от калькулятора 3 + 5 до языка с переменными, условиями, циклами и даже раздельными Lexer и Parser. Каждая часть посвящена одной концепции.

Пошаговые концепции

1) Token и Lexer (превращение текста в токены); 2–3) Parser и AST; 4) Interpreter (вычисление); 5–7) приоритет операторов и грамматики (синтаксические диаграммы); 8–9) обработка составных токенов; 10–11) выполнение вычислений и простой синтаксис; 12–13) переменные и присваивание; 14–15) обзор и ошибки; 16–20) условия, циклы, логические операторы и финальная структура.

Пример кода: лексер (части 1 и 2)

python# Типы токенов
INTEGER, PLUS, MINUS, MUL, DIV = 'INTEGER', 'PLUS', 'MINUS', 'MUL', 'DIV'

class Interpreter:
    def __init__(self, text):
        self.text = text
        self.pos = 0
        self.current_token = None

    def get_next_token(self):
        # lexer: пропуск пробелов, распознавание чисел/операторов
        while self.pos < len(self.text) and self.text[self.pos].isspace():
            self.pos += 1
        if self.pos >= len(self.text):
            return Token(EOF, None)
        tok = self.text[self.pos]
        if tok.isdigit():
            start = self.pos
            while self.pos < len(self.text) and self.text[self.pos].isdigit():
                self.pos += 1
            return Token(INTEGER, int(self.text[start:self.pos]))
        if tok == '+': self.pos += 1; return Token(PLUS, '+')
        ...
        raise Exception('ошибка разбора')

Почему эта серия популярна?

Тексты Руслана очень подробны: диаграммы грамматики, таблицы и объяснения в духе «лучше так не делать, потому что…». Особенно просто изложены темы AST и visitor pattern. В конце вы сможете расширять свой язык, определяя ключевые слова (BEGIN…END).

Итоги

Если вы хотите без каких-либо предпосылок о компиляторах интуитивно построить интерпретатор — это лучшая отправная точка. Параллельно можно читать «lispy» Норвига, чтобы сравнить два стиля (Lisp-интерпретатор и императивный интерпретатор).

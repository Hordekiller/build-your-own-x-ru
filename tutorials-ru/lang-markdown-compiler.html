Почему Markdown — это язык?

Хотя у Markdown лёгкий синтаксис, он делает ровно то же, что любой другой язык: превращает одну текстовую структуру в другое представление. В этом учебнике текст Markdown — вход, а HTML — выход, и снова проходится путь создания маленького компилятора — от lexer до генератора.

Красота проекта в том, что сложность языка очень мала, поэтому можно сосредоточиться на архитектуре компилятора: разбор, сопоставление с простым AST и единообразная генерация выхода.

Архитектура: парсеры и генераторы

Подход beezwax использует две независимые части. Парсер распознаёт фрагменты Markdown и превращает каждую строку во внутренний «результат» (заголовок, абзац или жирный текст). Генератор превращает эти результаты в HTML. Разделение двух этапов делает добавление новых правил простым маленьким методом.

Пример кода: простое правило для заголовка

Самое простое правило — распознать строку, начинающуюся с #. Если вдуматься, каждое правило должно лишь сказать: «если я вижу такой шаблон, какую структуру построить»:

ruby# Правило заголовка: строка, начинающаяся с одного-шести #
def parse_heading(line, output)
  if line =~ /^(#{1,6})\s+(.*)$/
    level = $1.length
    text  = $2
    # Преобразование во внутреннюю структуру (AST)
    output << { type: :heading, level: level, text: render_inline(text) }
    true
  else
    false
  end
end

# Шаблон bold: *текст* в <strong>текст</strong>
def render_inline(text)
  text.gsub(/\*(.*?)\*/) { "<strong>#{$1}</strong>" }
end

Этот метод называется «префиксный разбор»: для каждой строки шаблоны пробуются по порядку, и первый успешный отвечает за генерацию структуры.

Шаги полной реализации

После правил заголовка и абзаца приходит очередь того, что требует «состояния»: блоки списков и code fence, у которых есть первая и последняя строка. Здесь вы учитесь важности отслеживания текущего состояния обхода (например, «я внутри списка»).

В конце пишется html_renderer, превращающий AST в итоговый HTML, а вывод снабжается escape-функциями для безопасности (защита от инъекции HTML).

Lisp-интерпретатор на OCaml

О серии

Макс Бернстайн (работавший над настоящими компиляторами вроде OCaml и CMUCL) в этой серии статей строит интерпретатор Lisp на OCaml, добавляя в каждой статье новый кусок: от парсинга и простого eval до closures, макросов и разговора о рантаймах. Код каждой статьи лежит в отдельной папке (part1 … partN).

Структура статей

По порядку: (1) базовый интерпретатор — массивы, списки, простой eval; (2) символы и переменные; (3) функции lambda и вложенные окружения; (4) продвинутые конструкции вроде let*; (5) обработка ошибок и представление «Error» в рантайме; (6) макросы; (7) завершение оптимизацией и обсуждением рантайма. Каждая статья сопровождается backend'ом на Python или OCaml и тестом сравнения поведения.

Пример кода: eval с pattern matching

ocaml(* Вычисление: используем абстрактный тип данных *)
let rec eval env = function
  | Atom a -> List.assoc a env      (* найди переменную в окружении *)
  | Number n -> Number n
  | List (Atom "quote" :: [x]) -> x (* quote: без вычисления *)
  | List (Atom "if" :: [c; t; f]) ->
      if eval env c = Bool true then eval env t else eval env f
  | List (Atom "lambda" :: [params; body]) ->
      (* closure: тело + параметры + окружение *)
      Closure (params, body, env)
  | List (Atom fn :: args) ->
      let f = eval env (Atom fn) in
      let args' = List.map (eval env) args in
      apply f args'
  | _ -> raise (Invalid_argument "некорректное выражение")

Интересные моменты

1) Сравнение разных стратегий представления (например, использование Stone против Variant); 2) разбор того, почему передача параметров call-by-value корректно работает для окружений; 3) в конце — обсуждение стоимости рантайма и оптимизации, знакомящее с инженерным взглядом на настоящие компиляторы.

Итоги

Если вам нравится OCaml, эта серия — лучший выбор: хорошая глубина понимания, полный код и сравнение с другими реализациями. После неё можно перейти к «Write a C Compiler» Норы Сандлер, чтобы ощутить вес настоящего компилятора.

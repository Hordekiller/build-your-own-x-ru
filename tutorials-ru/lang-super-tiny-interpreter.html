Супер-маленький интерпретатор на JavaScript

Естественное дополнение супер-маленького компилятора

В «Супер-маленьком компиляторе» мы научились превращать AST в код C; но есть и другой вариант: вместо генерации кода взять тот же AST и сразу его «вычислить» — это и есть интерпретатор. Этот проект делает ровно это и делает ощутимым сравнение «компиляция» против «интерпретация».

Структура

Как и в версии-компиляторе, код аккуратно разделён: tokenizer и parser (тот же Lisp-подобный вход), затем evaluator, который при обходе AST хранит переменные в таблице окружения. Сердце интерпретатора — функция interpret:

jsfunction interpret(ast, env = {}) {
  const node = ast;

  switch (node.type) {
    case 'NumberLiteral':
      return Number(node.value);

    case 'CallExpression': {
      // вычисляем каждый аргумент
      const args = node.arguments.map(arg => interpret(arg, env));

      // ищем функцию в окружении (например, add или subtract)
      const func = env[node.callee];
      if (typeof func !== 'function')
        throw new Error(`функция ${node.callee} не определена`);

      return func.apply(null, args);
    }
    default:
      throw new Error(`неизвестный узел: ${node.type}`);
  }
}

// Начальное окружение: базовые функции
const env = {
  add: (a, b) => a + b,
  subtract: (a, b) => a - b,
};

const ast = parse(tokenize('(add 2 (subtract 4 2))'));
console.log(interpret(ast, env)); // 4

Почему важно сравнить эти два?

Между двумя проектами есть тонкая разница: компилятор выдаёт «код» (сам не исполняет), интерпретатор выдаёт «значение» (исполняет сам). Вы понимаете понятия «стоимость исполнения» и «стоимость компиляции» — а в реальном мире JIT (компиляция на лету) — это комбинация обоих.

Учебный совет

Если хотите расширить окружение (переменные, if, lambda) — это лучшая отправная точка: код короткий, и interpret можно развивать под каждый новый узел. Тот же паттерн — таблица символов и рекурсивное вычисление — в реальных интерпретаторах (например, jlox) реализован в большом масштабе.

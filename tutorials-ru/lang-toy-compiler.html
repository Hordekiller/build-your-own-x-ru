Почему Flex и Bison

Прежде чем писать всё вручную, полезно узнать, как работают классические инструменты «сборки компиляторов». Flex генерирует лексер (превращает входной текст в токены), а Bison — генератор парсеров (разбирает грамматику методом LALR). Этот урок с помощью этих двух инструментов строит маленький компилятор с ассемблерным выходом.

Часть первая: файл Flex

Файл лексера в Flex определяется тремя секциями: declarations (объявления), rules (правила) и дополнительный код. Например, определение математических токенов:

Flex%{
#include "parser.hpp"   // определение токенов из Bison
%}

DIGIT   [0-9]
NUMBER  {DIGIT}+

%%

"+"   { return PLUS; }
"-"   { return MINUS; }
"*"   { return MULT; }
"/"   { return DIV; }
{NUMBER}  { yylval.num = atoi(yytext); return NUMBER; }
[ \t\n]   { /* пропуск пробелов */ }
.         { yyerror("недопустимый символ"); }

%%

int yywrap(void) { return 1; }   // конец файла

Часть вторая: грамматика Bison

Скорость Bison — в грамматиках LALR; здесь определяется простое выражение, и при каждой свёртке (reduction) генерируется соответствующий ассемблерный код — именно эта связь «грамматика↔код» и есть суть работы компилятора:

Bison%token NUMBER
%left PLUS MINUS
%left MULT DIV

%%

expr: expr PLUS expr   { $$ = gen_add($1, $3); }
    | expr MULT expr   { $$ = gen_mult($1, $3); }
    | NUMBER           { $$ = gen_number($1); }
    ;

%%

int gen_number(int n) {
  printf("push %d\n", n);   // ассемблерный код для числа
  return 0;
}

Обратите внимание: выражения получают приоритет через %left — это эквивалентно тому, что делается в ручном парсере методом Пратта.

Итог

Эта статья показывает, что старые инструменты (Flex/Bison) до сих пор — лучший способ быстро собрать lexer/parser; если вам нравится «ручное изготовление», позже идите к таким урокам, как acwj, — но если вы просто хотите собрать компилятор, этот способ — самая быстрая точка старта.

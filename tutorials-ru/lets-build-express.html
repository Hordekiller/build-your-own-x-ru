Создадим Express с нуля — пишем свою библиотеку

Оригинальный источник: «lets-build-express»

Зачем эта серия?

Многие разработчики путаются в том, как работает next или в каком порядке идут маршруты в express. Построив саму библиотеку express, мы получим крепкое понимание — да и удовольствие немалое! Список глав (глава 6 — обработка ошибок — ещё пишется):

  • Строим абстракции express
  • Маршруты из коробки
  • Реализация функции next
  • Развитие объекта Response
  • Реализация send / json на response
  • Обработка ошибок (WIP)

Глава 1 — Создание абстракций express

В этой главе строятся абстракции, необходимые для создания express, и в конце у нас есть совсем крошечная библиотека, сопоставляющая один маршрут. Сначала наш файл express.js — с export:

javascriptexports = module.exports = createApplication;

function createApplication() {
    var app = function(req,res,next) {
    };

    return app;
}

Ничего фантастического: просто экспортируем функцию createApplication. Эта функция создаёт ссылку на функцию app и возвращает её. Именно возвращаемый app пользователь получает при вызове express(). Заметьте: функция ожидает req, res и даже next (req — входящий запрос, res — объект http-ответа, а next — особая express-функция; кто передаёт их — увидим позже). Раз пользователь получает наш app при express(), нужно добавить объекту app нужные методы вроде get и post.

Application.js — где живут методы вроде get и use

Создаём файл app.js, предоставляющий методы get, post и т.д. Начальный код:

javascriptvar app = exports = module.exports = {};

app.init = function() {
    this.cache = {};
    this.engines = {};
    this.settings = {}

    // для хранения роутера приложения
    this._router = undefined;
};

Подход исходного кода express очень прост: используется библиотека methods, возвращающая все HTTP-методы строчными буквами:

javascriptvar methods = require('methods');
var slice = Array.prototype.slice;

methods.forEach(function (method){
    app[method] = function(path) {
        this.lazyrouter()

        var route = this._router.route(path);

        route[method].apply(route, slice.call(arguments, 1));
        return this;
    }
});

Внутри каждого метода сначала вызывается this.lazyrouter() — то есть для приложения создаётся только один Router (а если создан — не создаётся снова):

javascriptapp.lazyrouter = function lazyrouter() {
    if(!this._router) {
        this._router = new Router({})
    }
};
К фрагменту var route = this._router.route(path); route[method].apply(route, slice.call(arguments, 1)); мы вернёмся в этой же главе.

Router.js — логика маршрутизации; один на приложение

javascriptvar proto = module.exports = function(options) {
    var opts = options || {}

    function router(req,res,next) {
        router.handle(req,res,next)
    }

    setPrototypeOf(router, proto)

    /* особое для express; доберёмся в следующих главах */
    router.params = {};
    router._params = [];
    router.caseSensitive = opts.caseSensitive;
    router.mergeParams = opts.mergeParams;
    router.strict = opts.strict;
    router.stack = []; // очень важное свойство

    return router;
};

Важное свойство роутера — stack: сюда уходит конфигурация маршрутов. Функция route позволяет пользователю добавлять в stack конкретные маршруты:

javascriptproto.route = function route(path) {
    var route = new Route(path)

    var layer = new Layer(path,{},route.dispatch.bind(route))

    layer.route = route;

    this.stack.push(layer);

    return route;
};

Для каждого path создаются Route и Layer; layer содержит route и помещается в stack роутера. (Код route.dispatch.bind(route) пока — пустая функция; это следующие главы.)

Route.js — информация о маршруте и нужный слой

javascriptfunction Route(path) {
    this.path = path;
    this.stack = [];

    this.methods = {}
}

Route, как и application, реализует все HTTP-методы:

javascriptmethods.forEach(function(method){
    Route.prototype[method] = function(){
        var handles = flatten(Array.prototype.slice.call(arguments));

        for (var i = 0; i < handles.length; i++) {
            var handle = handles[i];

            if (typeof handle !== 'function') {
                var type = toString.call(handle);
                var msg = 'Route.' + method + '() requires a callback function but got a ' + type
                throw new Error(msg);
            }

            var layer = Layer('/', {}, handle);
            layer.method = method;

            this.methods[method] = true;
            this.stack.push(layer);
        }

        return this;
    };
});

Заметьте: у route тоже свой stack с собственными экземплярами Layer.

Layer.js — путь и ссылка на исполняемую функцию

javascriptmodule.exports = Layer

function Layer(path, options, fn) {
    if (!(this instanceof Layer)) {
        return new Layer(path, options, fn);
    }

    this.handle = fn;
    this.name = fn.name || '<anonymous>';
    this.params = undefined;
    this.path = undefined;
}

Хранит только handle и имя функции.

Возвращаемся к application.js

Теперь понятен прежний неразрешённый фрагмент: после создания lazy router свойства роутера настраиваются вызовом route. Раз у application один роутер, а Route владеет всеми HTTP-методами, эта строка route[method].apply(route, slice.call(arguments, 1)) фактически создаёт в Route Layer, чей handle — переданный аргумент (тот самый обработчик, который должен исполняться при сопоставлении маршрута).

Теперь предоставим application и функцию listen:

javascriptapp.listen = function listen() {
    var server = http.createServer(this);
    return server.listen.apply(server, arguments);
};

Затем завершаем express.js — mixin копирует все методы app.js в функцию app (когда импортируется ./app, блок методов исполняется, и все HTTP-методы готовы):

javascriptvar proto = require("./app")

function createApplication() {
    let app = function(req,res,next) {
        app.handle(req,res,next)
    };

    mixin(app,proto,false);

    app.init();
    return app;
}

Тонкий момент: http.createServer(this) хочет функцию-callback, вызываемую с req и res; this — это app, а app.handle поручает работу роутеру:

javascriptapp.handle = function handle(req, res, callback) {
    var router = this._router;

    router.handle(req, res);
};

Запуск: наше первое приложение

javascriptlet express = require('./src/express')
const app = express()

app.get('/', (req, res) => {
    res.writeHead(200)
    res.write('Hello World');
    res.end();
});


app.listen(3000, () => console.log('Example app listening on port 3000!'))

Чтобы ответ реально доходил, Router должен реализовать handle — автор сначала просто печатает stack: когда запрос / шлётся, вывод выглядит так: [{"name":"bound dispatch","route":{"path":"/","stack":[{"name":"<anonymous>","method":"get"}],"methods":{"get":true}}}] — то есть на / определён get! (Временный подход: кусок, который просто вызывает созданный в route.stack[0] обработчик.) Для исполнения обработчика добавляется Layer.prototype.handle_request:

javascriptLayer.prototype.handle_request = function handle(req,res,next) {
    var fn = this.handle;

    try {
        fn(req, res, next);
    } catch (err) {
        console.error(err)
    }
}

Теперь снова запустите сервер и ударьте по / — наш callback вызывается с текущим запросом и ответом, и «Hello World» отправляется через write и end. (Примечание: res.send у нас пока нет, потому что объект ответа ещё не развит; поэтому не забывайте res.end().)

Глава 2 — Маршруты из коробки

В этой главе handle роутера улучшается, чтобы сопоставлять маршруты с URL запроса. Слои получают функцию match: если путь запроса подходит под паттерн слоя, слой выбирается. Паттерны компилируются в регулярные выражения, чтобы работали и параметры маршрута (вроде /user/:id):

javascriptLayer.prototype.match = function match(path) {
    var match = path.match(this.regexp);
    if (match) {
        this.params = {};
        // звёздочные параметры пути попадают в this.params
    }
    return !!match;
};

javascriptproto.handle = function handle(req, res, out) {
    var self = this;
    var stack = self.stack;
    var path = req.url;

    // Пройди по всем слоям stack, пока не найдётся первое совпадение
    for (var i = 0; i < stack.length; i++) {
        var layer = stack[i];
        if (layer.match(path)) {
            var route = layer.route;
            if (route && route.handle_method(method, req)) {
                // И путь, и метод совпали: выполняем обработчики route
                route.stack[0].handle_request(req, res);
            }
        }
    }
}

К концу главы приложение правильно отвечает на несколько маршрутов (/, /about, ...) и даже маршруты с параметрами, а на неизвестные маршруты выдаёт 404.

Глава 3 — Реализация функции next

Эта глава строит важнейшую концепцию express: цепочку исполнения мидлваров. Программе добавляется метод use для регистрации мидлваров (с путём или без). Функция next передаётся каждому обработчику и передаёт управление «следующему в очереди обработчику». Внутри handle_request исполняется вызов fn(req, res, next), где next означает self.handle_request для следующего слоя:

javascriptfunction next(err) {
    // Найди следующий обработчик в stack роутера и исполни его
    var layer = stack[i++];
    if (!layer) return done(err);

    if (layer.match(path)) {
        layer.handle_request(req, res, next);
    } else {
        next(err); // пропустить
    }
}

Именно здесь видно, почему «порядок регистрации» важен в express: если мидлвар на маршруте /foo зарегистрирован до маршрута /, они исполняются в порядке очереди, и только когда обработчик вызывает next(), переходим к следующему в очереди. Это то самое поведение, которое путает новичков в express.

Глава 4 — Развитие объекта Response

В этой главе основной express-ответ подключается к объекту ответа Node: методы res.status(code) для установки res.statusCode, res.set(field, value) для установки заголовка через res.setHeader и res.get(field) для чтения из res.getHeader. Для цепочечности (chainable) эти методы возвращают return this:

javascriptres.status = function status(code) {
    this.statusCode = code;
    return this;
};

res.set = function set(field, value) {
    if (typeof field === 'object') {
        for (var key in field) this.setHeader(key, field[key]);
    } else {
        this.setHeader(field, value);
    }
    return this;
};

res.get = function get(field) {
    return this.getHeader(field);
};

Эти методы через app.response (базовый объект ответа, из которого создаются все экземпляры) внедряются во все ответы — тот же паттерн, что сам express использует для добавления возможностей на res и req.

Глава 5 — Реализация send и json

Теперь время самых простых API: res.send() решает по типу входа — если пришла строка, ставится Content-Type: text/html; если объект или массив, отправляется JSON с Content-Type: application/json; и всегда устанавливается Content-Length по длине тела (потому что без него в Node возникают баги с буферизацией и удерживаемыми соединениями):

javascriptres.send = function send(body) {
    var chunk = body;

    switch (typeof chunk) {
        case 'string':
            if (!this.get('Content-Type')) {
                this.set('Content-Type', 'text/html');
            }
            break;
        case 'boolean':
        case 'number':
        case 'object':
            if (chunk === null) chunk = '';
            else if (Buffer.isBuffer(chunk)) {
                if (!this.get('Content-Type')) {
                    this.set('Content-Type', 'application/octet-stream');
                }
            } else {
                return this.json(chunk);
            }
            break;
    }

    if (typeof chunk === 'string') {
        this.set('Content-Length', Buffer.byteLength(chunk));
    }
    this.end(chunk);
};

res.json = function json(obj) {
    if (!this.get('Content-Type')) {
        this.set('Content-Type', 'application/json');
    }
    var body = JSON.stringify(obj);
    this.set('Content-Length', Buffer.byteLength(body));
    this.end(body);
};

Теперь «старое» приложение главы 1 переписывается в современном стиле express:

javascriptconst express = require('./src/express');
const app = express();

app.get('/', (req, res) => {
    res.send('Hello World!');
});

app.get('/user/:id', (req, res) => {
    res.json({ id: req.params.id });
});

app.listen(3000);
Примечание: глава 6 (обработка ошибок четырёхаргументными мидлварами (err, req, res, next)) ещё пишется; здесь уже видно, как ошибки переносятся из next(err) в обработчик ошибок. Серия минимальна, но вполне рабочая — и, поскольку она копирует настоящую структуру express, потом читать оригинальный код express будет привычно.

Задача: проверить сотни ссылок

Несколько сотен ссылок на веб-странице. Если проверять по одной (последовательно), каждый запрос ждёт несколько сотен миллисекунд, и вся работа займёт несколько минут. Решение: отправлять все запросы «одновременно» и обрабатывать результаты по мере поступления — это и есть идея async I/O.

async в Nim

Nim с библиотекой asyncdispatch имеет собственную модель async/await со своим event loop (без системного оператора). Каждая async-функция похожа на задачу; await приостанавливает задачу, пока I/O не завершится:

nimimport asyncdispatch, httpclient

# Получение HTML страницы в async-режиме
proc fetch(url: string): Future[string] {.async.} =
  let client = newAsyncHttpClient()
  result = await client.getContent(url)
  client.close()

# Проверка статуса ссылки без блокировки event loop
proc checkLink(url: string): Future[(string, bool)] {.async.} =
  try:
    let resp = await client.head(url)   # только заголовки
    result = (url, resp.status in {Http200, Http301, Http302})
  except:
    result = (url, false)

С помощью accept (ручная проверка event loop) или комбинирования futures можно запустить все проверки ссылок параллельно.

Одновременный запуск всех ссылок

Ключ работы — создать массив Future и ждать все сразу через await. У каждой проверки свой клиент, поэтому event loop отправляет все запросы в сеть одновременно:

nimproc main() {.async.} =
  let html = await fetch("https://example.com")
  let links = extractLinks(html)   # извлечение href

  # Создание Future для всех ссылок
  var futures: seq[Future[(string, bool)]]
  for link in links:
    futures.add(checkLink(link))

  # Ожидание прибытия всех
  let results = await all(futures)

  for (url, ok) in results:
    echo (if ok: "✓ " else: "✗ "), url

Результаты сохраняют порядок, потому что массив Future сохраняет порядок. Примечание: all бросает ошибку, если ошибается хотя бы один; с failOnError: false можно получить частичные результаты.

Сравнение с другими моделями

async/await — только одна из трёх моделей конкурентности. Модель потоков (1000 Thread или ThreadPool) хороша для CPU-нагруженных задач; модель event loop (Node.js) — для I/O-нагруженных. Тот же файл можно скомпилировать с --threads:on и запустить с потоками. С практикой из этого урока вы глубоко поймёте event loop, который есть и в Node.js.

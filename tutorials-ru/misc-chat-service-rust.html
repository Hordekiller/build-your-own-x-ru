Что нужно чат-сервису?

Групповой чат имеет двойную задачу: раздача сообщений всем пользователям (broadcast) и формат сообщения, одинаковый между сервером и клиентом. Стандартные решения: паттерн публикации/подписки (PUB/SUB), например ZeroMQ, для первой части, и Protocol Buffers для второй. Этот урок реализует оба на Rust.

Архитектура: ZeroMQ и PUB/SUB

ZeroMQ — библиотека сокетов с готовыми шаблонами сообщений; PUB/SUB означает: «издатель» шлёт сообщение по теме, и его получают все подписчики этой темы. В чате сервер — PUB, клиенты — SUB:

rust// сторона сервера (раздача)
let ctx = zmq::Context::new();
let publisher = ctx.socket(zmq::PUB).unwrap();
publisher.bind("tcp://*:5555").unwrap();

// сторона клиента (получение всех сообщений)
let subscriber = ctx.socket(zmq::SUB).unwrap();
subscriber.connect("tcp://server:5555").unwrap();
subscriber.set_subscribe(b"").unwrap();   // все темы

loop {
    let msg = subscriber.recv_string(0).unwrap();
    println!("{}", msg.unwrap());
}

Преимущество ZeroMQ: без ручной логики подключения/переподключения; сообщения буферизуются и могут быть перечитаны, и всё хорошо масштабируется.

Формат с Protocol Buffers

Сообщение чата — не только текст: имя пользователя, время, id комнаты. Protocol Buffers (от Google) дают компактный и расширяемый формат — определение в файле .proto и типобезопасный сгенерированный код:

protomessage ChatMessage {
  required string username = 1;
  required string content = 2;
  required int64 timestamp = 3;
}
rust// кодирование сообщения перед PUB
let mut msg = ChatMessage::new();
msg.set_username(user);
msg.set_content(text);
let bytes = msg.write_to_bytes().unwrap();
publisher.send(bytes, 0).unwrap();

Поскольку номера полей явные, новые версии proto могут добавлять поля, не ломая старых клиентов — извечная проблема текстовых API.

Настоящая масштабируемость

После MVP: клиент умеет отправлять сообщения на сервер (REQ/REP отдельно от PUB/SUB), комнаты разделяются темами ZeroMQ, а история хранится в базе данных. Ядро «публикация подписчикам» — тот же базовый паттерн, что у вас уже есть, — играет главную роль и в MQTT, и в Socket.IO.

Что такое CI и что оно делает?

Непрерывная интеграция (Continuous Integration): с каждым коммитом тесты автоматически запускаются на отдельном сервере, а результат показывается в веб-интерфейсе. GitHub Actions и GitLab CI делают именно это; эта глава (из известной книги 500 Lines) строит такую систему с объектно-ориентированным сервером и простым runner'ом.

Архитектура: две основные части

Система состоит из двух независимых компонентов: серверная программа, которая записывает состояние тестов и отчитывается, и runner, выполняющий тесты на каждой машине. Publisher'ы отправляют события в каналы (email, IRC). Такое разделение значит, что тесты можно гонять на любом сервере, а сервер — только координатор.

Модель данных

Каждый тест — это Build с разными состояниями. Смена состояния уведомляет подписчиков (subscribe/unsubscribe) — паттерн Observer:

pythonclass BuildStatus:
    """Состояние сборки, уведомляющее подписчиков."""
    def __init__(self, name):
        self.name = name
        self.status = 'pending'
        self.subscribers = []

    def subscribe(self, sub):
        self.subscribers.append(sub)

    def set_status(self, status):
        self.status = status
        for sub in self.subscribers:
            sub(self)   # уведомить: сборка перешла в это состояние

Уведомление подписчиков (например, email) в момент смены состояния — а не в цикле опроса — просто и прямо.

Runner: запуск тестов

Runner получает запросы и запускает тесты. Интересный момент главы: тесты выполняются в отдельном потоке с timeout, чтобы зависший тест (hang) не блокировал CI — «борьба» между смертью потока и timeout'ом:

pythondef run_tests(repo, test_cmd, timeout=60):
    """Запуск тестов в отдельном потоке с ограничением по времени."""
    result = {'status': 'running'}

    def _run():
        # clone/update репозитория, запуск и запись результата
        rc = subprocess.run(test_cmd, shell=True, timeout=timeout)
        result['status'] = 'success' if rc.returncode == 0 else 'failed'

    t = threading.Thread(target=_run)
    t.start(); t.join(timeout)
    if t.is_alive():
        result['status'] = 'timeout'   # тест завис
    return result

Видно, что CI в своей сердцевине знает всего 4 состояния: pending, running, success, failed — их достаточно для всей экосистемы Actions.

Зачем учить сети на проектах?

Многие руководства по сетям просто знакомят с «API»; этот же набор превращает каждую концепцию в полноценный выполняемый проект (чат, игра, Pong). Такой подход заставляет глубоко понимать «почему» и «как» каждого решения — TCP или UDP, буферы и кодирование.

TCP: чат-сервер

Первый проект — TCP-чат-сервер, который держит несколько клиентов и распространяет сообщения между ними. Ключевой момент — синхронизация: каждый клиент получает свой поток (или async), а сообщения должны отправляться атомарно:

csharp// Простой чат-сервер: принимает клиентов и распространяет сообщения
using System.Net.Sockets;
using System.Text;

var listener = new TcpListener(System.Net.IPAddress.Any, 8888);
listener.Start();
Console.WriteLine("Сервер готов...");

while (true) {
    TcpClient client = listener.AcceptTcpClient();
    _ = Task.Run(() => HandleClient(client));
}

void HandleClient(TcpClient client) {
    using var stream = client.GetStream();
    byte[] buffer = new byte[1024];
    while (true) {
        int read = stream.Read(buffer, 0, buffer.Length);
        if (read == 0) break;                    // клиент закрыл соединение
        string msg = Encoding.UTF8.GetString(buffer, 0, read);
        Broadcast($"[{client.Client.RemoteEndPoint}] {msg}");
    }
}

С такой простой структурой заработает первый многоклиентный чат. Следующий шаг — протокол кодирования (длина сообщения + данные), чтобы длинные сообщения правильно разделялись.

UDP: Pong

Быстрые игры вроде Pong работают по UDP, потому что низкая задержка здесь важнее гарантии доставки всех сообщений. В UDP каждый пакет должен сам содержать всю информацию (например, полное состояние игры):

csharp// Отправка состояния игры по UDP (каждый кадр)
using System.Net;
using System.Net.Sockets;
using System.Text;

var socket = new Socket(AddressFamily.InterNetwork,
                        SocketType.Dgram, ProtocolType.Udp);
var server = new IPEndPoint(IPAddress.Parse("127.0.0.1"), 9000);

// Состояние игры: превращаем позиции в строку
string state = $"{paddle1X};{paddle1Y};{ballX};{ballY}";
byte[] data = Encoding.UTF8.GetBytes(state);
socket.SendTo(data, server);

Критический момент UDP: если пакет потерян, его место занимает «следующий пакет»; поэтому каждый пакет должен содержать полное состояние игры.

Многопользовательская TCP-игра

В конце создаётся простая графическая игра, в которой клиенты общаются по TCP: события игры (движение, удары) сообщаются серверу, а сервер рассылает их всем.

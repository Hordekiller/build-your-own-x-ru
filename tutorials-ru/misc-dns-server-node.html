Как работает DNS?

Когда браузер хочет открыть example.com, сначала нужно найти его IP. Это и есть DNS — «телефонная книга интернета»: запрос отправляется по UDP на порт 53; ответ говорит example.com → 93.184.216.34. Имена имеют иерархическую структуру: от корня (.) до TLD (com) и до серверов имён домена.

В этом уроке DNS-сообщение читается и пишется вручную, в бинарном виде, — без библиотек.

Формат DNS-сообщения

Каждое DNS-сообщение имеет 12-байтовый заголовок, а затем вопросы (questions) и ответы (answers). Важные части заголовка: идентификатор (ID), флаги (QR, Opcode, RD) и счётчики. Имена используют формат label (длина + символы) и заканчиваются \0:

javascript// Создание секции вопроса для "example.com"
// Формат: labels + тип (A) + класс (IN)
function makeQuestion(name) {
  const labels = name.split('.').map(l =>
    Buffer.from([l.length]).toString() + l).join('');
  return Buffer.from(labels + '\x00' + '\x00\x01' + '\x00\x01', 'binary');
}

\x00\x01 — тип записи A (адрес IPv4), и ещё раз \x00\x01 — класс IN (интернет).

Сам сервер

Сервер слушает через dgram (UDP) порт 53, разбирает запрос и может ответить заранее заданным ответом (например, фиксированной записью A) — точно как простой DNS в духе hosts file:

javascriptconst dgram = require('dgram');
const server = dgram.createSocket('udp4');

const ZONE = { 'example.com': '93.184.216.34' };

server.on('message', (msg, rinfo) => {
  // 1. Разбор вопроса из сообщения
  const qname = parseName(msg, 12);
  // 2. Поиск в зоне
  const ip = ZONE[qname];
  // 3. Ответ: копируем ID запроса + запись A
  const response = buildResponse(msg, qname, ip);
  server.send(response, rinfo.port, rinfo.address);
});

server.bind(53);

Важнейший момент: ответ должен копировать тот же ID, что и в запросе, иначе клиент не примет ответ.

Следующий шаг: рекурсивный резолвер

Настоящий DNS-сервер, если не знает ответа, отправляет запрос вышестоящим серверам (корень → TLD → сервер имён домена) и идёт по цепочке. На этой базе можно добавить и такой алгоритм: вызывать встроенный dns.resolve Node как «вышестоящий сервер» и кешировать ответы для пользователей.

Территория: байт за байтом

DNS — простой двоичный протокол: по UDP на порт 53 отправляется запрос. Если разобрать сообщение байт за байтом (заголовок, вопрос, ответ), вы освоите концепции всех двоичных систем. Это руководство делает так на Rust — языке, отлично подходящем для байтовой работы.

Чтение байтов структурами Rust

Первый шаг: отправить простой запрос и вывести сырые байты ответа. Затем определяется структура Packet, читающая из BytePacketBuffer; каждое поле (ID, флаги, счётчики) достаётся методами вроде read_u16:

rustpub struct BytePacketBuffer {
    pub buf: [u8; 512],
    pub pos: usize,
}

impl BytePacketBuffer {
    pub fn read_u16(&mut self) -> Result<u16> {
        let hi = self.buf[self.pos] as u16;
        let lo = self.buf[self.pos + 1] as u16;
        self.pos += 2;
        Ok((hi << 8) | lo)      // в DNS — big-endian
    }

    pub fn read_string(&mut self) -> Result<String> {
        // формат label: каждая секция = длина + буквы
        let len = self.buf[self.pos]; self.pos += 1;
        let mut s = String::with_capacity(len as usize);
        for _ in 0..len {
            s.push(self.buf[self.pos] as char); self.pos += 1;
        }
        Ok(s)
    }
}

Важная деталь протокола: байты big-endian, а имена хранятся последовательностью label — без null-terminator, как в C.

Мощь: forwarder и ответ

После разбора запроса сервер пересылает его вышестоящему DNS-серверу (например, 8.8.8.8), получает ответ и возвращает его пользователю — это настоящий «релейный DNS-сервер». Распакуйте ответ и безопасно отправьте — дело сделано:

rustfn handle_query(socket: &UdpSocket, buf: &mut [u8]) -> Result<()> {
    // читаем запрос пользователя и запоминаем его адрес
    let (size, src) = socket.recv_from(buf)?;

    let query = Packet::from_buffer(&mut BytePacketBuffer::new(&buf[..size]))?;

    // пересылка вышестоящему серверу
    let mut resolver = UdpSocket::bind("0.0.0.0:0")?;
    resolver.send_to(&buf[..size], "8.8.8.8:53")?;
    let mut response = [0u8; 512];
    let (n, _) = resolver.recv_from(&mut response)?;

    // отправка ответа пользователю (тот же адрес отправителя)
    socket.send_to(&response[..n], src)?;
    Ok(())
}

Благодаря SocketAddr клиента из recv_from ответ возвращается ровно туда, куда нужно.

Апгрейды: recursive и DoT

Руководство в следующих главах добавляет больше: кеширование (Cache) ответов, автоматический рекурсивный обход (без опоры на 8.8.8.8), DNS-over-TCP и даже DNS-over-TLS. Каждая из них строится на тех же маленьких байтовых примитивах.

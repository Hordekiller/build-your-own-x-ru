Что делают отладчики?

Отладчик вроде gdb позволяет останавливать выполнение программы, ставить точки останова (breakpoint) и исследовать состояние памяти и стека. Чтобы написать отладчик для Linux, нужны три ключевых понятия: ptrace (API ядра для управления процессами), ELF (формат бинарных файлов) и DWARF (метаданные отладки).

Этот курс в нескольких «частях» с нуля реализует эти три уровня и в конце приводит к работающему TUI-отладчику.

ptrace: основа всего

Самый важный вызов — ptrace: PTRACE_ATTACH прикрепляется к процессу, PTRACE_CONT продолжает его, а PTRACE_PEEKDATA читает память. Для чтения регистров используется PTRACE_GETREGS:

cpp// Начало: присоединение к процессу и чтение регистров
#include <sys/ptrace.h>
#include <sys/user.h>
#include <sys/wait.h>

void continue_execution(pid_t pid) {
    if (ptrace(PTRACE_CONT, pid, nullptr, nullptr) == -1) {
        perror("ptrace CONT");
        return;
    }
    waitpid(pid, nullptr, 0);
}

void get_registers(pid_t pid, user_regs_struct& regs) {
    if (ptrace(PTRACE_GETREGS, pid, nullptr, ®s) == -1) {
        perror("ptrace GETREGS");
    }
}

На этом этапе, когда процесс остановлен, PTRACE_GETREGS возвращает содержимое регистров (например, rip), и вы можете проследить стек.

Точки останова

Простейший способ поставить breakpoint — заменить первый байт команды по нужному адресу на 0xcc (команда INT3), а после срабатывания вернуть исходное значение. Помните: после срабатывания нужно вернуть указатель на один байт назад (rip--):

cpp// Установка breakpoint: сохранить исходный байт и заменить на 0xcc
uint64_t set_breakpoint(pid_t pid, uint64_t addr) {
    uint64_t data = ptrace(PTRACE_PEEKDATA, pid, addr, nullptr);
    uint64_t intr = (data & 0xFFFFFFFFFFFFFF00) | 0xCC;
    ptrace(PTRACE_POKEDATA, pid, addr, intr);
    return data;   // для последующего восстановления
}

void unset_breakpoint(pid_t pid, uint64_t addr, uint64_t orig) {
    ptrace(PTRACE_POKEDATA, pid, addr, orig);
}

Эти две функции — ядро любой системы отладки; то же самое происходит и внутри gdb.

Понятия DWARF и метаданных

Чтобы показывать имена переменных и строки кода, нужно читать секцию .debug_info ELF-файла (стандарт DWARF). Ваш отладчик должен держать таблицу соответствий (jumptable): адрес ← имя файла/строка, чтобы можно было показывать «текущее место выполнения».

Полная реализация в этом пошаговом цикле статей доходит до таблиц строк (line table) и DWARF-выражений.

Итог

Создание отладчика даёт глубочайшее понимание «выполнения программы»: регистры, стек, точки останова и процессы Unix. Если вы хотите понять, что происходит под капотом gdb/LLDB, или собрать собственный инструмент отладки, этот цикл — самый полный справочник.

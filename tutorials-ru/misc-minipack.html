Что делает бандлер?

Когда ваш JavaScript-проект использует ES-модули, браузер не может прочитать их все в одном HTML-файле (разве что с import map). Бандлер (webpack, Rollup) превращает все модули в один исполняемый файл. Minipack реализует этот процесс в три главных шага: извлечение зависимостей, построение графа и генерация бандла.

Шаг 1: чтение и разбор

Каждый файл модуля нужно разобрать в AST, чтобы найти import-выражения. С babel-core и babel-traverse это просто:

javascript// Чтение файла, разбор в AST и поиск import-зависимостей
function createAsset(filename) {
  const source = fs.readFileSync(filename, 'utf-8');

  // Разбор в синтаксическое дерево (AST)
  const ast = babel.parse(source, { sourceType: 'module' });

  const dependencies = [];
  // Обход дерева и поиск import
  traverse(ast, {
    ImportDeclaration: ({ node }) => {
      dependencies.push(node.source.value);
    }
  });

  // Преобразование ES-модулей в CommonJS для использования в бандле
  const { code } = babel.transformFromAst(ast, null, {
    presets: ['env']
  });

  return { filename, dependencies, code };
}

Каждый «asset» — это файл с его зависимостями; из них и строится граф.

Шаг 2: построение графа зависимостей

BFS-обходом от входного файла собираются все модули, и каждому выдаётся идентификатор (id). Итоговый граф — карта id → asset:

javascript// Построение графа обходом в ширину (breadth-first)
function createGraph(entry) {
  const mainAsset = createAsset(entry);
  const queue = [mainAsset];

  for (const asset of queue) {
    asset.mapping = {};
    const dirname = path.dirname(asset.filename);

    asset.dependencies.forEach(relativePath => {
      const absolutePath = path.join(dirname, relativePath);
      const child = createAsset(absolutePath);
      asset.mapping[relativePath] = child.id;
      queue.push(child);
    });
  }
  return queue;
}

mapping — та самая таблица, превращающая относительный путь в id; она используется при выполнении бандла.

Шаг 3: генерация бандла

Теперь все assets вместе с маленьким загрузчиком (имитирующим require) собираются в один IIFE:

javascript// Генерация вывода: каждый модуль — в function с локальным require
function bundle(graph) {
  let modules = '';

  graph.forEach(mod => {
    modules += `${mod.id}: [
      function (require, module, exports) {
        ${mod.code}
      },
      ${JSON.stringify(mod.mapping)},
    ],`;
  });

  return `(function(modules) {
    function require(id) {
      const [fn, mapping] = modules[id];
      function localRequire(name) { return require(mapping[name]); }
      const module = { exports: {} };
      fn(localRequire, module, module.exports);
      return module.exports;
    }
    require(0);
  })({${modules}})`;
}

Этот внутренний require делает ровно то, что делает runtime webpack: разрешает зависимости по mapping и выполняет модули.

Итог

Minipack меньше чем на 200 строках показывает, что бандлеры — не магия: разбор, граф и runtime. После этого ваше понимание реального поведения webpack (tree shaking, chunking) станет намного глубже.

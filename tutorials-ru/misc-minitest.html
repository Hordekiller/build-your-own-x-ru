Пишем тестовый фреймворк MiniTest на Nim

Оригинальный источник: «Writing a MiniTest framework in Nim»

Из чего состоит тестовый фреймворк?

Минимальные компоненты любого тестового фреймворка: регистрация тестов, изолированный запуск каждого теста, сравнение ожидания с результатом (assertion), сводка результатов и ненулевой код выхода при неудаче. Более продвинутые фреймворки имеют фикстуры (setup/teardown) и наборы (suites).

В этом уроке мы сделаем MiniTest на Nim с синтаксисом в духе RSpec — с помощью макросов.

Описательный синтаксис с макросом

Основная идея: макрос describe собирает тестовые блоки, а при запуске выполняются только тесты, имена которых пришли из командной строки. Каждый тест — простое замыкание:

nimimport macros

# Регистрация тестов: массив из пары (имя, тело)
var tests: seq[(string, proc())]

macro describe(name: static[string], body: untyped): untyped =
  # Работа макроса: сбор тестов из AST
  result = newStmtList()
  for child in body:
    if child.kind == nnkCall and child[0].repr == "test":
      let testName = child[1].repr
      let body = child[2]
      # Узел регистрации: tests.add((имя теста, тело))
      result.add newCall(ident"tests.add",
                         newTree(nnkTupleConstr, newLit(testName), body))

describe "Математические вычисления":
  test "Простое сложение":
    check(1 + 1 == 2)
  test "Умножение":
    check(2 * 3 == 6)

Макросы Nim видят AST во время компиляции; поэтому можно строить «языки поверх языка» (DSL), не замедляя выполнение программы.

Запуск и отчёт

Часть запуска вызывает тесты по очереди, ловит ошибки и в конце подводит итог:

nimvar passed = 0
var failed = 0

for (name, body) in tests:
  try:
    body()
    passed.inc
    echo "✓ ", name
  except CatchableError as e:
    failed.inc
    echo "✗ ", name, " — ", e.msg
    echo "  ", getCurrentException().trace

echo ""
echo passed, " успешно, ", failed, " неудач"
if failed > 0:
  quit(1)   # важно для CI!

Именно quit(1) заставляет работать инструменты вроде pytest в CI-конвейерах: можно ничего не печатать, но нулевой или ненулевой код выхода говорит обо всём.

Итог

Удивительно, что примерно за 50 строк кода вы построили описательный тестовый фреймворк (describe/it). В следующий раз, когда будете использовать RSpec или Jest, вы будете знать, что происходит за кулисами, — и Nim показывает это наглядно благодаря макросам.

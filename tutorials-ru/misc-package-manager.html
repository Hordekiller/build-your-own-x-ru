Крошечный package manager — как устроены npm и Yarn

Что делает npm? (а что не делает?)

Менеджер пакетов выполняет три задачи: читает package.json, разрешает зависимости (resolution) и устанавливает файлы в node_modules. Выглядит просто, но часть «разрешение зависимостей» — понять, какую версию хочет каждый пакет, — это настоящее место сложности. Этот проект проясняет её, добавляя код шаг за шагом.

Резолюция: какая версия?

Пакет говорит "lodash": "^4.17.0" — значит 4.17.0 или выше, но ниже 5. Для каждой зависимости нужно получить из реестра список существующих версий и выбрать лучшую. Версии semver осмысленны при сравнении по компонентам (major.minor.patch):

typescript// сравнение двух semver-версий, например "2.1.4" и "2.2.0"
function compareVersions(a: string, b: string): number {
  const pa = a.split('.').map(Number);
  const pb = b.split('.').map(Number);
  for (let i = 0; i < 3; i++) {
    if (pa[i] !== pb[i]) return pa[i] - pb[i];
  }
  return 0;
}

// "^4.17.0": версия с major=4 и максимальная из них
function resolveRange(range: string, versions: string[]): string {
  const [major] = range.slice(1).split('.').map(Number);
  return versions
    .filter(v => Number(v.split('.')[0]) === major)
    .sort(compareVersions)
    .pop()!;
}

В действительности semver сложнее (prerelease, тильда, диапазоны) — существуют пакеты вроде semver, чтобы не выдумывать своё.

Граф зависимостей и кризис вложенности

Пакет A зависит от B, B от C и так далее. Строится древовидный граф, решаемый обходом BFS, и создаётся «замок» (lockfile) с точным списком всех версий, чтобы последующие установки были одинаковыми:

typescript// уплощение графа зависимостей и запись в lockfile
const lock: Record<string, string> = {};

function resolve(pkg, versions, depth = 0) {
  for (const [name, range] of Object.entries(pkg.dependencies ?? {})) {
    const version = resolveRange(range, versions[name]);
    if (lock[name] === undefined) lock[name] = version;
    // ... рекурсивно для подзависимостей
  }
}

Вызов, который решают yarn/pnpm: два пакета могут хотеть разные версии одной общей зависимости; «выравнивание» (dedupe) или «отдельные папки» (pnpm) — оба подхода решения одной задачи.

Установка и итог

Последний этап: скачивание tarball'а из реестра (registry.npmjs.org) и распаковка в node_modules/<имя>. Этими ~200 строками TypeScript tiny-package-manager симулирует npm. После этого, глядя на любой инструмент — Yarn, pnpm или Bun, — вы знаете, какие решения они приняли и почему.

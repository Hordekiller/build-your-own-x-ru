Что такое MVC?

MVC — это разделение ответственности: Model работает с данными и логикой, View занимается только отображением (HTML), а Controller — мост между ними: принимает запрос пользователя, вызывает Model и передаёт результат во View. Фреймворки Laravel и CodeIgniter упорядочили именно этот паттерн.

Front Controller и роутинг

Первый шаг: все запросы должны приходить в один файл (index.php). С помощью .htaccess всё направляется на index, а он по тексту URL решает, какой контроллер/экшен выполнить:

htaccessRewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteRule ^(.*)$ index.php?url=$1 [QSA,L]
phpclass Application {
    public function run() {
        // Например: home/index/5
        $parts = explode('/', trim($_GET['url'] ?? 'home/index', '/'));
        $controller = ucfirst($parts[0] ?? 'Home') . 'Controller';
        $action = $parts[1] ?? 'index';

        $file = "app/controllers/$controller.php";
        if (!file_exists($file)) { http_response_code(404); die('Не найдено'); }

        require $file;
        $obj = new $controller;
        $obj->$action();   // вызываем контроллер с экшеном
    }
}

Весь секрет роутинга в этом: разбить URL и вызвать нужный класс. (Безопасность: в контроллерах принимаются только допустимые имена директорий.)

Контроллер и модель

Контроллер берёт данные из модели и отдаёт во вью:

phpclass HomeController {
    public function index() {
        $posts = (new PostModel())->latest();   // данные из модели
        require "app/views/home.php";          // отображение: $posts
    }
}
phpclass Model {
    protected $db;
    public function __construct() {
        $this->db = new PDO('sqlite:app.db');   // общее подключение
    }
    protected function query($sql, $params = []) {
        $st = $this->db->prepare($sql);
        $st->execute($params);
        return $st->fetchAll();
    }
}

С PDO — prepared-запросы и bind параметров, первый след безопасности против SQL-инъекций.

Итоговая структура

Базовая структура папок: app/controllers, app/models, app/views, core/ для базовых классов и public/ для статики. Это та же структура, что во всех известных фреймворках; построив её с нуля, вы будете читать исходники фреймворков как знакомый текст.

Современный PHP = Composer + стандарты

Современный PHP ушёл далеко вперёд от тегов, разбросанных по HTML: управление зависимостями через Composer, стандартная автозагрузка PSR-4, строгие типы и аккуратный роутинг. Этот урок показывает, что всё это можно получить и без какого-либо фреймворка.

Автозагрузка и namespace

С PSR-4 каждый класс App\X лежит в папке src/X.php, и Composer сам загрузит его где угодно. Никаких цепочек include и ручных require:

json{
  "name": "me/my-app",
  "autoload": {
    "psr-4": { "App\\": "src/" }
  }
}
phpnamespace App;

require __DIR__ . '/../vendor/autoload.php';

use App\Http\Request;
use App\Http\Response;

$request = Request::capture();
$response = new Response('Привет, мир!', 200);
$response->send();

После каждого нового класса нужен composer dump-autoload, чтобы карта файлов обновилась.

Свой маленький роутер

Определим всего несколько маршрутов без борьбы с фреймворком. Тонкий момент: сравнение HTTP-метода через strtoupper и параметры {id} через regex для безопасности:

phpfinal class Router
{
    private array $routes = [];

    public function add(string $method, string $path, callable $handler): void
    {
        $this->routes[] = [$method, $path, $handler];
    }

    public function dispatch(string $method, string $uri): Response
    {
        foreach ($this->routes as [$m, $path, $handler]) {
            if ($m !== $method) continue;
            $pattern = '#^' . str_replace('{id}', '(\d+)', $path) . '$#';
            if (preg_match($pattern, $uri, $m)) {
                return $handler((int) $m[1]);
            }
        }
        return new Response('Not Found', 404);
    }
}

После этого всё, что дают фреймворки (валидация, шаблоны, контейнер), можно собрать такими же кусочками или взять маленькие независимые пакеты Composer.

Зачем это делать?

Для маленьких проектов полный фреймворк избыточен; для обучения лучший учитель — увидеть слои без обёрток. Навыки, которые вы получаете (PSR, autoload, тесты), напрямую работают и во фреймворк-проектах.

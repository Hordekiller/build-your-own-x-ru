Как работает поисковый движок?

У любого поискового движка две фазы: индексация (indexing) и запрос (query). При индексации каждый документ разбивается на «токены» (слова), и строится инвертированная карта «слово → документы»; при запросе слова поисковой фразы находятся в этой карте, и возвращаются документы, содержащие их все.

Токенизация и база данных

Бен в этой серии использует SQLite: таблица документов + таблица слов + таблица связей (слово → документ со счётчиком). Токенизация — это разделение на слова и удаление мусорных символов:

phpfunction tokenise($text) {
    // простое разделение на слова (с сохранением регистра)
    $words = str_word_count(strtolower($text), 1);
    // удаление стоп-слов (stop words) типа «и, с, для»
    $stop = ['the', 'and', 'for', 'php'];
    return array_diff($words, $stop);
}

Удаление стоп-слов не даёт самым частым словам создавать гигантские файлы, а результаты становятся точнее.

Индексация документов

phpforeach ($documents as $doc) {
    $docId = insertDocument($db, $doc['url'], $doc['title']);

    foreach (tokenise($doc['body']) as $word) {
        $wordId = getOrCreateWord($db, $word);
        // строка связи: слово—документ со счётчиком повторов
        incrementLink($db, $wordId, $docId);
    }
}

Таблица links с (word_id, doc_id, count) — сердце «инвертированного индекса»: прозрачный формат того, что коммерческие движки хранят в более сжатом виде.

Запрос

Поиск выполняется JOIN между словами и связями, а подсчёт и сортировка дают самые релевантные результаты. Простая ранжировка TF (частота повторения слова в документе) даже без IDF даёт хорошие результаты:

sqlSELECT d.url, SUM(l.count) AS score
FROM words w
JOIN links  l ON l.word_id = w.id
JOIN docs   d ON d.id = l.doc_id
WHERE w.word IN ('php', 'search')
GROUP BY d.id
ORDER BY score DESC
LIMIT 10;

После этой реализации примерно на 100 строк понятия BM25, PageRank и распределённая индексация больше не загадка — всё это апгрейды той же основы.

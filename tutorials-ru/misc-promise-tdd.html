Реализуем промисы с нуля — в стиле TDD

Зачем TDD для этого проекта?

У промисов точное, специфицированное поведение (однократный settle, цепочки, ошибки). Тесты, написанные до кода, точно определяют «какое поведение нам нужно» и позволяют реализовывать без догадок. Этот урок работает с jest или простым тест-раннером.

Первые тесты: resolve и then

Первые тесты определяют базовое поведение: промис через resolve получает значение, а then принимает его:

javascript// Тест: промис создан и резолвится
test('resolve отдаёт значение', () => {
  const p = new MyPromise((resolve) => resolve(42));
  return p.then(value => {
    expect(value).toBe(42);
  });
});

test('работает цепочка then', () => {
  const p = new MyPromise((resolve) => resolve(2));
  return p
    .then(v => v * 10)
    .then(v => v + 1)
    .then(v => {
      expect(v).toBe(21);
    });
});

Теперь пишем минимальный код, чтобы тесты стали зелёными: state, settle и then с цепочкой.

Тесты reject и catch

Следующий этап — ошибки: reject отдаёт значение ошибки, catch ловит её, а throw в executor приводит к reject:

javascript// Отклонение реализуется той же структурой settle
test('reject вызывает catch', () => {
  const p = new MyPromise((resolve, reject) => reject(new Error('Плохо')));

  return p.catch(err => {
    expect(err.message).toBe('Плохо');
  });
});

test('throw в executor равен reject', () => {
  const p = new MyPromise(() => {
    throw new Error('Взрыв');
  });
  return expect(p).rejects.toThrow('Взрыв');
});

Чтобы тесты прошли, constructor должен выполнять аргумент executor в try/catch, а catch определяться как then(undefined, onRejected).

Финальная реализация (кратко)

С этими тестами реализация становится понятной: объект с тремя состояниями, массив handlers и settle, вызываемый только один раз:

javascriptclass MyPromise {
  static PENDING = 'pending';
  static FULFILLED = 'fulfilled';
  static REJECTED = 'rejected';

  constructor(executor) {
    this.state = MyPromise.PENDING;
    this.value = undefined;
    this.handlers = [];
    const resolve = v => this.settle(MyPromise.FULFILLED, v);
    const reject = r => this.settle(MyPromise.REJECTED, r);
    try { executor(resolve, reject); } catch (e) { reject(e); }
  }

  settle(state, value) {
    if (this.state !== MyPromise.PENDING) return;
    this.state = state;
    this.value = value;
    this.handlers.forEach(h => h());
  }

  then(onF, onR) {
    return new MyPromise((resolve, reject) => {
      this.handlers.push(() => {
        const handler = this.state === MyPromise.FULFILLED ? onF : onR;
        try {
          const r = handler ? handler(this.value) : this.value;
          if (r instanceof MyPromise) r.then(resolve, reject);
          else resolve(r);
        } catch (e) { reject(e); }
      });
    });
  }

  catch(onR) { return this.then(undefined, onR); }
}

Важный момент: сначала пишутся тесты, потом код; и каждый этап реализуется ровно настолько, насколько нужно для зелёного теста.

Итог

Этот урок показывает, что TDD нужен не только в больших проектах — даже для алгоритмических задач это лучший способ добиться точности. После завершения можно добавить тесты асинхронного поведения (setTimeout и микротаски).

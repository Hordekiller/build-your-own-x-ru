О чём это

Урок разрабатывает Promise методом TDD: сначала пишутся тесты, затем маленькими шагами реализуется поведение — состояния, цепочки, обработка ошибок — каждая деталь подтверждена тестом.

Что вы узнаете

  • Дисциплина TDD: тест сначала, код потом
  • Реализация состояний и переходов
  • Обработка ошибок и прокидывание исключений
  • Кросс-браузерные нюансы микротасков

Основная идея

Подход прост: для каждого поведения сначала пишется тест, он падает, затем пишется минимальный код, и тест зеленеет. Так промис вырастает из десятков проверенных деталей.

Пример теста, который определяет поведение:

JavaScripttest("then вызывается с результатом", () => {
  const p = new MyPromise((res) => res(42));
  return p.then((v) => expect(v).toBe(42));
});

Почему это важно

TDD — это способ мышления, а не просто инструмент: реализуя промис таким образом, вы получаете и работающий код, и уверенность в каждой его детали.

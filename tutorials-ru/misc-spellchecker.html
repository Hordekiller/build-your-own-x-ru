Создание проверки орфографии на Clojure

Как работает проверка орфографии?

Проверка орфографии состоит из двух шагов: обнаружение — понять, что слова нет в словаре; и предложение — найти ближайшее допустимое слово. Простейший способ предлагать варианты — сгенерировать «редакции на расстоянии один» (deletion, insertion, substitution, transposition) и искать их в словаре.

Проект этого урока написан на Clojure — языке, который благодаря неизменяемым структурам данных и чистым функциям делает такой алгоритм аккуратным и читаемым.

Генерация кандидатов редактированием на один символ

Для каждого слова генерируются все однобуквенные изменения: удаление, замена, вставка и перестановка соседних букв:

clojure; Генерация всех слов, получаемых одним изменением
(defn edits1 [word]
  (let [letters "abcdefghijklmnopqrstuvwxyz"
        splits (for [i (range (inc (count word)))]
                 [(subs word 0 i) (subs word i)])]
    (concat
      ; удаление буквы
      (for [[a b] splits :when (pos? (count b))]
        (str a (subs b 1)))
      ; перестановка двух соседних букв
      (for [[a b] splits :when (pos? (count (subs b 1)))]
        (str a (subs b 1 2) (subs b 0 1) (subs b 2)))
      ; замена
      (for [[a b] splits :when (pos? (count b)) c letters]
        (str a c (subs b 1)))
      ; вставка
      (for [[a b] splits c letters]
        (str a c b))))

Теперь сравниваем кандидатов со словарём, а если ни один не подошёл, применяем вторую редакцию (edits2).

Выбор лучшего предложения

Чтобы выбрать среди нескольких допустимых кандидатов, используется частота слов в корпусе: побеждает самое частое слово. Эта простая «байесовская» модель — основа настоящих проверок орфографии:

clojure; Лучший кандидат — с наибольшей частотой в словаре
(defn best-candidate [freqs candidates]
  (when (seq candidates)
    (reduce (fn [best c]
              (if (> (get freqs c 0) (get freqs best 0))
                c best))
            (first candidates)
            (rest candidates))))

; Полная проверка: редакция 1, затем 2
(defn correct [word freqs known-words]
  (cond
    (contains? known-words word) word
    (seq (filter known-words (edits1 word)))
      (best-candidate freqs (filter known-words (edits1 word)))
    :else (best-candidate freqs
            (filter known-words (edits2 word)))))

Эта структура показывает, что «умные» алгоритмы иногда состоят из нескольких сотен простых строк.

Шаги реализации и тестирования

Этапы: 1) построить словарь из текстового корпуса функцией frequencies; 2) реализовать edits1/edits2; 3) написать функцию correct; 4) сделать небольшой REPL, исправляющий введённое пользователем слово, плюс набор тестов, проверяющих корректность.

Итог

Этот маленький проект демонстрирует большие концепции языковых моделей (частоты, редакционное расстояние) и красиво сочетается с Clojure. После него можно перейти к более продвинутым алгоритмам (например, BK-tree или Soundex).

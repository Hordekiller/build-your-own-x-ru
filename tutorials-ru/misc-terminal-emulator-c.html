Что происходит внутри терминала

Эмулятор терминала (вроде xterm или st) снаружи просто текстовое окно, но за ним важный механизм: сетка символьных ячеек, буфер для хранения содержимого и обработка escape-последовательностей — тех управляющих кодов, что меняют цвета, движение курсора и состояние экрана.

Когда программа вроде vim или ls выполняется, она шлёт последовательности байтов (например, \x1b[31m для красного); терминал должен их интерпретировать и отрендерить фон и текст соответственно.

Модель данных: ячейка и буфер

Сердце терминала — двумерный массив «ячеек». Каждая ячейка содержит символ, цвет текста и фона и несколько атрибутов (жирный, подчёркнутый):

ctypedef struct {
    char c;          // символ ячейки
    int fg, bg;      // цвет текста и фона
    int bold, underline;
} Cell;

// Буфер: массив строк, каждая строка — массив ячеек
typedef struct {
    int rows, cols;
    Cell** cells;
} Buffer;

// Очистка экрана и установка курсора
void term_clear(Buffer* buf) {
    for (int y = 0; y < buf->rows; y++)
        for (int x = 0; x < buf->cols; x++) {
            buf->cells[y][x].c = ' ';
            buf->cells[y][x].fg = DEFAULT;
        }
}

Эта простая структура — основа всех операций рендера: любая операция лишь меняет значения массива, а затем «проход рендера» рисует его на экране.

Интерпретация escape-последовательностей

Основная часть кода — конечный автомат, читающий входные байты. Когда виден байт 0x1b, терминал входит в состояние «escape» и интерпретирует следующую последовательность (например, [2J — очистка экрана):

c// Обработка CSI-последовательностей (Control Sequence Introducer)
void handle_csi(char* params, int plen) {
    // "J" — очистка: 2J — весь экран
    if (params[plen-1] == 'J') {
        term_clear(&buf);
        return;
    }
    // "H" — перемещение курсора в (row, col)
    if (params[plen-1] == 'H') {
        int row = 0, col = 0;
        if (plen > 1)
            sscanf(params, "%d;%d", &row, &col);
        cursor.row = row - 1;
        cursor.col = col - 1;
    }
}

Для полного терминала нужно поддерживать сотни разных последовательностей, но уже с этими функциями имитируется базовое поведение xterm.

Итог

Постройка терминала сочетает понятия ОС (pty, управляющие сигналы), текстовую графику и конечные автоматы. После этого введения можно браться за полные проекты вроде «st» или «alacritty» и по-настоящему понимать их архитектуру.

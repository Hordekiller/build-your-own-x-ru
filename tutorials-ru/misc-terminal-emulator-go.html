Терминал и псевдо-терминал

Терминал отображает то, что в нём выполняется. Чтобы настоящая программа (например, sh) запускалась внутри вашего терминала, нужен pty (псевдо-терминал): пара master/slave, связывающая ввод и вывод. В Go библиотека creack/pty упрощает эту задачу.

Архитектура: два цикла

У эмулятора два потока данных: вывод программы → на экран и ввод пользователя → в программу. Они выполняются одновременно. Отображение делается с помощью termbox-go (библиотека TUI):

gofunc runTerminal(ptmx *os.File) {
    go func() {
        // Цикл чтения вывода программы и его отображения
        buf := make([]byte, 4096)
        for {
            n, err := ptmx.Read(buf)
            if err != nil { return }
            termbox.SetCell(x, y, rune(buf[i]), fg, bg)
            ...
        }
    }()

    // Цикл событий клавиатуры: отправка в ptmx
    for {
        ev := termbox.PollEvent()
        if ev.Type == termbox.EventKey {
            _, err := ptmx.Write([]byte{byte(ev.Ch)})
            if err != nil { ... }
        }
    }
}

Здесь ptmx и «читается», и «записывается»: мы читаем вывод программы и показываем его на сетке, а нажатия пользователя отправляем программе.

Обработка escape-последовательностей

Все терминалы должны интерпретировать ANSI-последовательности. Простейший дизайн — маленький конечный автомат: когда встречается символ \x1b, собирай остальное до завершающего кода (например, [m):

go// Простая интерпретация ANSI-кодов цвета
func interpretANSI(data []byte) {
    if len(data) > 2 && data[0] == 0x1b && data[1] == '[' {
        // Разбор параметров до завершающей буквы
        parts := strings.Split(string(data[2:len(data)-1]), ";")
        if len(parts) > 0 {
            switch parts[0] {
            case "31": fg = termbox.ColorRed
            case "32": fg = termbox.ColorGreen
            case "0":  fg = termbox.ColorDefault
            }
        }
    }
}

С этой простой функцией цветные выводы ls --color отображаются правильно.

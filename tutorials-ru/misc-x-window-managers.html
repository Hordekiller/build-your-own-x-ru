Менеджер окон в экосистеме X11

В X11 сервер X управляет только «рисованием» и вводом; раскладка окон отдаётся менеджеру окон (Window Manager). Менеджер окон — особый клиент: меняет рамки окон, рисует titlebar и интерпретирует клавиши. Обычные программы из-за декораций ничего не знают о раскладке.

Этот урок начинается с простого менеджера окон, который накладывает и перемещает окна, а позже добавляет такие возможности, как тайлинг (tiling) и фокус.

События и подключение к серверу

Вся работа идёт через протокол X (на C с xcb). Менеджер окон должен слушать события MapRequest (когда новое окно хочет стать видимым) и ConfigureRequest (когда окно хочет изменить размер или позицию):

cpp// Главный цикл событий менеджера окон
while ((e = xcb_wait_for_event(conn))) {
    switch (e->response_type & ~0x80) {
        case XCB_MAP_REQUEST:
            map_request(conn, (xcb_map_request_event_t*)e);
            break;
        case XCB_CONFIGURE_REQUEST:
            configure_request(conn, (xcb_configure_request_event_t*)e);
            break;
        case XCB_KEY_PRESS:
            handle_key(conn, (xcb_key_press_event_t*)e);
            break;
    }
    free(e);
}

// Показ и раскладка нового окна
void map_request(xcb_connection_t* c, xcb_map_request_event_t* e) {
    xcb_configure_window(c, e->window,
        XCB_CONFIG_WINDOW_X | XCB_CONFIG_WINDOW_Y |
        XCB_CONFIG_WINDOW_WIDTH | XCB_CONFIG_WINDOW_HEIGHT,
        (uint32_t[]){ 0, 0, SCR_W, SCR_H });
    xcb_map_window(c, e->window);
    xcb_flush(c);
}

Так каждая новая программа автоматически разворачивается на весь экран — базовое поведение тайлинг-менеджеров окон.

EWMH и современный рабочий стол

Одного протокола X недостаточно: чтобы рабочие среды замечали менеджера окон, нужно соблюдать протокол EWMH — объявлять _NET_SUPPORTED, _NET_NUMBER_OF_DESKTOPS и тому подобное. А также работать с _NET_WM_STATE для полноэкранных окон.

Эта часть полностью раскрывается во второй части урока, после чего проект готов к использованию на настоящем рабочем столе.

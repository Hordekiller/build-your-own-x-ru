Сетевой стек на Ruby

Идея: зачем строить свой сетевой стек

Каждый день мы работаем с сетью, но её слои обычно скрыты от нас. Эта статья — путешествие «под капот»: построение сетевого стека — да, на сырых сокетах — от битов на проводе до puts "Hello". Начинается с того, как сырой сокет Linux открывается в Ruby двумя строками:

ruby# Как TCP — но сырой, без обработки сетевым стеком; 'INET' берёт пакет сам!
socket = Socket.open(Socket::AF_INET, Socket::SOCK_RAW, Socket::IPPROTO_UDP)
# socket() / bind() / recvfrom() / sendto() — всё отсюда доступно.

Почему UDP? Потому что без возни со сложными соединениями он упрощает структуру пакета: ядро не строит за вас IP-заголовок — это облегчает работу с исходными данными. Следствие: каждый принятый пакет мы должны анализировать сами, потому что ядро за нас ничего не решает.

Ethernet-кадр: вход байтов

Первое, что мы получаем из сокета, — Ethernet-кадр, в котором «утоплены» заголовки IP и UDP. Определяем его положение (байты 0–13) вручную:

rubyclass EthernetFrame
  ETH_P_IP = 0x0800          # тип пакета: IPv4

  def initialize(raw)
    @raw = raw
    @dst_mac = raw[0, 6].unpack("H*").first
    @src_mac = raw[6, 6].unpack("H*").first
    @ethertype = raw[12, 2].unpack("n").first
  end

  def ipv4?   # это IP-пакет?
    @ethertype == ETH_P_IP
  end
end

Эта структура в Ruby переходит к ipv4_packet, пропустив начало Ethernet.

Заголовок IPv4: побитово

IP-заголовок — каркас, на котором держится всё остальное: версия протокола, IHL (длина заголовка в 32-битных словах), TTL, вышележащий протокол и, конечно, адреса источника и назначения. В Ruby биты отделяются распаковкой строки байтов:

rubyclass IPv4Packet
  IPPROTO_UDP = 17

  def initialize(raw)
    @raw = raw
    version_and_ihl = raw[0].unpack("C").first
    @version = (version_and_ihl >> 4) & 0x0F   # четыре старших бита
    @ihl     = version_and_ihl & 0x0F           # четыре младших бита
    @protocol = raw[9].unpack("C").first
    @src_ip = raw[12, 4].unpack("C4").join(".")
    @dst_ip = raw[16, 4].unpack("C4").join(".")
  end

  def udp?; @protocol == IPPROTO_UDP; end
end

И особенно важно: @ihl говорит нам, где начинается payload (байт ihl * 4) — ведь только стандартный заголовок мы и разбираем. Самое забавное: это те самые биты, которые настоящий стек ядра всегда обрабатывает не задумываясь!

Дейтаграмма UDP

Следующий шаг: дейтаграмма UDP — 8-байтовый заголовок с портами источника/назначения, длиной и контрольной суммой:

rubyclass UDPDatagram
  def initialize(raw)
    @src_port = raw[0, 2].unpack("n").first
    @dst_port = raw[2, 2].unpack("n").first
    @length   = raw[4, 2].unpack("n").first
    @checksum = raw[6, 2].unpack("n").first
    @payload  = raw[8, @length - 8]     # длина включает сам заголовок!
  end
end

Теперь полная модель из трёх слоёв: EthernetFrame ← IPv4Packet ← UDPDatagram — и нужен ещё «нисходящий» путь для отправки: упаковываем (pack) UDP-дейтаграмму, добавляем спереди IP-заголовок, затем Ethernet-кадр — и «выкрикиваем» через sendto из сырого сокета.

Связываем структуры: «upper-сервер»

Теперь, когда есть обе стороны, выводим «модели» наружу: беззаботный сервер, который берёт каждую UDP-дейтаграмму, переводит строку внутри в ВЕРХНИЙ РЕГИСТР (uppercase) и возвращает ответ. Это та самая настоящая сетевая цепочка, которую проходят браузеры — но теперь линии анализа и сборки целиком под нашими пальцами:

rubysocket = Socket.open(Socket::AF_INET, Socket::SOCK_RAW, Socket::IPPROTO_UDP)

puts "listening for raw frames on #{packet socket…}"

loop do
  frame = EthernetFrame.new(socket.recvfrom(65535).first)
  next unless frame.ipv4?

  packet = IPv4Packet.new(frame.payload)
  next unless packet.udp?

  datagram = UDPDatagram.new(packet.payload)
  puts "RX #{datagram.payload.inspect} from #{packet.src_ip}:#{datagram.src_port}"

  # просто: возвращаем ответ в ВЕРХНЕМ регистре
  reply = UDPDatagram.to_bytes(
    src_port: datagram.dst_port, dst_port: datagram.src_port,
    payload: datagram.payload.upcase)
  packet.send_ipv4(socket, packet.src_ip, reply)
end

Чтобы увидеть результат: из отдельного файла отправьте UDP-дейтаграмму на тот же интерфейс loopback — одной строкой ruby -rsocket -e 'u = UDPSocket.new; u.bind("127.0.0.1", 0); u.send("hello", 0, "127.0.0.1", 1337)' — и наш сервер вернёт ответ «HELLO». Открытие и в объёме работы: почти ноль строк для реальной работы; большая часть кода — описание структур.

Уроки и следующие шаги

Главный вывод упражнения — образное понимание «стека» как сборочной линии: каждый слой работает только со своим «payload», не больше. Следующие шаги для вас — на уровне настоящих сетей: разбор TCP (с конечным автоматом и порядком байтов — сложнее), вычисление контрольной суммы для UDP/IPv4, реализация ARP для поиска MAC соседа и, наконец, «роутер» с несколькими интерфейсами и таблицей маршрутизации. Полный код проекта (стек RUDP) на GitHub: geckoboard/RUDP.

Инженерный постскриптум: IP-заголовок, создаваемый ядром (в IPPROTO_RAW), может немного отличаться — но пока модель ясна, это приемлемая отправная точка.

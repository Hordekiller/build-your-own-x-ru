Пишем nistow — управление dotfiles на Nim

Оригинальный источник: «Day 6: Manage your dotfiles easily with nistow»
↗ Перейти к оригинальному уроку فارسی — Персидская версия EN — English version

Введение

Сегодня мы создадим инструмент для лёгкого управления вашими dotfiles-файлами.

Структура dotfiles

text        i3
        `-- .config
            `-- i3
                `-- config

Итак, в верхнем уровне есть каталог с именем i3 — «имя приложения» (APP_NAME) — а под ним дерево путей конфигурации. Это значит, что файл config должен быть симлинком на путь .config/i3/config относительно «целевого каталога» (destination directory).

Примечание: целевой каталог по умолчанию — домашний каталог (Home).

Чего мы ожидаем?

shell➜  ~ nistow --help
    Stow 0.1.0
        -h | --help     : show help
        -v | --version  : show version
        --verbose       : verbose messages
        -s | --simulate : simulate stow operation
        -f | --force    : override old links
        -a | --app      : application path to stow
        -d | --dest     : destination to stow to
  • Флаг --simulate используется для имитации операции с файловой системой без реальных симлинков.
  • Каталог --app — каталог приложения, совместимый с описанной выше структурой dotfiles.
  • Каталог --dest — цель, под которой файлы будут симлинковаться; по умолчанию — домашний каталог.
shellnistow --app=/home/striky/wspace/dotfiles/localdir --dest=/tmp/tmpconf --verbose

Реализация

nimproc writeHelp() = 
    echo """
Stow 0.1.0 (Manage your dotfiles easily)

Allowed arguments:
    -h | --help     : show help
    -v | --version  : show version
    --verbose       : verbose messages
    -s | --simulate : simulate stow operation
    -f | --force    : override old links
    -a | --app      : application path to stow
    -d | --dest     : destination to stow to

    """

Процедура writeHelp — простая процедура (proc), выводящая строку справки в стандартный вывод (stdout).

nimproc writeVersion() =
    echo "Stow version 0.1.0"

Для вывода версии.

nimproc cli*() =

Точка входа (entry point) нашей CLI-программы.

nim  var 
    simulate, verbose, force: bool = false
    app, dest: string = ""

Эти переменные представляют различные опции, которые мы разрешаем в программе.

nim  if paramCount() == 0:
    writeHelp()
    quit(0)

Если не передано ни одного аргумента, выводим строку справки и выходим из программы — по терминологии Nim, с «exit» или «quit» и «кодом выхода» (exit status) 0.

nim  for kind, key, val in getopt():
    case kind
    of cmdLongOption, cmdShortOption:
        case key
        of "help", "h": 
            writeHelp()
            quit()
        of "version", "v":
            writeVersion()
            quit()
        of "simulate", "s": simulate = true
        of "verbose": verbose = true
        of "force", "f": force = true
        of "app", "a": app = val
        of "dest", "d": dest = val 
        else:
          discard
    else:
      discard

Здесь мы разбираем (parse) командную строку с помощью getopt.

nim  for kind, key, val in getopt():
    case kind
    of cmdLongOption, cmdShortOption:

Так, для команды --app=/home/striky/dotfiles/i3 -f тип (kind) для --app равен cmdLongOption, а для -f — cmdShortOption; ключ (key) для --app — app, для -f — f; значение (val) для --app — /home/striky/dotfiles/i3, а для -f в нашем разборе ставится true, потому что оно больше похоже на булев переключатель (boolean): если присутствует — значит, хотим установить его в true.

nim  if dest.isNilOrEmpty():
    dest = getHomeDir()

Здесь мы устанавливаем целевой каталог по умолчанию (dest) в домашний каталог.

nim  if app.isNilOrEmpty():
    echo "Make sure to provide --app flags"
    quit(1)

Здесь, если app не задан, выходим с «кодом ошибки» (exit status) 1.

nim  try:
    stow(getLinkableFiles(appPath=app, dest=dest), simulate=simulate, verbose=verbose, force=force)
  except ValueError:
    echo "Error happened: " & getCurrentExceptionMsg()

Здесь мы пытаемся засимлинковать все линкуемые файлы из каталога app в каталог dest, передавая все собранные из аргументов опции — simulate, verbose и force — и оборачиваем всё в try/except, чтобы ошибка была показана пользователю.

nimwhen isMainModule:
  cli()

Если этот модуль — главный модуль (main module), вызываем нашу точку входа cli.

Возвращаемся к stow и getLinkableFiles

Отлично! Вернёмся к stow и getLinkableFiles.

Начнём с getLinkableFiles. Помните структуру dotfiles?

nim    # appPath: каталог dotfiles-файлов приложения
    #     ожидается, что каталог имеет эту иерархию.
    #     i3
    #     `-- .config
    #         `-- i3
    #         `-- config

Мы хотим получить все находящиеся в нём файлы с полными путями; путь симлинка каждого — тот же путь, только имя appPath заменяется путём dest:

text[/home/striky/wspace/dotfiles/i3]/.config/i3/config -> [/home/striky]/.config/i3/config
__________________appPath________                      _____dest____
nimtype
  LinkInfo = tuple[original:string, dest:string]

Простой тип для представления исходного пути и места, куда нужно сделать симлинк.

nimproc getLinkableFiles*(appPath: string, dest: string=expandTilde("~")): seq[LinkInfo] =

    # Собирает линкуемые файлы в указанном приложении.

    # appPath: каталог dotfiles-файлов приложения
    #     ожидается, что каталог имеет эту иерархию.
    #     i3
    #     `-- .config
    #         `-- i3
    #         `-- config

    # dest: цель файлов симлинков; по умолчанию — домашний каталог пользователя.

Процедура getLinkableFiles принимает appPath и dest и возвращает seq из LinkInfo, которая выполняет это преобразование для каждого файла:

text[/home/striky/wspace/dotfiles/i3]/A_FILE_PATH -> [/home/striky]A_FILE_PATH
__________________apppath________                _____dest____
nim  var appPath = expandTilde(appPath)
  if not dirExists(appPath):
    raise newException(ValueError, fmt("App path {appPath} doesn't exist."))
  var linkables = newSeq[LinkInfo]()
  for filepath in walkDirRec(appPath, yieldFilter={pcFile}):
    let linkpath = filepath.replace(appPath, dest)
    var linkInfo : LinkInfo = (original:filepath, dest:linkpath)
    linkables.add(linkInfo)
  return linkables

Здесь мы обходим каталог appPath с помощью walkDirRec и в аргументе yieldFilter указываем, что нас интересует pcFile — «компонент пути файла»; иными словами, только записи типа обычного файла (regular file).

Процедура stow

nimproc stow(linkables: seq[LinkInfo], simulate: bool=true, verbose: bool=true, force: bool=false) = 
    # Создаёт симлинки и соответствующие каталоги

    # linkables — список кортежей (filepath, linkpath) : List[Tuple[file_path, link_path]]
    # simulate выполняет имитацию без какого-либо влияния на файловую систему: bool
    # verbose выводит сообщения лога: bool

  for linkinfo in linkables:
    let (filepath, linkpath) = linkinfo
    if verbose:
      echo(fmt("Will link {filepath} -> {linkpath}"))

    if not simulate:
      createDir(parentDir(linkpath))
      if not fileExists(linkpath):
        createSymlink(filepath, linkpath)
      else:
        if force:
          removeFile(linkpath)
          createSymlink(filepath, linkpath)
        else:
          if verbose:
            echo(fmt("Skipping linking {filepath} -> {linkpath}"))

Процедура stow очень простая: принимает список LinksInfo со всей информацией (имя исходного файла и цель симлинка) и выполняет симлинкинг — но только если это не имитация — и печатает сообщения, если включён verbose.

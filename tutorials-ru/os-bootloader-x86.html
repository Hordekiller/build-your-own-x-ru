Что такое загрузчик и зачем его писать

Когда компьютер включается, BIOS инициализирует систему, а затем смотрит на первый сектор (первые 512 байт) загрузочного диска: если два последних байта равны 0xAA55, этот сектор — загрузчик — загружается в память по адресу 0x7C00 и выполняется. Задача загрузчика — прочитать операционную систему с диска, разместить её в памяти и передать ей управление. Написание загрузчика — первый настоящий и увлекательный шаг на пути «создай свою операционную систему».

Структура проекта и инструменты

В проекте tiny-bootstrap всего три файла: bootloader.asm (код на ассемблере), Makefile и файл конфигурации Bochs. Инструменты: NASM для сборки, Bochs в роли эмулятора (замена QEMU) и dd для записи образа на диск. Сборка очень проста:

make# Сборка загрузчика в сырой бинарный файл
nasm -f bin bootloader.asm -o bootloader.bin

# Запись на файл образа диска (или настоящую/виртуальную дискету)
dd if=bootloader.bin of=disk.img conv=notrunc

# Запуск в эмуляторе Bochs
bochs -f bochsrc.txt

Код загрузчика: печать сообщения с помощью BIOS

В 16-битном режиме проще всего выводить текст через прерывание int 0x10 с функцией 0x0E, которая печатает один символ на экран. Цикл ниже печатает символы сообщения по одному. В конце обязательно нужно поставить jmp $, чтобы CPU остался в бесконечном цикле — выполнять больше нечего:

nasm; Мини-загрузчик — печать сообщения через видеосервис BIOS
[org 0x7c00]          ; загрузчик загружается по адресу 0x7C00
[bits 16]             ; 16-битный режим (real mode)

mov si, msg           ; адрес сообщения в si
call print            ; печать сообщения
jmp $                 ; бесконечный цикл (конец системы)

print:
    mov ah, 0x0e      ; функция BIOS «печать символа»
.loop:
    lodsb             ; следующий символ в al
    test al, al       ; конец строки (ноль)?
    jz .done
    int 0x10          ; печать символа
    jmp .loop
.done:
    ret

msg db 'Hello, World!', 0

times 510 - ($ - $$) db 0   ; заполнение до байта 510
dw 0xaa55                   ; магическое число загрузочного сектора

Критически важные части: [org 0x7c00] — базовый адрес, по которому BIOS помещает код (без него все относительные адреса сломаются), — и два последних байта 0xaa55 (на x86 действует little-endian, поэтому они записываются директивой dw).

Запуск в Bochs и отладка

Bochs — эмулятор x86, спроектированный для разработки операционных систем: у него есть встроенный отладчик, позволяющий смотреть регистры, память и пошаговое выполнение. Файл bochsrc.txt указывает Bochs, с какого образа диска загружаться. Именно этот «быстрый отклик» (сборка и запуск за несколько секунд) — главное преимущество разработки загрузчика в эмуляторе:

text# bochsrc.txt — конфигурация Bochs
megs: 32
floppya: 1_44=disk.img, status=inserted
boot: a
display_library: sdl2

После запуска на экране эмулятора появится слово «Hello, World!» — значит, ваш загрузчик работает.

Дальнейший путь: от загрузчика к ядру

Этот загрузчик ещё ничего не загружает — он лишь печатает сообщение. Естественные следующие шаги: чтение следующих секторов с диска через int 0x13, переход в 32-битный режим (protected mode), настройка GDT и, наконец, прыжок в ядро, написанное на C.

Дополнительно: этот урок (вместе с чужими переработками) — одна из самых популярных отправных точек в разработке ОС за последние 10 лет; его естественное продолжение — учебники 3zanders и os-tutorial, переведённые в этом же каталоге.

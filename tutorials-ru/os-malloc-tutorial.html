Malloc изнутри: учебник для ОС

Зачем писать malloc

С точки зрения программиста malloc — «магическая коробка». Этот урок открывает коробку: мы строим аллокатор памяти, который берёт у операционной системы сырую память (системным вызовом sbrk) и выдаёт её программе в виде структуры блоков. Этот проект — мост между обычным программированием и миром ОС: той самой памятью, которой управляют ядра.

Структура данных: связный список блоков

Сердце реализации — связный список блоков. У каждого блока есть заголовок с четырьмя полями: размер данных, указатель на следующий блок, флаг свободности и «магическое число» для обнаружения порчи памяти:

ctypedef struct block_meta {
    size_t size;          // размер данных этого блока
    struct block_meta *next;  // следующий блок в списке
    int free;             // 1 = свободен, 0 = занят
    int magic;            // магическое число (для поиска порчи)
} block_meta_t;

#define META_SIZE sizeof(block_meta_t)
#define MAGIC 0x77777777
#define ALIGN 8            // выравнивание: блоки по границе 8 байт

void *global_base = NULL;  // начало списка блоков

Выделение: поиск блока и его разбиение

Алгоритм malloc: ищем в списке свободный блок достаточного размера. Если найден — снимаем с него флаг свободности; если нет — берём новый блок у системы через sbrk. Если свободный блок сильно больше необходимого, его можно разбить (split), а остаток оставить как свободный блок:

cvoid *malloc(size_t size) {
    block_meta_t *block;

    // выравнивание размера по 8 байт
    size = (size + ALIGN - 1) & ~(ALIGN - 1);

    if (!global_base) {
        // первый раз: берём у системы начальный блок
        block = request_space(NULL, size);
        if (!block) return NULL;
        global_base = block;
    } else {
        // поиск свободного блока подходящего размера
        block = find_free_block(global_base, &size);
        if (!block) {
            block = request_space(global_base, size);
            if (!block) return NULL;
        } else {
            block->free = 0;    // помечаем занятым
            block->magic = MAGIC;
        }
    }
    return block + 1;   // данные начинаются после заголовка
}

Освобождение и слияние

Для free достаточно просто поменять флаг блока на «свободен» (и вернуть системе системным вызовом munmap последние блоки). Но чтобы избежать фрагментации памяти, свободные соседние блоки объединяются (coalescing) — если следующий блок тоже свободен, текущий объявляется больше:

cvoid free(void *ptr) {
    if (!ptr) return;
    block_meta_t *block = (block_meta_t *) ptr - 1;
    block->free = 1;
    block->magic = 0;

    // слияние со следующим свободным блоком
    if (block->next && block->next->free) {
        block->size += META_SIZE + block->next->size;
        block->next = block->next->next;
    }
}

Любопытно, что free гораздо проще malloc — потому что мы ничего по-настоящему не «удаляем», а просто сообщаем системе, что эта область снова пригодна для использования.

Результат и тестирование

Урок завершается тестовой программой, проверяющей выделение и освобождение разными паттернами. Полный тест проверяет: простую работу, многократное выделение, освобождение, повторное выделение того же адреса и возможную утечку памяти:

bashgcc -o test malloc.c test.c
valgrind --leak-check=full ./test
# вывод: утечек памяти нет
Дополнительно: этот маленький, но полный проект простым языком объясняет концепции, которые вы потом увидите в «управлении heap-памятью» ядер (например, в части 7 курса Джеймса Моллоя), ещё до входа в мир ядер.

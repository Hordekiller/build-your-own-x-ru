О курсе

Это один из самых классических и полных учебников по созданию ОС в интернете. Джеймс Моллой в десяти частях собирает монолитную ОС с unix-подобной архитектурой: от загрузки через GRUB до одновременного выполнения нескольких процессов с планировщиком. Каждая часть включает полную пояснительную статью, готовый код на C/ассемблере и советы по отладке.

Карта десяти частей

  • 1. Окружение: подготовка компилятора, линкера, GRUB и кросс-компиляция.
  • 2. Рождение: файлы загрузочного ассемблера, линковка и основная структура ядра.
  • 3. Экран: запись в память VGA и текстовый драйвер.
  • 4. GDT и IDT: таблицы дескрипторов и управление прерываниями.
  • 5. IRQ и PIT: контроллеры аппаратных прерываний и системный таймер — основа многозадачности.
  • 6. Страничная память: управление виртуальной памятью через страницы.
  • 7. Куча (Heap): динамический аллокатор памяти для ядра (kmalloc).
  • 8. VFS и initrd: виртуальная файловая система и загрузка программ из начального архива.
  • 9. Многозадачность: планировщик (scheduler) и переключение контекста — одновременное выполнение процессов.
  • 10. Пользовательский режим: переход CPU из ring 0 в ring 3 и запуск программ в защищённом пользовательском пространстве.

Пример кода: переключение контекста процесса

В части про многозадачность у каждого процесса есть «контекст», включающий регистры и адрес стека. Функция переключения сохраняет состояние предыдущего процесса и восстанавливает новый — это сердце планировщика любой современной ОС:

c// switch_context: сохранение и восстановление состояния процессов
void switch_context(process_t *next, process_t *prev) {
    // сохранение регистров текущего процесса в prev
    asm volatile(
        "movl %%esp, %0\n"   // стек
        "movl %%ebp, %1\n"   // кадр стека
        : "=r"(prev->esp), "=r"(prev->ebp));

    // загрузка регистров процесса next
    asm volatile(
        "movl %0, %%esp\n"
        "movl %1, %%ebp\n"
        : : "r"(next->esp), "r"(next->ebp));

    // продолжение выполнения с места остановки следующего процесса
    asm volatile("ret");
}

Этот «кооперативный» (cooperative) метод прост; дальше по курсу планировщик переписывается на прерываниях таймера (preemptive), чтобы каждый процесс «принудительно» получал свою долю CPU.

Сильные стороны и меры предосторожности

  • Полнота: от загрузчика до пользовательского режима и файловой системы — полный путь настоящего ядра.
  • Чистая архитектура: разделённые модули (screen, gdt, idt, paging, heap, vfs), которые можно развивать дальше.
  • Рабочий код: у каждой части полный код, собираемый через make и запускаемый в QEMU/Bochs.
  • Известные сложности: курс старый (около 2007 года); с новыми компиляторами и окружениями могут возникать ошибки сборки, а некоторые части (например, звук) неполны. Для решения обязательно настройте установку x86_64-elf-* и совместимые версии инструментов.
Дополнительно: этот курс — идеальный выбор для того, кто уже сделал «несколько маленьких ядер» и теперь хочет погрузиться в настоящие концепции ОС (планирование, виртуальная память, пользовательский режим).

Введение — о чём эта серия?

«Серия по физике игр» — коллекция обучающих постов Мин-Луня «Аллена» Чоу (инженера физики игр, работавшего в студиях вроде EA и Ubisoft), который делится опытом изучения симуляции игровой физики и архитектуры физического движка. Серия — один из самых полных и глубоких бесплатных ресурсов о «внутренностях физического движка», и почти весь материал сопровождается кодом и математикой.

Путь обучения серии по порядку:

  • Динамика движения — основы и реализация движения тел
  • Broadphase — быстрая фильтрация столкновений с помощью динамического AABB-дерева
  • Обнаружение столкновений — CSO, алгоритм GJK и генерация контактов через EPA
  • Разрешение столкновений — ограничения и последовательные импульсы, контактные ограничения
  • Стабильность — Slop и Warm Starting

Динамика движения (Motion Dynamics)

Основы (Fundamentals)

Эта статья закладывает математические основы движения: позиция, скорость (производная позиции по времени) и ускорение (производная скорости). Второй закон Ньютона F = ma — мост между силой и ускорением; здесь же интуитивно вводятся понятия массы, момента инерции и момента силы — основа всех следующих статей.

Реализации (Implementations)

Эта статья показывает, как реализовать основы: полуявное интегрирование Эйлера (метод стандарта современных движков) с фиксированным шагом времени, вместе с интегрированием вращения в двух измерениях:

cpp// Полуявное интегрирование Эйлера для линейного и углового движения
// сначала скорости, затем позиции:
v += (f / m) * dt;        // линейная скорость
w += (torque / I) * dt;   // угловая скорость
x += v * dt;              // позиция
angle += w * dt;          // ориентация

Важный момент этой статьи — система отсчёта: все величины должны вычисляться в едином пространстве (например, в мире игры) или правильно преобразовываться; ошибка здесь — одна из самых частых проблем самодельных движков.

Broadphase — обзор и динамическое AABB-дерево

Попарное тестирование столкновений всех пар тел (O(n²)) в большом мире непрактично. Broadphase — этап, который дёшево строит список «пар-кандидатов на столкновение», чтобы дорогой этап Narrowphase выполнялся только на них.

Статья «Обзор» сравнивает методы: Sweep and Prune и AABB-дерево. Статья «Динамическое AABB-дерево» фокусируется на методе современных движков вроде Box2D:

  • Каждое тело имеет AABB (выровненный по осям прямоугольник) — приближение его объёма.
  • Строится бинарное дерево, листья которого — AABB тел; каждый узел хранит AABB-родителя своих детей.
  • AABB держатся «толстыми» (fat), чтобы мало двигающиеся тела не требовали дорогого обновления дерева каждый кадр.
  • Когда рамка тела изменилась, спускаемся от корня дерева, чтобы найти правильное место; удаление, разрезание (splitting) и балансировка дерева тоже описаны в статье.

Результат: стоимость каждого кадра вместо O(n²) становится примерно O(n log n) — при n активных телах.

Обнаружение столкновений — CSO, GJK и EPA

После того как Broadphase дал пары-кандидаты, Narrowphase должен точно ответить «пересекаются ли эти две фигуры?» и, если пересекаются, сгенерировать точки контакта. Серия здесь имеет три связанные статьи:

CSO и функция поддержки (Support Function)

Разность Минковского двух фигур (сокращённо CSO) — это множество всех разностей точек двух фигур; важный факт: две фигуры пересекаются тогда и только тогда, когда начало координат находится внутри их CSO! Для проверки нужна лишь функция поддержки, возвращающая «самую внешнюю точку фигуры в направлении d»:

cpp// Функция поддержки: самая дальняя точка фигуры от начала, в направлении d
Vec2 support(const Vec2& direction) {
    float maxDot = -FLT_MAX;
    Vec2 best;
    for (const Vec2& p : vertices) {   // для многоугольников; для круга есть формула
        float dot = p.x * direction.x + p.y * direction.y;
        if (dot > maxDot) { maxDot = dot; best = p; }
    }
    return best;
}

Алгоритм GJK

Алгоритм Gilbert–Johnson–Keerthi находит расстояние между двумя выпуклыми фигурами (в движках этот метод предпочитают вместо SAT). Идея: вызывая функцию поддержки, мы строим симплекс (треугольник в 2D, тетраэдр в 3D) внутри CSO и итеративно приближаем его к началу координат, пока начало не окажется внутри (столкновение!) или не найдётся лучшая соседняя точка — цикл «мы ещё не видели / обработай / столкновение»:

textwhile true:
    d = ближайшая точка симплекса к началу координат (в направлении -> начало)
    if d == 0: return столкновение
    p = supportA(d) - supportB(-d)     # точка поддержки CSO
    if p·d < 0: return нет столкновения  # симплекс не может дотянуться до начала
    обновить симплекс с p (оставить ближайший подсимплекс)

EPA — генерация контактов

Когда GJK подтвердил столкновение, нужно извлечь точку контакта, нормаль столкновения и глубину проникновения — входные данные для этапа разрешения. Алгоритм Expanding Polytope Algorithm работает так: постоянно расширяет симплекс GJK через функцию поддержки, пока не получит многогранник, хорошо приближающий границу CSO; ближайшее к началу ребро и даёт нормаль контакта и глубину проникновения.

Разрешение столкновений — ограничения и последовательные импульсы

Теперь, когда контакты есть, нужно помешать телам проникать друг в друга. В этой части серия знакомит с методом последовательных импульсов (Sequential Impulse) — основным методом Box2D, Bullet и Chipmunk:

  • Ограничение (Constraint): правило, ограничивающее скорости тел — например, «относительная скорость вдоль нормали не должна быть проникающей». Два типа: ограничение-равенство и ограничение-неравенство (контакт относится ко второму).
  • Импульс (Impulse): мгновенное изменение скорости, без вмешательства времени — вместо очень жёсткой пружинной силы.
  • Последовательность: ограничения решаются по одному, и с остаточной ошибкой повторяются несколько итераций, пока решение не приблизится к сходимости.
cpp// Импульс вдоль нормали контакта (упрощённый скелет):
// 1) относительная скорость в точке контакта:  vRel = dot(vB - vA, normal)
// 2) сумма обратных масс/инерций:               invMassSum = invMassA + invMassB ...
// 3) величина импульса:                         j = -(vRel + bias) * k
// 4) применение:                                vA -= j * normal * invMassA ...
// 5) при необходимости повторить несколько раз (Solver Iterations)

Статья «Контактные ограничения» завершает это для многоточечных контактов: построение матрицы импульса вдоль нормали (и трения по двум касательным) и распределение импульса между несколькими точками контакта тел, касающихся одновременно нескольких тел (например, куб, лежащий на земле несколькими углами).

Стабильность — Slop и Warm Starting

Две последние статьи серии посвящены практическим проблемам симуляции столкновений; классические проблемы: «квадрат должен лежать на земле, но дрожит» или «стопка коробок постепенно оседает»:

  • Slop: допустимая величина проникновения (очень маленькая), при которой, если проникновение меньше, никакой реакции не происходит — позволяет дрожанию успокоиться. Стабилизация Баумгарте также добавляет в решатель «смещающий» (bias) член на основе глубины проникновения, чтобы мягко устранять проникновение.
  • Warm Starting: сохраняем импульсы предыдущего шага и подаём их решателю как начальное приближение следующего — сходимость в стопках и многоточечных контактах ускоряется в разы; это основа «стабильности» коммерческих движков.

Дополнительные статьи и слайды

  • Реализация функции поддержки для многогранников через полуребра: для использования GJK в 3D с выпуклыми мешами нужна функция поддержки; эффективный способ — структура данных half-edge и «восхождение» по конфигурациям CH/CH и V/V.
  • Обновление AABB многогранников: вместо вычисления AABB из всех вершин за O(n) — постепенный метод, обновляющий только по старейшим данным.
  • Слайды — физика на основе ограничений (Constraint-Based Physics): слайды публичной презентации серии с единым взглядом на все концепции.

Зачем пересобирать Git на Ruby

Git — мощный инструмент, которым мы пользуемся каждый день, но задумывались ли вы, как работает его «магия»? Внутренняя документация Git пугающая, неполная и без примеров; а изучение реальной реализации сложно, если вы не знаете C. Разборка и повторная сборка системы — один из лучших способов её понять. Статья делает это на Ruby: реализует Git для Rails-разработчиков, которые знают Ruby лучше, чем C.

Результат — RGit, который: выполняет команды через собственную rgit, инициализирует репозиторий (init), индексирует файлы (add) и снимает снапшоты (commit).

Шаг 1 — команды Git и философия Unix

Git построен модульно и следует «философии Unix»: маленькие острые инструменты. Каждая команда — отдельный файл-скрипт, а высокоуровневая команда лишь проксирует к ним. Достаточно соблюдать соглашение об именах, чтобы создать свою команду:

ruby#!/usr/bin/env ruby
# bin/rgit
command, *args = ARGV

if command.nil?
  $stderr.puts "Usage: rgit <command> [<args>]"
  exit 1
end

path_to_command = File.expand_path("../rgit-#{command}", __FILE__)
if !File.exist? path_to_command
  $stderr.puts "No such command"
  exit 1
end

exec path_to_command, *args

Этот скрипт делает одно из трёх: показывает справку, если подкоманда не передана; выдаёт ошибку, если скрипта подкоманды нет; или запускает подкоманду. Как добропорядочный гражданин Unix, сообщения об ошибках идут в stderr, а код выхода ненулевой.

Шаг 2 — инициализация репозитория (init)

Git хранит все данные и метаданные в папке .git в корне репозитория. Целевая структура:

терминал.rgit
├── HEAD
├── config
├── objects
│   ├── info
│   └── pack
└── refs
    ├── heads
    └── tags

HEAD — файл с фиксированным значением ref: refs/heads/master, а остальное дерево — пустые папки. «Большую часть этой структуры составляют последовательные вызовы Dir.mkdir»:

ruby#!/usr/bin/env ruby
# bin/rgit-init
RGIT_DIRECTORY = ".rgit".freeze
OBJECTS_DIRECTORY = "#{RGIT_DIRECTORY}/objects".freeze
REFS_DIRECTORY = "#{RGIT_DIRECTORY}/refs".freeze

if Dir.exists? RGIT_DIRECTORY
  $stderr.puts "Existing RGit project"
  exit 1
end

def build_objects_directory
  Dir.mkdir OBJECTS_DIRECTORY
  Dir.mkdir "#{OBJECTS_DIRECTORY}/info"
  Dir.mkdir "#{OBJECTS_DIRECTORY}/pack"
end

def build_refs_directory
  Dir.mkdir REFS_DIRECTORY
  Dir.mkdir "#{REFS_DIRECTORY}/heads"
  Dir.mkdir "#{REFS_DIRECTORY}/tags"
end

def initialize_head
  File.open("#{RGIT_DIRECTORY}/HEAD", "w") do |file|
    file.puts "ref: refs/heads/master"
  end
end

Dir.mkdir RGIT_DIRECTORY
build_objects_directory
build_refs_directory
initialize_head

$stdout.puts "RGit initialized in #{RGIT_DIRECTORY}"

Шаг 3 — добавление в область индекса (add)

Индексация файла состоит из нескольких шагов: вычисление SHA из содержимого файла, создание блоба со сжатием контента, сохранение блоба в objects/<первые два символа sha>/<остаток sha> и запись sha с путём в индекс.

Настоящий индекс Git — бинарный файл с заголовком DIRC и кучей метаданных (ctime, mtime, mode, uid, gid и т.д.), поэтому он выглядит как «набор бессмысленных символов». Статья ради простоты и читаемости выбирает простой текстовый формат:

ruby# Формат индекса RGit
<SHA> <path>
<SHA> <path>
<SHA> <path>
ruby#!/usr/bin/env ruby
# bin/rgit-add
require "digest"
require "zlib"
require "fileutils"

RGIT_DIRECTORY = ".rgit".freeze
OBJECTS_DIRECTORY = "#{RGIT_DIRECTORY}/objects".freeze
INDEX_PATH = "#{RGIT_DIRECTORY}/index"

path = ARGV.first
if path.nil?
  $stderr.puts "No path specified"
  exit 1
end

file_contents = File.read(path)
sha = Digest::SHA1.hexdigest file_contents
blob = Zlib::Deflate.deflate file_contents
object_directory = "#{OBJECTS_DIRECTORY}/#{sha[0..1]}"
FileUtils.mkdir_p object_directory
blob_path = "#{object_directory}/#{sha[2..-1]}"

File.open(blob_path, "w") { |file| file.print blob }
File.open(INDEX_PATH, "a") { |file| file.puts "#{sha} #{path}" }

После rgit add bin/rgit в хранилище объектов есть сжатый блоб, а в индексе — строка вроде b302dd6f8cd2b385b170e78c14503342c0ba6ae8 bin/rgit.

Шаг 4 — снятие снапшота (commit)

Блобы — это содержимое одного файла в определённый момент времени. Чтобы снять снапшот всего проекта, Git для каждой папки создаёт объект «tree»: деревья представляют папки, блобы — файлы, а вся структура завязывается на объект «commit». Команда commit делает три дела:

  • построение структуры tree/blob
  • создание объекта commit, указывающего на эту структуру
  • обновление текущей ветки, чтобы указывать на этот commit

Так как создание объектов — частая операция, она вынесена во вспомогательный класс:

ruby# lib/rgit/object
require "fileutils"

module RGit
  class Object
    def initialize(sha)
      @sha = sha
    end

    def write(&block)
      object_directory = "#{OBJECTS_DIRECTORY}/#{sha[0..1]}"
      FileUtils.mkdir_p object_directory
      object_path = "#{object_directory}/#{sha[2..-1]}"
      File.open(object_path, "w", &block)
    end

    private
    attr_reader :sha
  end
end

Затем сама команда commit: сначала индекс превращается в хеш-структуру дерева, потом эта структура рекурсивно превращается в tree-объекты на диске, а sha каждого записывается в родителя; сообщение коммита берётся из редактора пользователя ($VISUAL); в конце текущая ветка (читается из HEAD) указывает на новый commit, а индекс очищается:

ruby#!/usr/bin/env ruby
# bin/rgit-commit — сокращённо
def index_tree
  index_files.each_with_object({}) do |line, obj|
    sha, _, path = line.split
    segments = path.split("/")
    segments.reduce(obj) do |memo, s|
      if s == segments.last
        memo[segments.last] = sha
        memo
      else
        memo[s] ||= {}
        memo[s]
      end
    end
  end
end

def build_tree(name, tree)
  sha = Digest::SHA1.hexdigest(Time.now.iso8601 + name)
  object = RGit::Object.new(sha)
  object.write do |file|
    tree.each do |key, value|
      if value.is_a? Hash
        dir_sha = build_tree(key, value)
        file.puts "tree #{dir_sha} #{key}"
      else
        file.puts "blob #{value} #{key}"
      end
    end
  end
  sha
end

def build_commit(tree:)
  # Сообщение берётся через редактор $VISUAL
  sha = Digest::SHA1.hexdigest(Time.now.iso8601 + "user")
  object = RGit::Object.new(sha)
  object.write do |file|
    file.puts "tree #{tree}"
    file.puts "author user"
    file.puts
    file.puts message
  end
  sha
end

Итог: чтобы найти текущее состояние, из HEAD находим текущую ветку; ветка указывает на последний commit; commit указывает на корневой tree-объект; а тот — на деревья подпапок и блобы файлов. Эта структура взаимосвязанных объектов-указателей и есть то, что делает Git мощным: меняя несколько файлов-указателей, мы перемещаемся в любую точку истории.

Зачем это стоит того

  • Вы видите реальную структуру .git, индекса и объектов на настоящих примерах Ruby — не просто теорию
  • Вы испытываете на практике философию «маленьких острых инструментов» Git
  • Вы понимаете, почему Git может перемещаться по истории, меняя несколько файлов-указателей

Регексп-движок на Go

Введение

В этой статье мы строим простой движок регулярных выражений, который может использовать шаблон

[a-zA-Z][a-zA-Z0-9_.]+@[a-zA-Z0-9]+.[a-zA-Z]{2,}

(где . — литеральная точка вместо «любой символ»), чтобы проверять корректность адресов электронной почты. Используем язык Go. Статья разделена на 3 части:

  • Разбор (Parsing)
  • Построение машины состояний (Building the state machine)
  • Сопоставление (Matching)

Разбор (Parsing)

Сама по себе строка regex — просто строка. Нужно превратить её в нечто со структурой; например:

Токены// Исходная строка regex
"[a-zA-Z0-9_]+@[a-zA-Z0-9]+.[a-zA-Z]{2,}"
// Токены regex
Repeat(1, бесконечность):
   Range(a, b,...z, A, B,...,Z, 0,...,9, _)
Literal(@)
Repeat(1, бесконечность):
   Range(a, b,...z, A, B,...,Z, 0,...,9)
Literal(.)
Repeat(2, бесконечность):
   Range(a, b,...z, A, B,...,Z)

Основная идея при разборе строки regex проста: ищем символы с особыми смыслами, такие как * + ? () [] {}, и пытаемся с их помощью строить токены. Сначала определим несколько типов и констант:

gotype tokenType uint8 // <1>
const ( // <2>
   group         tokenType = iota
   bracket       tokenType = iota
   or            tokenType = iota
   repeat        tokenType = iota
   literal       tokenType = iota
   groupUncaptured tokenType = iota
)
type token struct { // <3>
   tokenType tokenType
   // содержимое для каждого токена будет разным
   // поэтому нужен гибкий тип
   value     interface{}
}
type parseContext struct { // <4>
   // индекс символа, который мы сейчас
   // обрабатываем в строке regex
   pos    int
   tokens []token
}
  • Просто псевдоним типа для символа.
  • Константы, определяющие тип токена, с которым мы работаем; вроде enum.
  • Основная структура токена; имеет тип и значение, которое в зависимости от типа может быть чем угодно.
  • parseContext помогает отслеживать позиции и хранить разобранные токены.

Теперь алгоритм разбора:

gofunc parse(regex string) *parseContext {
   ctx := &parseContext{
      pos:    0,
      tokens: []token{},
   }
   for ctx.pos < len(regex) {
      process(regex, ctx)
      ctx.pos++
   }
   return ctx
}
  • Проходим по каждому символу и обрабатываем его, пока не дойдём до конца строки regex.

Теперь посмотрим на метод process. Он посложнее; разберём его шаг за шагом.

gofunc process(regex string, ctx *parseContext) {
    ch := regex[ctx.pos]
    if ch == '(' { // <1>
        groupCtx := &parseContext{
            pos:    ctx.pos,
            tokens: []token{},
        }
        parseGroup(regex, groupCtx)
        ctx.tokens = append(ctx.tokens, token{
            tokenType: group,
            value:     groupCtx.tokens,
        })
    } else if ch == '[' { // <2>
        parseBracket(regex, ctx)
    } else if ch == '|' { // <3>
        parseOr(regex, ctx)
    } else if ch == '*' || ch == '?' || ch == '+' { // <4>
        parseRepeat(regex, ctx)
    } else if ch == '{' { // <5>
        parseRepeatSpecified(regex, ctx)
    } else { // <6>
        // литерал
        t := token{
            tokenType: literal,
            value:     ch,
        }
        ctx.tokens = append(ctx.tokens, t)
    }
}

Как уже говорилось, пытаемся сопоставить известные символы и использовать их для разбора токенов.

  • Если текущий символ — (, имеем дело с группой и пытаемся разобрать несколько следующих символов как группу.
  • Если [ — скобочное выражение.
  • Если | — альтернатива (Or).
  • Символы * (звёздочка Клини), + и ? обозначают повторение. ? означает необязательность; в терминах повторения — максимум один раз.
  • Фигурные скобки тоже задают повторение: a* == a{0,}, a+ == a{1,}, a? == a{0,1}.
  • Если ничего из этого — считаем литералом. Заметьте: это упрощённая реализация; есть много случаев, которые нужно учитывать. Упрощённый алгоритм также не учитывает escape-символы (то есть \a считается конкатенацией литералов \ и a).

Теперь разберём каждую определённую функцию. Начнём с разбора групповых выражений (1):

gofunc parseGroup(regex string, ctx *parseContext) {
   ctx.pos += 1 // пропустить открывающую скобку
   for regex[ctx.pos] != ')' {
      process(regex, ctx)
      ctx.pos += 1
   }
}
  • Обрабатываем каждый символ, как в методе parse, пока не дойдём до закрывающей скобки. Обработку ошибок не покрываем; если индекс выйдет за границы, всё равно случится panic.

Что делает дополнительный код вокруг parseGroup в функции process? Мы создаём контекст специально для каждой группы, чтобы упаковать все токены внутри конкретной группы, не смешивая с контекстом верхнего уровня. После окончания разбора группы все токены заворачиваются в новый токен типа group и добавляются в общий список токенов.

Теперь посмотрим, как разбирать скобочные выражения (2). Вот вся функция:

gofunc parseBracket(regex string, ctx *parseContext) {
    ctx.pos++ // пропустить открывающую скобку [
    var literals []string
    for regex[ctx.pos] != ']' { // <1>
        ch := regex[ctx.pos]
        if ch == '-' { // <2>
            next := regex[ctx.pos+1] // <3-1>
            prev := literals[len(literals)-1][0] // <3-1>
            literals[len(literals)-1] = fmt.Sprintf("%c%c", prev, next) // <3-2>
            ctx.pos++  // чтобы потребить символ next
        } else { // <4>
            literals = append(literals, fmt.Sprintf("%c", ch))
        }
        ctx.pos++ // <5>
    }
    literalsSet := map[uint8]bool{}
    for _, l := range literals { // <6>
        for i := l[0]; i <= l[len(l)-1]; i++ { // <7>
            literalsSet[i] = true
        }
    }
    ctx.tokens = append(ctx.tokens, token{ // <8>
        tokenType: bracket,
        value:     literalsSet,
    })
}
  • Как с группой, идём до закрывающей скобки ].
  • Проверяем, не - ли это, потому что он обозначает диапазон (например, a-zK-Z2-8).
  • Когда видим знак диапазона: берём следующий символ и предыдущий (последний элемент списка литералов) и храним их как два символа вместе.
  • Если нет — одиночный литерал, добавляем в список.
  • Переходим к следующему символу.
  • Список literals содержит и литералы, и диапазоны, и они могут повторяться (например, [a-me-s]). Проходим по сохранённым значениям и добавляем каждый литерал в literalsSet; множества по своей природе не содержат дубликатов. В Go используем map, потому что встроенного множества нет.
  • Добавляем все символы между первым и последним из сохранённого значения. Для одиночных литералов — только сам литерал; для диапазонов — все от первого до последнего (включительно).
  • Наконец, добавляем токен скобки в список токенов.

Дальше — parseOr, разбирающий альтернативы (3):

gofunc parseOr(regex string, ctx *parseContext) {
    // <1:start>
    rhsContext := &parseContext{
        pos:    ctx.pos,
        tokens: []token{},
    }
    rhsContext.pos += 1 // пропустить |
    for rhsContext.pos < len(regex) && regex[rhsContext.pos] != ')' {
        process(regex, rhsContext)
        rhsContext.pos += 1
    }
    // <1:end>
    // обе стороны выражения OR
    left := token{
        tokenType: groupUncaptured,
        value:     ctx.tokens, // <2>
    }
    right := token{ // <3>
        tokenType: groupUncaptured,
        value:     rhsContext.tokens,
    }
    ctx.pos = rhsContext.pos // <4>
    ctx.tokens = []token{{ // <5>
        tokenType: or,
        value:     []token{left, right},
    }}
}
  • Операция альтернативы имеет синтаксис <левая>|<правая>. К моменту встречи | мы уже разобрали всё слева от него. Теперь время разбирать правую сторону; код почти такой же, как для групп. Создаём пустой контекст для правой стороны и собираем в нём все токены до конца строки regex или до закрывающей скобки.
  • Левая сторона содержит все токены, находящиеся в основном контексте.
  • Для правой берём все токены, собранные в rhsContext. Для обеих используем тип groupUncaptured — тип, созданный для обозначения группы токенов.
  • Обновляем позицию основного контекста.
  • Создаём токен альтернативы и добавляем в основной контекст. Важно: старые токены в основном контексте не сохраняем, потому что они уже внутри токена альтернативы.

Теперь повторения (4):

goconst repeatInfinity = -1
func parseRepeat(regex string, ctx *parseContext) {
    ch := regex[ctx.pos]
    var min, max int
    if ch == '*' {
        min = 0
        max = repeatInfinity
    } else if ch == '?' {
        min = 0
        max = 1
    } else {
        // ch == '+'
        min = 1
        max = repeatInfinity
    }
    // нужно обернуть последний токен данными счётчика,
    // чтобы знать, к чему применяются min и max
    lastToken := ctx.tokens[len(ctx.tokens)-1]
    ctx.tokens[len(ctx.tokens)-1] = token{
        tokenType: repeat,
        value: repeatPayload{
            min:   min,
            max:   max,
            token: lastToken,
        },
    }
}
  • Базовая идея: каждый символ здесь имеет определённое минимальное и максимальное число повторений. repeatInfinity равен -1, но мы считаем его бесконечностью.
  • После определения границ берём последний разобранный токен (потому что символы повторения всегда стоят справа от токена), оборачиваем его в токен repeat с нужными границами и сохраняем на той же позиции списка токенов.

Другой оператор повторения имеет код чуть длиннее, но идея та же (5):

gofunc parseRepeatSpecified(regex string, ctx *parseContext) {
    // +1 потому что пропускаем открывающую скобку {
    start := ctx.pos + 1
    // идём до конца фигурных скобок
    for regex[ctx.pos] != '}' {
        ctx.pos++
    }
    boundariesStr := regex[start:ctx.pos] // <1>
    pieces := strings.Split(boundariesStr, ",") // <2>
    var min, max int
    if len(pieces) == 1 { // <3>
        if value, err := strconv.Atoi(pieces[0]); err != nil {
            panic(err.Error())
        } else {
            min = value
            max = value
        }
    } else if len(pieces) == 2 { // <4>
        if value, err := strconv.Atoi(pieces[0]); err != nil {
            panic(err.Error())
        } else {
            min = value
        }
        if pieces[1] == "" {
            max = repeatInfinity
        } else if value, err := strconv.Atoi(pieces[1]); err != nil {
            panic(err.Error())
        } else {
            max = value
        }
    } else {
        panic(fmt.Sprintf("для счётчика нужно указать 1 или 2 значения: '%s'", boundariesStr))
    }
    // <5>
    lastToken := ctx.tokens[len(ctx.tokens)-1]
    ctx.tokens[len(ctx.tokens)-1] = token{
        tokenType: repeat,
        value: repeatPayload{
            min:   min,
            max:   max,
            token: lastToken,
        },
    }
}
  • Берём строку границ; всё между {}.
  • Разбиваем её по запятой.
  • Если один элемент (например, {1}) — точное число повторений, min и max равны.
  • Если два элемента, первый — min, второй — max (например, {3,7}). Если второго нет ({3,}), нужно минимум три повторения и потолка нет; то есть repeatInfinity.
  • Теперь, имея границы, берём последний разобранный токен, оборачиваем в токен repeat с нужными границами и сохраняем.

На этом разбор строки regex завершается. В следующей части научимся строить из токенов машину состояний.

Построение машины состояний

В этой части узнаём, как из разобранных токенов построить машину состояний; но сначала посмотрим, что такое машина состояний.

Что такое конечная машина состояний?

Конечная машина состояний (FSM) или конечный автомат (FA) — абстрактная машина из конечного множества состояний, начального состояния, конечных состояний и переходов между ними. FA бывают двух видов: детерминированный (DFA) и недетерминированный (NFA).

Проверка принадлежности делается так:

  • Всегда начинаем в стартовом состоянии.
  • Берём первый символ входной строки и смотрим, есть ли соответствующий переход: если есть — переходим в то состояние и продолжаем со следующим символом; если нет — строка не принимается.
  • Повторяем до конца строки и проверяем, находимся ли в конечном состоянии.
  • Нахождение в конечном состоянии означает, что строка принята.

В DFA при одном и том же состоянии и входе всегда попадаешь в одно и то же целевое состояние. Он детерминирован.

В NFA при одном и том же состоянии и входе можно попасть в разные состояния; он недетерминирован. epsilon означает пустой вход. Этот NFA принимает только строки abd и ace; но со значением epsilon можно войти в несколько состояний.

В следующих разделах берём список разобранных токенов и строим из них epsilon-NFA. Когда NFA готов, нужно пройти по каждому состоянию и попытаться потреблять символы входной строки один за другим, проверяя, дойдём ли до конечного состояния.

От regex к epsilon-NFA

Предыдущий шаг даёт список токенов. Превращаем их в epsilon-NFA. Для этого используем алгоритм под названием «конструкция Томпсона» — алгоритм построения и объединения нескольких NFA в один NFA.

Для представления состояния NFA используем эту простую структуру:

gotype state struct {
    start       bool
    terminal    bool
    transitions map[uint8][]*state
}
  • start показывает, является ли это состояние точкой входа.
  • terminal показывает, конечное ли это состояние. Попадание в него означает, что вход соответствует regex.
  • transitions — карта, в которой символ сопоставляется со списком разных состояний.

Есть начальное состояние (розовое) и конечное (синее). Для каждого токена строим отдельный NFA, и эти NFA объединяются epsilon-переходами. Последнее состояние предыдущего NFA соединяется с первым состоянием следующего.

Есть epsilon-переход от стартового состояния к первому состоянию (s1) объединённых NFA и один — от последнего состояния объединённых NFA к конечному.

То же самое в коде:

goconst epsilonChar uint8 = 0 // пустой символ
func toNfa(ctx *parseContext) *state {
    startState, endState := tokenToNfa(&ctx.tokens[0]) // <1>
    for i := 1; i < len(ctx.tokens); i++ { // <2>
        startNext, endNext := tokenToNfa(&ctx.tokens[i]) // <3>
        endState.transitions[epsilonChar] = append(
            endState.transitions[epsilonChar],
            startNext,
        ) // <4>
        endState = endNext // <5>
    }
    start := &state{ // <6>
        transitions: map[uint8][]*state{
            epsilonChar: {startState},
        },
        start: true,
    }
    end := &state{ // <7>
        transitions: map[uint8][]*state{},
        terminal:    true,
    }
    endState.transitions[epsilonChar] = append(
        endState.transitions[epsilonChar],
        end,
    ) // <8>
    return start // <9>
}
  • Берём первый токен и превращаем в NFA. tokenToNfa создаёт NFA из токена и возвращает его начальное и конечное состояния.
  • Проходим по остальным токенам.
  • Для каждого токена вызываем tokenToNfa и сохраняем начальное и конечное состояния.
  • Соединяем конечное состояние предыдущего вызова с начальным состоянием нового NFA.
  • Сохраняем конечное состояние, оно понадобится в следующей итерации.
  • Создаём стартовое состояние; с epsilon-переходом к началу первого NFA.
  • Создаём конечное состояние.
  • Теперь конечное состояние последнего NFA имеет epsilon-переход к конечному состоянию.
  • В итоге возвращаем стартовое состояние, потому что это точка входа.

Теперь, имея общий план построения NFA, посмотрим, как каждый токен превращается в NFA:

go// возвращает (start, end)
func tokenToNfa(t *token) (*state, *state) {
    start := &state{
        transitions: map[uint8][]*state{},
    }
    end := &state{
        transitions: map[uint8][]*state{},
    }
    switch t.tokenType {
    case literal:
    case or:
    case bracket:
    case group, groupUncaptured:
    case repeat:
    default:
        panic("неизвестный тип токена")
    }
    return start, end
}
  • Код выше — скелет tokenToNfa; каждый тип токена и его обработку увидим дальше.
  • В целом создаём пустые состояния start и end, логика выполняется в switch, и возвращаем их.

Литералы

Начнём с литералов, потому что они проще всего. Чтобы пройти от start к end, нужен переход ch; ch — одиночный символ.

gocase literal:
    ch := t.value.(uint8)
    start.transitions[ch] = []*state{end}

t.value указывает на значение, сохранённое при разборе в структуре token.

Альтернатива (or)

Or означает выбор между двумя разными путями. Вспомните: в фазе разбора значение токена or имеет две стороны — левую и правую; каждая представляет отдельный NFA. Для построения NFA альтернативы нужно:

  • Epsilon-переход от стартового состояния к началу обоих NFA — левого и правого
  • Epsilon-переход от конца обоих NFA к конечному состоянию
gocase or:
    values := t.value.([]token)
    left := values[0]
    right := values[1]
    s1, e1 := tokenToNfa(&left) // <1>
    s2, e2 := tokenToNfa(&right) // <1>
    start.transitions[epsilonChar] = []*state{s1, s2} // <2>
    e1.transitions[epsilonChar] = []*state{end} // <3>
    e2.transitions[epsilonChar] = []*state{end} // <3>
  • Строятся оба NFA — левый и правый.
  • Стартовое состояние epsilon-переходом соединяется с началом обоих NFA.
  • Конечное состояние каждого NFA epsilon-переходом соединяется с конечным состоянием NFA альтернативы.

Скобочные выражения

Скобочные выражения можно считать большой альтернативой; например, [a-c0-2x] означает a|b|c|0|1|2|x. Маленькая разница: мы имеем дело с литералами, а не произвольными NFA, поэтому просто для каждого литерала создаём переход от стартового состояния к конечному.

gocase bracket:
    literals := t.value.(map[uint8]bool)
    for l := range literals { // <1>
        start.transitions[l] = []*state{end} // <2>
    }
  • Проходим по каждому литералу скобки.
  • Добавляем переход от start к end.

Группы

Чтобы превратить группу в NFA, конкатенируем все отдельные NFA, построенные из токенов внутри группы. Это мы уже видели в функции toNFA; код тот же:

go// в нашем движке нет разницы между
// group и groupUncaptured
case group, groupUncaptured:
    tokens := t.value.([]token)
    start, end = tokenToNfa(&tokens[0])
    for i := 1; i < len(tokens); i++ {
        ts, te := tokenToNfa(&tokens[i])
        end.transitions[epsilonChar] = append(
            end.transitions[epsilonChar],
            ts,
        )
        end = te
    }

Повторение

Из всех рассмотренных случаев повторение, пожалуй, труднее всего понять; идём шаг за шагом и пытаемся найти общее решение, покрывающее все случаи повторения. Во всех дальнейших примерах A — произвольный NFA.

Начнём со звёздочки (замыкание Клини), плюса и вопросительного знака (необязательность). Во всех трёх примерах указаны соответствующие минимальное и максимальное числа вхождений.

  • Каждый пример имеет epsilon-переход от стартового состояния к началу A и от конца A к конечному состоянию; то есть повторение ровно один раз NFA A.
  • * означает, что A можно проигнорировать или повторить сколько угодно раз: для игнорирования добавлен прямой epsilon-переход от стартового состояния к конечному (полный обход A); для бесконечного повторения — epsilon-переход от конечного состояния к началу A.
  • + означает минимум одно повторение без потолка: чтобы обеспечить минимум один, убираем epsilon-переход из примера *; теперь обойти A нельзя.
  • ? означает либо игнорировать, либо ровно один раз: очень похоже на *, только убран epsilon-переход от конечного состояния к началу A.

Заметки:

  • Если минимум равен нулю, добавь epsilon-переход от стартового состояния к конечному.
  • Если максимум — бесконечность, добавь epsilon-переход от конечного состояния к началу A.

Теперь случай точного числа повторений:

Просто конкатенируем тот же NFA A m раз.

Если минимум задан, а потолок — бесконечность:

Опять конкатенируем NFA A m раз, потому что это минимальное число повторений; но добавляем и epsilon-переход от конечного состояния к началу последнего экземпляра A.

Финальный случай: и минимум, и максимум заданы, и максимум — не бесконечность:

A должен повторяться m раз, поэтому конкатенируем его m раз. Остальные (n-m) повторений полностью необязательны; значит, после достижения минимума нужно уметь попасть в конечное состояние. Для раннего завершения добавляем epsilon-переход от стартового состояния каждого экземпляра A к конечному состоянию.

Теперь посмотрим, как это закодировано:

gocase repeat:
    p := t.value.(repeatPayload)
    if p.min == 0 { // <1>
        start.transitions[epsilonChar] = []*state{end}
    }
    var copyCount int // <2>
    if p.max == repeatInfinity {
        if p.min == 0 {
            copyCount = 1
        } else {
            copyCount = p.min
        }
    } else {
        copyCount = p.max
    }
    from, to := tokenToNfa(&p.token) // <3>
    start.transitions[epsilonChar] = append( // <4>
        start.transitions[epsilonChar],
        from,
    )

    for i := 2; i <= copyCount; i++ { // <5>
        s, e := tokenToNfa(&p.token)
        // соединить конец предыдущего с началом этого
        to.transitions[epsilonChar] = append( // <6>
            to.transitions[epsilonChar],
            s,
        )

        // отслеживать состояния входа и выхода предыдущего NFA
        from = s // <7>
        to = e   // <7>
        // после минимально необходимых повторений
        // остальные должны быть необязательными; поэтому к началу
        // каждого NFA добавляем epsilon-переход,
        // чтобы при необходимости их можно было пропустить
        if i > p.min { // <8>
            s.transitions[epsilonChar] = append(
                s.transitions[epsilonChar],
                end,
            )
        }
    }
    to.transitions[epsilonChar] = append( // <9>
        to.transitions[epsilonChar],
        end,
    )

    if p.max == repeatInfinity { // <10>
        end.transitions[epsilonChar] = append(
            end.transitions[epsilonChar],
            from,
        )
    }
  • Если минимум — ноль, нужен epsilon-переход от стартового состояния к конечному.
  • copyCount — максимальное число раз, которое нужно построить NFA из p.token: если потолок — бесконечность и минимум — ноль, то 1, потому что нужна минимум одна копия; если потолок — бесконечность и минимум не ноль, то значение min (нужно минимум p.min раз); если потолок не бесконечность — значение max.
  • Как с группой, нужно конкатенировать несколько NFA; поэтому начинаем со сборки первой версии.
  • Стартовое состояние соединяется с началом этого нового NFA.
  • Проходим остальные повторения.
  • Собственно шаг конкатенации; здесь конец предыдущего NFA соединяется с началом текущего.
  • Сохраняем начало и конец текущего NFA.
  • После построения минимального числа нужных NFA остальные должны быть необязательными; поэтому от начала каждого необязательного NFA добавляем epsilon-переход к конечному состоянию.
  • Соединяем конец последнего NFA с конечным состоянием.
  • Если потолок — бесконечность, добавляем epsilon-переход от конечного состояния к началу последнего NFA.

Сопоставление

Финальный кусок нашего движка — логика сопоставления. Базовая идея: по очереди подаём каждый символ тестовой строки текущему состоянию NFA, пока не дойдём до конца строки. Если строка закончилась и мы в конечном состоянии — строка соответствует regex.

Во время обхода строки используем указатель/курсор на конкретную позицию в строке. Помимо каждого индекса строки, наш указатель может указывать на начало строки (до сопоставления) и конец строки (после потребления всех символов).

В коде у нас такие константы и вспомогательный метод:

goconst (
    startOfText uint8 = 1
    endOfText   uint8 = 2
)
func getChar(input string, pos int) uint8 {
    if pos >= len(input) {
        return endOfText
    }
    if pos < 0 {
        return startOfText
    }
    return input[pos]
}

И код сопоставления:

gofunc (s *state) check(input string, pos int) bool { // <1>
    ch := getChar(input, pos) // <2>
    if ch == endOfText && s.terminal { // <3>
        return true
    }
    if states := s.transitions[ch]; len(states) > 0 { // <4>
        nextState := states[0]
        if nextState.check(input, pos+1) { // <5>
            return true
        }
    }
    for _, state := range s.transitions[epsilonChar] { // <6>
        if state.check(input, pos) { // <7>
            return true
        }
        if ch == startOfText && state.check(input, pos+1) { // <8>
            return true
        }
    }
    return false // <9>
}
  • (s *state) — просто способ добавить функцию к структуре state в Go; к алгоритму отношения не имеет.
  • Берём текущий проверяемый символ; либо валидный символ строки, либо startOfText, либо endOfText.
  • Если мы в конце строки и в конечном состоянии — значит, сопоставление есть; возвращаем true.
  • Проверяем, задан ли переход для текущего символа.
  • Если переход есть, берём следующее состояние, продвигаем указатель на шаг и проверяем. Если успешно — возвращаем true.
  • Если символьного перехода нет, проверяем пустые/epsilon-переходы.
  • Для всех этих переходов пробуем следующее состояние с тем же входом и позицией; поскольку переход пустой, позицию увеличивать не нужно.
  • Есть риск застрять в начале текста и никогда не продвинуться; это условие предотвращает его.
  • Если ничего не сопоставилось — неудача, возвращаем false.

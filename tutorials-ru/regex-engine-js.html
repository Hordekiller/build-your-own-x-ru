Регексп-движок на JavaScript

Введение

Понимание и правильное использование регулярных выражений — ценный навык в обработке текста. Из-за своего декларативного и вместе с тем идиоматического синтаксиса регулярные выражения порой могут быть источником путаницы (и даже тревоги!) среди разработчиков ПО. В этой статье реализуем простой и эффективный движок regex. Определим синтаксис наших выражений, научимся их разбирать и построим распознаватель. Сначала кратко покроем теоретические основы.

Конечные автоматы

Неформально, конечный автомат (или конечная машина состояний) — абстрактная машина с состояниями и переходами между ними. Он всегда находится в одном из своих состояний и, читая вход, переходит из состояния в состояние. У него есть начальное состояние и одно или более конечных (принимающих) состояний.

Детерминированный конечный автомат (DFA)

На рисунке 1.1 автомат с четырьмя состояниями; q0 — начальное состояние, q3 — конечное (принимающее) состояние. Он распознаёт все строки, начинающиеся с «ab», за которыми идёт произвольное число «b», и заканчивающиеся на «a». Если пропустить строку «abba» через машину рисунка 1.1, проходим такие состояния:

Таблицашаг   состояние   вход   новое состояние
0     q0          a      q1
1     q1          b      q2
2     q2          b      q2
3     q2          a      q3

Для строк «aba», «abbba» или «abbbbba» автомат заканчивает в принимающем состоянии q3. Если в любой момент обработки у машины нет состояния для данного входного символа, исполнение останавливается и строка не распознаётся. Поэтому «ab» не распознаётся (потому что заканчивается в непринимающем состоянии q2) и «abca» тоже нет (потому что из q2 нет перехода по символу «c»). В примере рисунка 1.1 для каждого валидного входного символа в каждом состоянии мы можем закончить ровно в одном состоянии; говорим, что машина детерминирована (DFA).

Недетерминированный конечный автомат (NFA)

Видно, что из q1 по входу «b» можно попасть в два состояния — q1 и q2. В этом случае говорим, что машина недетерминирована (NFA). Легко видно, что эта машина эквивалентна машине рисунка 1.1; то есть распознаёт то же множество строк. Любой NFA можно превратить в соответствующий DFA.

ε-NFA

ε-NFA представляем точно так же, как NFA, но с одним исключением: он содержит переходы по пустой строке — ε. То есть из состояния можно перейти в другое, не читая ни одного входного символа. На рисунке 1.3 видим ε-переход из q2 в q1. Этот ε-NFA эквивалентен NFA рисунка 1.2.

Компиляция регулярных выражений в конечные автоматы

Множество строк, распознаваемых конечным автоматом A, называется языком A и обозначается L(A). Если язык распознаваем конечным автоматом, то ему соответствует и регулярное выражение, описывающее тот же язык, и наоборот (теорема Клини). Иными словами, регулярные выражения можно считать дружественной заменой конечных автоматов для описания шаблонов в тексте.

Конструкция Томпсона

Алгебры начинаются с элементарных выражений, обычно констант и/или переменных. Затем позволяют строить более сложные выражения применением набора операций к элементарным. Обычно нужен и способ группировки операторов с операндами, например скобки. Регулярные выражения не отличаются: с константами, переменными и операторами в качестве строительных блоков они представляют формальные языки (множества строк).

Мы описываем реализацию Кена Томпсона, представленную в его статье Regular Expression Search Algorithm (1968).

Чтобы скомпилировать выражение R в NFA, сначала нужно разобрать R на составляющие подвыражения. Правила построения NFA можно разделить на две части:

  • Базовые правила для работы с подвыражениями без операторов.
  • Индуктивные правила для построения больших NFA из меньших применением операторов.

Базис

Автомат, распознающий пустую строку ε; i — начальное состояние, f — принимающее.

Для символа «a» строим автомат. Каждый символ входного алфавита считаем выражением самим по себе. Язык этого автомата состоит только из слова «a».

Индукция

Предположим, у нас есть два выражения S и T и их NFA N(S) и N(T):

а) Объединение: R = S | T

Вводим начальное состояние i и добавляем ε-переходы от него к начальным состояниям N(S) и N(T). Затем добавляем переходы от конечных состояний N(S) и N(T) к заново созданному состоянию f и помечаем их непринимающими. Полученный NFA распознаёт строки, принадлежащие либо L(S), либо L(T).

б) Конкатенация: R = S · T

Помечаем принимающее состояние N(S) непринимающим и добавляем переход от него к начальному состоянию N(T). Получаем NFA, распознающий все конкатенации строк vw, где v принадлежит L(S), а w — L(T).

в) Замыкание (звёздочка Клини): R = S*

Вводим i как начало и f как принимающее состояние. Добавляем ε-переходы: от i к f, от i к начальному состоянию N(S); затем соединяем принимающее состояние N(S) с f и, наконец, добавляем переход от конечного состояния N(S) к его началу. Конечное состояние N(S) помечаем промежуточным.

Оператор замыкания (*) имеет наивысший приоритет, затем конкатенация (·). Объединение (|) — самый низкоприоритетный. Современные реализации regex имеют больше операторов, например + (один и более) и ? (ноль или один); их реализация аналогична приведённым и для краткости опущена.

Пример

Приведём пример. Хотим построить NFA для (a|b)*c. Язык этого выражения содержит все строки с нулём и более «a» или «b», заканчивающиеся на «c». Как в арифметических выражениях, скобки используются для явного задания приоритета операторов. Разбиваем выражение на атомарные подвыражения и строим снизу вверх. По порядку приоритета:

  • Построение N(a): NFA для «a»
  • Построение N(b): NFA для «b»
  • Применение объединения к N(a) и N(b) ← N(a|b)
  • Применение замыкания к N(a|b) ← N((a|b)*)
  • Применение конкатенации к N((a|b)*) и N(c) ← N((a|b)*c)

Разбор регулярного выражения

Сначала нужно предобработать строку, добавив явный оператор конкатенации. По статье, используем точку (.). Так, выражение abc превращается в a · b · c, а (a|b)c — в (a|b) · c.

Есть разные способы разбора выражения. Мы следуем основному пути статьи Томпсона: превращение выражения из инфиксной нотации в постфиксную. Так можно просто применять операторы в заданном порядке приоритета. (Реализация этой предобработки в менее чем 40 строках JavaScript есть в репозитории regexjs; алгоритм Shunting-yard хорошо объяснён.)

Построение NFA

Представляем состояние NFA как объект со следующими свойствами:

jsfunction createState(isEnd) {
    return {
        isEnd,
        transition: {},
        epsilonTransitions: []
    };
}

У нас два типа переходов — по символу и по эпсилон (пустой строке). Состояние в NFA Томпсона имеет либо символьный переход максимум в одно состояние, либо эпсилон-переходы максимум в два состояния; но не может одновременно иметь символьный и эпсилон-переходы.

jsfunction addEpsilonTransition(from, to) {
    from.epsilonTransitions.push(to);
}

function addTransition(from, to, symbol) {
    from.transition[symbol] = to;
}

Из нашего базиса есть два типа NFA, служащих строительными блоками: ε-NFA и символ-NFA. Реализуем их так:

jsfunction fromEpsilon() {
    const start = createState(false);
    const end = createState(true);
    addEpsilonTransition(start, end);

    return { start, end };
}

function fromSymbol(symbol) {
    const start = createState(false);
    const end = createState(true);
    addTransition(start, end, symbol);

    return { start, end };
}

NFA — просто объект, хранящий ссылки на свои начальное и конечное состояния. Следуя индуктивным правилам (описанным выше), строим большие NFA из меньших применением трёх операций:

jsfunction concat(first, second) {
    addEpsilonTransition(first.end, second.start);
    first.end.isEnd = false;

    return { start: first.start, end: second.end };
}

function union(first, second) {
    const start = createState(false);
    addEpsilonTransition(start, first.start);
    addEpsilonTransition(start, second.start);

    const end = createState(true);
    addEpsilonTransition(first.end, end);
    first.end.isEnd = false;
    addEpsilonTransition(second.end, end);
    second.end.isEnd = false;

    return { start, end };
}

function closure(nfa) {
    const start = createState(false);
    const end = createState(true);

    addEpsilonTransition(start, end);
    addEpsilonTransition(start, nfa.start);

    addEpsilonTransition(nfa.end, end);
    addEpsilonTransition(nfa.end, nfa.start);
    nfa.end.isEnd = false;

    return { start, end };
}

Теперь время собрать всё вместе. Сканируем постфиксное выражение по одному символу и храним контекст в стеке. Стек содержит NFA.

  • Когда сканируем символ — создаём символьный NFA и кладём на стек.
  • Когда сканируем оператор — снимаем со стека, применяем эту операцию к NFA и возвращаем полученный NFA на стек.
jsfunction toNFA(postfixExp) {
	if(postfixExp === '') {
	    return fromEpsilon();
	}

	const stack = [];

	for (const token of postfixExp) {
		if(token === '*') {
   		    stack.push(closure(stack.pop()));
   		} else if (token === '|') {
   		    const right = stack.pop();
   		    const left = stack.pop();
   		    stack.push(union(left, right));
   		} else if (token === '.') {
   		    const right = stack.pop();
   		    const left = stack.pop();
   		    stack.push(concat(left, right));
   		} else {
   		    stack.push(fromSymbol(token));
   		}
   	}

	return stack.pop();
}

Пример

Промоделируем алгоритм на (a|b)*c:

  • Вставить явный оператор конкатенации (.): (a|b)*c ← (a|b)*.c
  • Превратить в постфиксную нотацию: (a|b)*.c ← ab|*c.
  • Построить NFA:
Таблицашаг   скан        операция                      стек
0     a b|*c.     fromSymbol(a); push;          { N(a) }
1     a b|*c.     fromSymbol(b); push;          { N(a), N(b) }
2     ab |*c.     pop; pop; union(N(a), N(b));  { N(a|b) }
                  push;
4     ab| *c.     pop; closure(N(a|b)); push;   { N((a|b)*) }
5     ab|* c.     fromSymbol(c); push;          { N((a|b)*), N(c) }
6     ab|*c .     pop; pop;                     { N((a|b)*c) }
                  concat(N((a|b)*), N(c)); push;

Алгоритмы поиска в NFA

Рекурсивный бэктрекинг

Простейший способ проверить, распознаётся ли строка автоматом, — вычислить все возможные пути через NFA, пока не дойдём до принимающего состояния или не исчерпаем все возможности. Это сводится к рекурсивному поиску в глубину с откатом.

Автомат рисунка 5.1 распознаёт строку «aba» или «abb». Если хотим обработать «abb», рекурсивная симуляция обрабатывает вход по одному состоянию за раз; после чтения «ab» попадаем в q3. Следующий символ «b», но из q3 нет перехода по «b»; поэтому возвращаемся в q0 и идём другим путём, ведущим в принимающее состояние.

Для автомата рисунка 5.1 пришлось пройти оба возможных пути. В более сложном сценарии последствия для производительности могут быть значительными. В NFA с n состояниями из каждого состояния может быть максимум n возможных переходов; значит, возможных путей может быть максимум 2n, и в худшем случае алгоритм должен пройти все эти пути, пока не найдёт сопоставление (или не поймёт, что его нет). Очевидно, O(2n) не масштабируется: для строки из 10 символов, вероятно, придётся выполнить 1024 операции. Точно нужно сделать лучше.

Нахождение в нескольких состояниях одновременно

Можно представить NFA находящимся в нескольких состояниях одновременно, как описано в статье Томпсона. Этот подход сложнее, но даёт заметно лучшую производительность.

Когда читаем символ входной строки, вместо перехода из состояния в состояние переходим ко всем возможным состояниям, достижимым из текущего множества состояний. Иными словами, текущее состояние NFA фактически становится множеством состояний. После каждого чтения символа для каждого состояния в текущем множестве находим состояния, в которые можно перейти по этому символу, и помечаем их как следующие состояния. С этим подходом наша симуляция для «abb» выглядит так:

Таблицашаг   текущее состояние   скан   следующее состояние
1     { q1, q5 }          a bb   { q2, q6 }
2     { q2, q6 }          a b b  { q3, q7 }
3     { q3, q7 }          ab b   { q9 }

Проверяем, является ли какое-либо состояние во множестве, куда пришли, принимающим; если да, строка распознана NFA. В нашем случае итоговое множество содержит только q9, которое принимающее.

Работа с ε-переходами

Как упоминалось, конструкция Томпсона даёт два типа состояний: с ε-переходами и с переходами по символу. Поэтому всякий раз, оказавшись в состоянии с ε-переходом(ами), просто следуем к следующему(им) состоянию(ям), пока не дойдём до состояния с символьным переходом, и вставляем его в множество следующих состояний. В q7 читаем «b» и идём в q8 — состояние с ε-переходом. Следуем ε-переходу и попадаем в q9, у которого ε-перехода нет, поэтому добавляем его в список следующих состояний. Это рекурсивная процедура:

jsfunction addNextState(state, nextStates, visited) {
    if (state.epsilonTransitions.length) {
        for (const st of state.epsilonTransitions) {
            if (!visited.find(vs => vs === st)) {
                visited.push(st);
                addNextStates(st, nextStates, visited);
            }
        }
    } else {
        nextStates.push(state);
    }
}

Состояния с ε-переходами тоже нужно помечать посещёнными, чтобы избежать бесконечного цикла. Дно рекурсии — когда достигаем состояния без ε-переходов. Код процедуры поиска:

jsfunction search(nfa, word) {
    let currentStates = [];
    addNextState(nfa.start, currentStates, []);

    for (const symbol of word) {
        const nextStates = [];

        for (const state of currentStates) {
            const nextState = state.transition[symbol];
            if (nextState) {
                addNextState(nextState, nextStates, []);
            }
        }
        currentStates = nextStates;
    }

    return currentStates.find(s => s.isEnd) ? true : false;
}

Изначальное множество текущих состояний — либо само начальное состояние, либо множество состояний, достижимых ε-переходами из начального. Со строкой длины n этот алгоритм на каждой итерации держит два списка состояний длины примерно n. Это даёт сложность O(n2), заметно лучше рекурсивного отката. Можно оптимизировать, превратив NFA в NFA без ε и даже в DFA. DFA гарантируют сложность распознавания O(n), но могут привести к 2n состояниям из-за проблемы взрыва состояний.

Собираем всё вместе

jsfunction createMatcher(exp) {
    const postfixExp = toPostfix(insertExplicitConcatOperator(exp));
    const nfa = toNFA(postfixExp);

    return word => search(nfa, word);
}

const match = createMatcher('a*b');
match(''); // false
match('b'); // true
match('ab'); // true

Резюме

Мы начали с изучения конечных автоматов и того, как они работают. Классифицировали их на детерминированные и недетерминированные и ввели понятие ε-NFA — особого типа недетерминированного автомата. Увидели, что NFA и DFA имеют одинаковую выразительную мощь и как использовать их для распознавания строк.

Определили строительные блоки регулярных выражений и узнали, как применением операторов (конкатенации, объединения и замыкания) строить из простых более сложные. Затем научились компилировать выражение в эквивалентный NFA и реализовали алгоритм, обрабатывающий строку через NFA, чтобы определить, сопоставляется ли она.

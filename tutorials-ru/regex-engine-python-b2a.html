R1. Разбор регулярных выражений (новичок)

Введение

Что вы узнаете:

  • Regex — не магия.
  • Деревья и структурированные данные.
  • Рекурсия и техники разбора.

Какие возможности regex вы реализуете:

  • ab — конкатенация: сначала сопоставь подвыражение a, затем b.
  • a|b — альтернатива: сопоставь либо a, либо b.
  • a*, a+, a{n}, a{x,y} — повторение: ноль или более раз, минимум один раз, n раз и от x до y раз.
  • (a) — подвыражение: процитируй подвыражение. Выражения могут быть вложенными.
  • x, . — сопоставление одного символа: литеральный символ или произвольный символ.

Анализ задачи

Regex — это кусок строки. Эта строка представляет структуру. Часто мы работаем не со строкой, а со структурой, которую она обозначает. Процесс превращения строки в структуру называется «разбор» (parsing).

Структура regex рекурсивна. Рекурсия означает иерархию и подструктуры, похожие на саму структуру. Возможно, не очевидно, как regex рекурсивен; начнём с того, что вам знакомо.

Формула (1+2)+3 рекурсивна; у второго + два подвыражения: 1+2 и 3. 1+2+3 эквивалентно (1+2)+3, просто скобки неявные. 1+2×3 неявно 1+(2×3); × имеет больший приоритет, чем +.

Вернёмся к regex. abc неявно ((a)b)c; просто считайте невидимый оператор конкатенации как ×: ((a)×b)×c. Точно так же a|bc равно a|(bc), как a+(b×c).

Конкатенация и альтернатива — «инфиксные» операторы; их подвыражения — слева и справа от оператора. Оператор повторения — «постфиксный», как факториал (n!).

Три оператора, три приоритета. Постфиксный оператор — самый высокий, затем конкатенация, затем альтернатива.

Чтобы разобрать regex рекурсией, оператор с самым высоким приоритетом должен разбираться на самом нижнем (самом глубоком) уровне иерархии. Самый нижний уровень regex — либо одиночный символ, либо процитированное подвыражение. На уровень выше добавляется оператор повторения (может, ни одного). Затем конкатенация, затем альтернатива.

Начало кода

Во-первых, определяем форму наших разобранных структур. Это деревья, очевидно.

pythonassert re_parse('') is None
assert re_parse('.') == 'dot'
assert re_parse('a') == 'a'
assert re_parse('ab') == ('cat', 'a', 'b')
assert re_parse('a|b') == ('split', 'a', 'b')
assert re_parse('a+') == ('repeat', 'a', 1, float('inf'))
assert re_parse('a{3,6}') == ('repeat', 'a', 3, 6)
assert re_parse('a|bc') == ('split', 'a', ('cat', 'b', 'c'))

Самый верхний уровень разбора — оператор альтернативы.

Аргументы:

  • r: строка regex.
  • idx: текущая позиция разбора.
python# a|b|c...
def parse_split(r, idx):
    idx, prev = parse_concat(r, idx)
    while idx < len(r):
        if r[idx] == ')':
            # вернуться к внешнему parse_node
            break
        assert r[idx] == '|', 'BUG'
        idx, node = parse_concat(r, idx + 1)
        prev = ('split', prev, node)
    return idx, prev

С первого взгляда parse_split получает подвыражения от parse_concat и строит узел «split».

parse_concat — на уровень ниже. Очень похож на parse_split.

python# abc...
def parse_concat(r, idx):
    prev = None
    while idx < len(r):
        if r[idx] in '|)':
            # вернуться к parse_split или внешнему parse_node
            break
        idx, node = parse_node(r, idx)
        if prev is None:
            prev = node
        else:
            prev = ('cat', prev, node)
    # когда prev всё ещё None, это обозначает пустую строку
    return idx, prev

И parse_split, и parse_concat останавливаются на «)». «)» обычно означает, что разбор идёт внутри внешнего процитированного подвыражения, и при достижении конца подвыражения нужно вернуться к внешнему разборщику. Точно так же parse_concat останавливается на «|», чтобы вернуться к внешнему parse_split.

Спускаемся к parse_node. Он разбирает либо одиночный символ, либо процитированное подвыражение, а затем может добавить оператор повторения.

python# разбор одного элемента
def parse_node(r, idx):
    ch = r[idx]
    idx += 1
    assert ch not in '|)'
    if ch == '(':
        idx, node = parse_split(r, idx)
        if idx < len(r) and r[idx] == ')':
            idx += 1
        else:
            raise Exception('unbalanced parenthesis')
    elif ch == '.':
        node = 'dot'
    elif ch in '*+{':
        raise Exception('nothing to repeat')
    else:
        node = ch

    idx, node = parse_postfix(r, idx, node)
    return idx, node

Обратите внимание: вызов parse_split рекурсирует на самый верхний уровень иерархии.

parse_postfix намного длиннее, но это просто утомительный последовательный код.

python# a*, a+, a{x}, a{x,}, a{x,y}
def parse_postfix(r, idx, node):
    if idx == len(r) or r[idx] not in '*+{':
        return idx, node

    ch = r[idx]
    idx += 1
    if ch == '*':
        rmin, rmax = 0, float('inf')
    elif ch == '+':
        rmin, rmax = 1, float('inf')
    else:
        # первое число внутри {}
        idx, i = parse_int(r, idx)
        if i is None:
            raise Exception('expect int')
        rmin = rmax = i
        # второе число необязательно
        if idx < len(r) and r[idx] == ',':
            idx, j = parse_int(r, idx + 1)
            rmax = j if (j is not None) else float('inf')
        # закрыть скобку }
        if idx < len(r) and r[idx] == '}':
            idx += 1
        else:
            raise Exception('unbalanced brace')

    # проверки корректности
    if rmax < rmin:
        raise Exception('min repeat greater than max repeat')
    if rmin > RE_REPEAT_LIMIT:
        raise Exception('the repetition number is too large')

    node = ('repeat', node, rmin, rmax)
    return idx, node
pythondef parse_int(r, idx):
    save = idx
    while idx < len(r) and r[idx].isdigit():
        idx += 1
    return idx, int(r[save:idx]) if save != idx else None

Реальный интерфейс:

pythondef re_parse(r):
    idx, node = parse_split(r, 0)
    if idx != len(r):
        # разбор остановился на неуместной ")"
        raise Exception('unexpected ")"')
    return node

Заключение

Мы научились разбирать regex рекурсией. Эти знания полезны и для разбора других вещей. Хотя разбор занимает значительные страницы в книгах по компиляторам, многие языки реального мира можно разобрать просто рекурсией, и часто простейший способ разобрать что-то — рукописный рекурсивный код. R2. Regex-движок с backtracking (новичок)

Введение

Что вы узнаете:

  • Разложение задачи на подзадачи.
  • Поиск и backtracking.

В предыдущей главе мы научились разбирать regex в древесные структуры. Из древесной структуры можно начать строить движок regex. Метод, используемый в этой главе, называется «backtracking». Backtracking — не самый эффективный способ реализации regex; другие методы представлены в следующих главах.

Анализ задачи

Часто первый шаг решения задачи — разложить её на меньшие куски или подзадачи. Древесная природа структуры делает это даже очевиднее.

  • Конкатенация, ab: выполни подвыражение a, затем b с позиции результата a.
  • Альтернатива, a|b: объедини результаты a и b.

Для конкатенаций первое может порождать любое число кандидатов на сопоставление. А второе зависит от результатов первого: если второе не может найти сопоставление с конкретной позиции результатов первого, поиск возобновляется с другой позиции. Это и есть «backtracking». Для повторений всё как с конкатенацией.

Кратко:

  • Подвыражение с данной позиции строки порождает список кандидатов.
  • Оператор конкатенации: для каждого результата первого подвыражения выполни и передай результаты второму.
  • Оператор повторения ведёт себя как конкатенация.
  • Объедини результаты подвыражений альтернативы.

Начало кода

Код короткий:

python# метод backtracking — почти полный перебор.
# можно добавить кэш для удаления повторяющихся idx.
def match_backtrack(node, text, idx):
    if node is None:
        yield idx   # пустая строка
    elif node == 'dot':
        if idx < len(text):
            yield idx + 1
    elif isinstance(node, str):
        assert len(node) == 1   # односимвольный
        if idx < len(text) and text[idx] == node:
            yield idx + 1
    elif node[0] == 'cat':
        # yield from эквивалентно:
        # for idx1 in match_backtrack_concat(node, text, idx):
        #     yield idx1
        yield from match_backtrack_concat(node, text, idx)
    elif node[0] == 'split':
        yield from match_backtrack(node[1], text, idx)
        yield from match_backtrack(node[2], text, idx)
    elif node[0] == 'repeat':
        yield from match_backtrack_repeat(node, text, idx)
    else:
        assert not 'reachable'

Для тех, кто не знаком с Python: оператор yield приостанавливает исполнение и возвращает значение вызывающему, а вызывающий обычно итерирует по результатам. yield from — сокращение цикла и передачи всего.

Каждый раз, когда сопоставление найдено, результат передаётся через yield вызывающему. Вызывающий может сделать с ним что-то и попросить следующий результат (продолжив итерацию).

Передача управления вперёд и назад делает написание кода backtracking на Python безболезненным. Но если вы впервые пытаетесь понять backtracking, рекомендуется сделать это без оператора yield и управлять состояниями backtracking явно — упражнение для тех, кто не использует Python.

Код конкатенации:

pythondef match_backtrack_concat(node, text, idx):
    met = set()
    for idx1 in match_backtrack(node[1], text, idx):
        if idx1 in met:
            continue    # дубликат
        met.add(idx1)
        yield from match_backtrack(node[2], text, idx1)

Обратите внимание: я добавил hash set, чтобы отбрасывать повторяющиеся результаты первого подвыражения.

Код повторения длиннее:

pythondef match_backtrack_repeat(node, text, idx):
    _, node, rmin, rmax = node
    rmax = min(rmax, RE_REPEAT_LIMIT)
    # вывод буферизуется и затем разворачивается
    output = []
    if rmin == 0:
        # ничего не должно сопоставляться
        output.append(idx)
    # позиции предыдущего шага
    start = {idx}
    # пробуем все возможные числа повторений
    for i in range(1, rmax + 1):
        found = set()
        for idx1 in start:
            for idx2 in match_backtrack(node, text, idx1):
                found.add(idx2)
                if i >= rmin:
                    output.append(idx2)
        # TODO: выйти, если единственное сопоставление — нулевой длины
        if not found:
            break
        start = found
    # повторение жадно; первым выдай сопоставление с наибольшим числом повторений.
    yield from reversed(output)

Повторение обрабатывается повторным исполнением подвыражения, пока оно может сопоставляться. Каждый шаг начинается с результатов предыдущего, и позиции стартов дедуплицируются.

Ещё заметьте: повторение regex «жадное»; нужно найти сопоставление с максимальным числом повторений и выдать его первым.

Функция проверки того, сопоставляется ли строка с regex полностью:

pythondef re_full_match_bt(node, text):
    for idx in match_backtrack(node, text, 0):
        # idx — размер сопоставленного префикса
        if idx == len(text):
            # примечание: жадность regex кажется
            # нерелевантной, если мы принимаем только полное сопоставление.
            return True
    return False

Заключение

Мы научились сопоставлять regex с backtracking. Отсюда можно добавлять больше возможностей regex.

Однако подход backtracking — сравнительно грубая сила и может выполнять повторяющиеся поиски. Можно добавить кэш для их уменьшения; но не беспокойтесь, в следующей главе вы исследуете новый метод: недетерминированные конечные автоматы (NFA).

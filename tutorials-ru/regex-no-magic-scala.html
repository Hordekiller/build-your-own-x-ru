Регекспы без магии на Scala

⚙ Язык: Scala 📁 Regex-движок 🌐 Русская страница 🔗 Оригинальный источник
Оригинальный источник: «No Magic: Regular Expressions»
↗ Перейти к оригинальному уроку فارسی — Персидская версия EN — English version

Введение

До недавнего времени регулярные выражения казались мне магией. Я никогда не понимал, как можно определить, сопоставляется ли строка с данным выражением. Теперь я знаю! Вот способ реализовать начальный движок регулярных выражений меньше чем в 200 строк кода.

Спецификация

Полная реализация регулярных выражений довольно утомительна и, что хуже, мало чему вас учит. Версия, которую мы реализуем, ровно настолько велика, чтобы учиться без скуки. Наш язык регулярных выражений поддерживает:

Таблица.    сопоставь с любым символом
|    сопоставь с «abc» или «cde»
+    сопоставь с одним и более вхождений предыдущего шаблона
*    сопоставь с нулём и более вхождений предыдущего шаблона
( )  для группировки

Хотя это маленький набор возможностей, мы всё равно можем строить забавные regex; например, m(t|n| )|b для сопоставления субтитров «Звёздных войн» без сопоставления «Стартрека», или (..)* — множество всех строк чётной длины.

План атаки

Оцениваем регулярные выражения в 3 фазы:

  • Разобрать выражение в дерево синтаксиса
  • Превратить дерево синтаксиса в машину состояний
  • Выполнить машину состояний на нашей строке

Для оценки выражений используем машину состояний под названием NFA (подробнее о ней позже). На высоком уровне NFA представляет наш regex. Потребляя входы, мы переходим из состояния в состояние в NFA. Если доходим до места, где не можем следовать допустимому переходу, выражение не сопоставляется со строкой.

Этот подход впервые продемонстрировал Кен Томпсон, один из главных авторов Unix. В своей статье 1968 года (CACM) он описывает реализацию текстового редактора и включает в неё оценщик регулярных выражений. Единственная разница: его статья написана на машинном коде 7094. Раньше всё было серьёзнее.

Этот алгоритм — упрощение того, как движки regex без backtracking, такие как RE2, оценивают выражения: в доказуемо линейное время. Заметный контраст с движками regex в Python и Java, использующими backtracking: на специальных входах на маленьких строках они исполняются практически вечно. Наш движок работает за O(длина входа × длина выражения).

Мой подход почти следует стратегии, намеченной Рассом Коксом в его превосходном посте.

Представление регулярного выражения

Сделаем шаг назад и подумаем, как представить выражение. Прежде чем надеяться оценить выражение, нужно превратить его в структуру данных, с которой может работать компьютер. В то время как строки имеют линейную структуру, регулярные выражения имеют естественную иерархию.

Рассмотрим строку abc|(c|(de)). Если хранить её как строку, при оценке придётся прыгать вперёд-назад между разными наборами скобок и откатываться. Одно из решений — превратить её в дерево, которое компьютер легко может обойти. Например, b+a становится деревом.

Для представления дерева хотим построить иерархию классов. Например, наш класс Or должен иметь два поддерева, представляющие две его стороны. По спецификации нужно распознавать 4 разных компонента regex: +, *, | и литеральные символы вроде ., a и b. Кроме того, нужно уметь показывать, что одно выражение следует за другим. Вот наши классы:

scalaabstract class RegexExpr

// ., a, b
case class Literal(c: Char) extends RegexExpr

// a|b
case class Or(expr1: RegexExpr, expr2: RegexExpr) extends RegexExpr

// ab -> Concat(a,b); abc -> Concat(a, Concat(b, c))
case class Concat(first: RegexExpr, second: RegexExpr) extends RegexExpr

// a*
case class Repeat(expr: RegexExpr) extends RegexExpr

// a+
case class Plus(expr: RegexExpr) extends RegexExpr

Разбор регулярного выражения

Чтобы перейти от строки к древесному представлению, используем процесс под названием «разбор» (parsing). Я не собираюсь подробно рассказывать о построении разборщиков. Вместо этого дам столько, сколько нужно, чтобы направить вас, если захотите написать свой. Здесь я расскажу, как разобрал выражения с помощью библиотеки parser combinator из Scala.

Библиотека разбора Scala позволяет написать разборщик, просто записав набор правил, описывающих наш язык. К сожалению, она использует много символов, но надеюсь, вы сможете увидеть суть за этим шумом.

При реализации разборщика нужно учитывать порядок операций. Так же как «приоритет операторов» применяется к вычислениям, для выражений применяется другой набор правил. Можно формализовать это идеей «сцепления» оператора с соседними символами. Разные операторы «сцепляются» с разной силой — по аналогии, в выражениях вроде 5+6*4, * сцепляется сильнее +. В выражениях * сцепляется сильнее |. Если представить это деревом, слабейшие операторы оказываются сверху.

Вывод: сначала нужно разбирать слабейшие операторы, затем более сильные. При разборе можно представить: вытащи оператор, добавь в дерево, затем рекурсивно обработай оставшиеся две части строки.

В регулярных выражениях порядок силы сцепления такой:

Таблицалитеральный символ и скобки      (сильнейший)
+ и *
конкатенация — «a» следует за «b»
|                                  (слабейший)

Поскольку есть 4 уровня силы сцепления, нужны 4 разных типа выражений. Назовём их (несколько произвольно): lit, lowExpr (+ и *), midExpr (конкатенация) и highExpr (|). Перейдём к коду. Сначала разборщик для самого начального уровня — одиночного символа:

scalaobject RegexParser extends RegexParsers {
    def charLit: Parser[RegexExpr] = ("""\w""".r | ".") ^^ {
        char => Literal(char.head)
    }

Остановимся на минуту, чтобы объяснить этот синтаксис. Он определяет разборщик, создающий RegexExpr. Правая часть говорит: «найди что-то, сопоставимое с \w (любой слово-символ) или точкой. Если нашёл, преврати в Literal».

Скобки нужно определять на самом нижнем уровне разборщика, потому что у них сильнейшее сцепление. Но нужно уметь класть внутрь скобок что угодно. Сделаем это так:

scala    def parenExpr: Parser[RegexExpr] = "(" ~> highExpr <~ ")"
    def lit: Parser[RegexExpr] = charLit | parenExpr

Здесь определяем * и +:

scala    def repeat: Parser[RegexExpr] = lit <~ "*"
        ^^ { case l => Repeat(l) }
    def plus: Parser[RegexExpr] = lit <~ "+"
        ^^ { case p => Plus(p) }
    def lowExpr: Parser[RegexExpr] = repeat | plus | lit

Затем конкатенацию, следующий уровень:

scala    def concat: Parser[RegexExpr] = rep(lowExpr)
        ^^ { case list => listToConcat(list)}
    def midExpr: Parser[RegexExpr] = concat | lowExpr

Наконец, определяем or:

scala    def or: Parser[RegexExpr] = midExpr ~ "|" ~ midExpr
        ^^ { case l ~ "|" ~ r => Or(l, r)}

И в самом конце определяем highExpr. highExpr — это or, слабейший оператор сцепления, или, если or нет, midExpr:

scala    def highExpr: Parser[RegexExpr] = or | midExpr

И наконец, немного вспомогательного кода для завершения:

scala    def listToConcat(list: List[RegexExpr]): RegexExpr = list match {
        case head :: Nil => head
        case head :: rest => Concat(head, listToConcat(rest))
    }

    def apply(input: String): Option[RegexExpr] = {
        parseAll(highExpr, input) match {
            case Success(result, _) => Some(result)
            case failure : NoSuccess => None
        }
    }
}

Готово! С этим кодом Scala вы можете создавать деревья разбора для любого выражения, соответствующего спецификации. Полученные структуры данных — деревья.

Теперь, когда мы умеем превращать выражения в деревья синтаксиса, мы на полпути к их оценке. Следующие шаги описаны в разделах 2 и 3 статьи: превращение дерева синтаксиса в NFA и затем оценка этого NFA на данных строках — тем же подходом алгоритмов RE2 и конструкции Томпсона, на которые есть ссылки.

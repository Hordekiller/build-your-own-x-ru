Реализация RESTful веб-API на Python с Flask

Введение

Для начала:

Bashsudo pip install flask

Предполагается, что вы знаете основы REST. Flask — это микрофреймворк Python на базе Werkzeug — прикладной библиотеки WSGI.

Flask — хороший выбор для REST-подобного API, потому что:

  • написан на Python (что может быть преимуществом);
  • прост в использовании;
  • гибок;
  • имеет множество хороших вариантов развёртывания (deployment);
  • имеет RESTful-диспетчеризацию запросов (Request Dispatching).

Автор обычно отправляет тестовые запросы через curl, и в конце статьи есть маленький справочник по curl. REST Console — тоже хороший инструмент для Google Chrome.

Примеры кода этой статьи — на GitHub.

Ресурсы

Начнём с полного приложения, отвечающего на запросы к корню, /articles и /articles/:id:

pythonfrom flask import Flask, url_for
app = Flask(__name__)

@app.route('/')
def api_root():
    return 'Welcome'

@app.route('/articles')
def api_articles():
    return 'List of ' + url_for('api_articles')

@app.route('/articles/<articleid>')
def api_article(articleid):
    return 'You are reading ' + articleid

if __name__ == '__main__':
    app.run()

С curl вы можете отправить такие запросы:

Bashcurl http://127.0.0.1:5000/

Ответы, соответственно, такие:

ConsoleGET /
Welcome

GET /articles
List of /articles

GET /articles/123
You are reading 123

Пути могут использовать в своих определениях различные конвертеры:

python@app.route('/articles/<articleid>')

можно заменить на:

python@app.route('/articles/<int:articleid>')
@app.route('/articles/<float:articleid>')
@app.route('/articles/<path:articleid>')

По умолчанию используется string, принимающий любой текст без слэшей.

Запросы

GET-параметры

Создадим приложение, отвечающее на запросы к /hello и управляющее необязательным GET-параметром:

pythonfrom flask import request

@app.route('/hello')
def api_hello():
    if 'name' in request.args:
        return 'Hello ' + request.args['name']
    else:
        return 'Hello John Doe'

Сервер отвечает так:

ConsoleGET /hello
Hello John Doe

GET /hello?name=Luis
Hello Luis

Методы запроса (HTTP-глаголы)

Изменим приложение так, чтобы оно управляло разными HTTP-глаголами:

python@app.route('/echo', methods = ['GET', 'POST', 'PATCH', 'PUT', 'DELETE'])
def api_echo():
    if request.method == 'GET':
        return "ECHO: GET\n"

    elif request.method == 'POST':
        return "ECHO: POST\n"

    elif request.method == 'PATCH':
        return "ECHO: PACTH\n"

    elif request.method == 'PUT':
        return "ECHO: PUT\n"

    elif request.method == 'DELETE':
        return "ECHO: DELETE"

В curl опция -X задаёт тип запроса:

Bashcurl -X PATCH http://127.0.0.1:5000/echo

Данные и заголовки запроса

Обычно POST и PATCH сопровождаются данными; иногда в одном из нескольких форматов: обычный текст, JSON, XML, ваш собственный формат данных, бинарный файл и т.д. Доступ к HTTP-заголовкам — через словарь request.headers, а к данным запроса — через строку request.data. Если mimetype равен application/json, то request.json содержит разобранный JSON:

pythonfrom flask import json

@app.route('/messages', methods = ['POST'])
def api_message():

    if request.headers['Content-Type'] == 'text/plain':
        return "Text Message: " + request.data

    elif request.headers['Content-Type'] == 'application/json':
        return "JSON Message: " + json.dumps(request.json)

    elif request.headers['Content-Type'] == 'application/octet-stream':
        f = open('./binary', 'wb')
        f.write(request.data)
        f.close()
        return "Binary message written!"

    else:
        return "415 Unsupported Media Type ;)"

Задание типа содержимого в curl:

Bashcurl -H "Content-type: application/json" \
-X POST http://127.0.0.1:5000/messages -d '{"message":"Hello Data"}'

Отправка файла в curl:

Bashcurl -H "Content-type: application/octet-stream" \
-X POST http://127.0.0.1:5000/messages --data-binary @message.bin

Ответы для разных типов содержимого:

ConsolePOST /messages {"message": "Hello Data"}
Content-type: application/json
JSON Message: {"message": "Hello Data"}

POST /message <message.bin>
Content-type: application/octet-stream
Binary message written!

Кстати, Flask умеет обрабатывать загружаемые по HTML-формам файлы через request.files, а curl может имитировать это поведение флагом -F.

Ответы

Ответами управляет класс Response из Flask:

pythonfrom flask import Response

@app.route('/hello', methods = ['GET'])
def api_hello():
    data = {
        'hello'  : 'world',
        'number' : 3
    }
    js = json.dumps(data)

    resp = Response(js, status=200, mimetype='application/json')
    resp.headers['Link'] = 'http://luisrei.com'

    return resp

Чтобы увидеть заголовки HTTP-ответа, укажите в curl опцию -i:

Bashcurl -i http://127.0.0.1:5000/hello
ConsoleGET /hello
HTTP/1.0 200 OK
Content-Type: application/json
Content-Length: 31
Link: http://luisrei.com
Server: Werkzeug/0.8.2 Python/2.7.1
Date: Wed, 25 Apr 2012 16:40:27 GMT
{"hello": "world", "number": 3}

Mimetype — это просто content-type без дополнительной информации (такой как charset, encoding, language и т.д.). Если возможно, возвращайте полную информацию о типе содержимого.

Предыдущий пример можно упростить удобным методом Flask для генерации JSON-ответов:

python    from flask import jsonify

и заменой:

python  resp = Response(js, status=200, mimetype='application/json')

на:

pythonresp = jsonify(data)
resp.status_code = 200

что даёт ровно тот же ответ, что раньше. Задание mime type особенно полезно для собственных mime type вроде application/vnd.example.v2+json.

Коды состояния и ошибки

Обратите внимание, что 200 — код состояния по умолчанию для GET-запросов, и в обоих примерах его задание было лишь для наглядности. Есть случаи, когда нужно переопределить значения по умолчанию; например, обработка ошибок:

python@app.errorhandler(404)
def not_found(error=None):
    message = {
            'status': 404,
            'message': 'Not Found: ' + request.url,
    }
    resp = jsonify(message)
    resp.status_code = 404

    return resp

@app.route('/users/<userid>', methods = ['GET'])
def api_users(userid):
    users = {'1':'john', '2':'steve', '3':'bill'}
    
    if userid in users:
        return jsonify({userid:users[userid]})
    else:
        return not_found()

Это даёт:

ConsoleGET /users/2
HTTP/1.0 200 OK
{
    "2": "steve"
}

GET /users/4
HTTP/1.0 404 NOT FOUND
{
"status": 404, 
"message": "Not Found: http://127.0.0.1:5000/users/4"
}

Сообщения об ошибках Flask по умолчанию можно переопределить либо декоратором @error_handler, либо через app.error_handler_spec[None][404] = not_found. Даже если вашему API не нужны собственные сообщения об ошибках, эта возможность важна, если он поддерживает разные mime type (JSON, XML и т.д.), потому что Flask по умолчанию выдаёт ошибки в HTML.

Аутентификация

Очень полезный snippet Армина Ронахера показывает, как управлять HTTP Basic Authentication, и легко адаптируется под другие схемы. Его слегка изменённая версия:

pythonfrom functools import wraps

def check_auth(username, password):
    return username == 'admin' and password == 'secret'

def authenticate():
    message = {'message': "Authenticate."}
    resp = jsonify(message)

    resp.status_code = 401
    resp.headers['WWW-Authenticate'] = 'Basic realm="Example"'

    return resp

def requires_auth(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        auth = request.authorization
        if not auth: 
            return authenticate()

        elif not check_auth(auth.username, auth.password):
            return authenticate()
        return f(*args, **kwargs)

    return decorated

и его использование — просто замена функции check_auth и применение декоратора requires_auth:

python@app.route('/secrets')
@requires_auth
def api_hello():
    return "Shhh this is top secret spy stuff!"

Итак, запрос без аутентификации:

ConsoleGET /secrets
HTTP/1.0 401 UNAUTHORIZED
WWW-Authenticate: Basic realm="Example"
{
  "message": "Authenticate."
}

в то время как аутентифицированный запрос — отправленный в curl с опцией -u для Basic authentication и -v для просмотра заголовков — даёт ожидаемый результат:

Bashcurl -v -u "admin:secret" http://127.0.0.1:5000/secrets
ConsoleGET /secrets Authorization: Basic YWRtaW46c2VjcmV0
Shhh this is top secret spy stuff!

Flask использует MultiDict для хранения заголовков. Чтобы предложить клиентам несколько схем аутентификации, достаточно добавить в заголовок больше строк WWW-Authenticate:

pythonresp.headers['WWW-Authenticate'] = 'Basic realm="Example"'
resp.headers.add('WWW-Authenticate', 'Bearer realm="Example"')

или использовать одну строку с несколькими схемами (стандарт разрешает оба варианта).

Отладка и простой журнал

Включить красивые (HTML) сообщения отладки во время разработки просто — всего один аргумент:

pythonapp.run(debug=True)

Flask использует тот же logging, что и Python, — с небольшой настройкой:

pythonimport logging
file_handler = logging.FileHandler('app.log')
app.logger.addHandler(file_handler)
app.logger.setLevel(logging.INFO)

@app.route('/hello', methods = ['GET'])
def api_hello():
    app.logger.info('informing')
    app.logger.warning('warning')
    app.logger.error('screaming bloody murder!')
    
    return "check your logs\n"

Маленький справочник: опции curl

ОпцияИспользование
-Xзадание HTTP-метода запроса, например POST
-Hзадание заголовков запроса, например "Content-type: application/json"
-dзадание данных запроса, например '{"message":"Hello Data"}'
--data-binaryзадание бинарных данных запроса, например @file.bin
-iотображение заголовков ответа
-uзадание имени пользователя и пароля, например "admin:secret"
-vвключение verbose-режима, выводящего такую информацию, как заголовки запроса и ответа и ошибки

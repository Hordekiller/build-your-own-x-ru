Поиск: движок на CSS?

Поиски, о которых мы забыли

Поисковые движки обычно представляются сложными системами: обход веба, индексация, лингвистический анализ, ранжирование… Но если чуть отмотать назад, «поиск» — это механизм, который принимает строку и находит подходящее. Ваш браузер делает то же самое ещё до того, как вы напечатаете слово в поисковой строке Google: когда вы вводите текст в поле формы, подсказки автодополнения — это не поиск по HTML самой страницы; это маленькие «поиски», которые каждый браузер выполняет по своей собственной истории. Эта статья продвигает ту же идею на шаг дальше: поисковый движок, который работает только на CSS, вообще без JavaScript.

Центральная идея: CSS-поисковик использует «движок самого браузера» как поисковый движок — то, что вы печатаете, становится селектором, а селектор фильтрует страницы/контент.

Селекторы — это и есть движок

Когда вы вводите что-то в поисковик, движок ищет по «инвертированному индексу» и возвращает результат по релевантности. В CSS эквивалент этого — селектор: движок рендеринга браузера обходит DOM-дерево, чтобы понять, какие элементы подпадают под селектор, — это настоящий поиск по структуре документа. Ключевая деталь статьи — селектор, который смотрит на значение, которое вводится прямо сейчас:

css/* Если текущее значение input в точности «tim», это правило активируется */
input[value="tim" i] ~ p.tim {
  /* показываем связанный элемент */
  display: block;
}

Флаг i после значения делает сравнение нечувствительным к регистру (case-insensitive). Так поиск «TIM», «Tim» или «tim» даёт одинаковый результат. Поскольку значение атрибута можно «склеивать» в CSS с помощью ~= и псевдоклассов (например, :valid), поведение поисковика расширяется: например, показывать результаты только когда поиск «валиден».

Почему i? Спецификация Selectors Level 4 позволяет CSS делать сопоставление атрибутов нечувствительным к регистру; именно этот «флаг» создаёт естественный пользовательский опыт поиска.

Архитектура: ввод, контент и правила отображения

Структура демо сводится к трём простым частям:

  • Один глобальный <input>: поле поиска; всё, что печатается, живьём становится значением атрибута, то есть value (некоторые браузеры обновляют атрибут, и CSS может реагировать на него в тот же момент).
  • Набор «результатов»: каждый результат — абзац/карточка с ключевыми словами, хранящимися в собственном атрибуте (например, data-kw).
  • Правила отображения: для каждого результата пишем правило, которое показывает его только тогда, когда набранное слово есть в атрибуте результата — то есть «запрос» в CSS-дереве.

Это значит — поисковый движок, который ведёт себя «умно», но в котором нет ни строчки JavaScript: настоящий искатель — селекторный движок самого браузера, работающий на нативной скорости.

Ограничения и что вы узнаете

  • CSS — язык декларативный: мы описываем «как фильтровать», а не шаги алгоритма. Переход от «алгоритма» к «инструкциям выбора» меняет образ мышления.
  • Поведение value в браузерах неодинаково; часть удовольствия — тестирование браузеров (демо рассчитано в основном на современные браузеры).
  • Это демо — творческая инженерия наоборот: вместо создания движка оно использует существующий (CSS-движок браузера) — тот же креативный «хак», что встречается в старых работах веб-строителей.

Статья — отличный пример «мышления вне рамок»: прежде чем бежать к Elasticsearch, поиграйте несколько минут с CSS — иногда нужный вам поисковик уже живёт в браузере пользователя.

Заключение

«Поисковый движок на CSS» — забавное доказательство концепции (proof of concept), показывающее, что даже «язык описания внешнего вида» справляется с простым поиском, когда доступны селекторы. Для понятного примера идея статьи особенно привлекательна: input как живая база данных, селектор как запрос, а показ/скрытие как ранжирование. Если хотите понять, каков поисковик «по-настоящему минимально», это демо — забавная, но поучительная отправная точка.

Поиск с фидбеком: обучение ранжированию

Проблема: обратная связь, которая теряется

У полнотекстового поиска много применений: от поисковиков кастомных сайтов до корпоративных систем управления знаниями. Есть и очень полные инструменты вроде Elasticsearch, с которыми полнотекстовый индекс строится просто. Но то, что часто упускается, — это: как только пользователи начинают использовать поиск, они дают обратную связь — какой результат кликнули и какой отвергли. Эта статья строит игрушечный поисковик на Python (с nltk и scikit-learn), чтобы: 1) дать базовое понимание классического текстового поиска, 2) предложить простой способ использовать отзывы пользователей для улучшения результатов.

Основа: оценка TF-IDF и косинусная близость

Как и Google, наша задача — вернуть набор документов, отсортированных по «релевантности запросу». Для этого нужно число: оценка, количественно выражающая релевантность каждого документа запросу. Каждый документ превращается в TF-IDF-вектор — количественную оценку того, насколько каждое слово словаря заметно в этом документе, — а близость вектора документа и вектора запроса вычисляется через косинусное сходство. В примере статьи два документа без общих слов с запросом получают ноль, а документ с общим словом — оценку. С scikit-learn это делается одним классом TfidfVectorizer:

pythonfrom sklearn.feature_extraction.text import TfidfVectorizer

docs = [
    "Our mission is to make AI accessible to everyone",
    "How to build a chatbot in 10 minutes",
    "About us: we are a small team of engineers",
    "Chatbots are fun and easy to make",
]

vectorizer = TfidfVectorizer()
matrix = vectorizer.fit_transform(docs)

# строим вектор запроса в том же пространстве
query = ["who makes chatbots"]
query_vec = vectorizer.transform(query)

# косинусное сходство между запросом и каждым документом
from sklearn.metrics.pairwise import cosine_similarity
scores = cosine_similarity(query_vec, matrix).flatten()
print(scores)   # ранжирование на основе этих оценок

Это «хак» базового поисковика: словарь извлекается из набора документов, и когда пользователь задаёт запрос, возвращается документ, вектор которого ближе к вектору запроса (и так же просто можно вернуть 10 лучших результатов).

Оценка = взвешенная сумма признаков

Наша простая система использует для оценки только один бит информации: векторное сходство. Если мы хотим улучшить поиск, можно учесть и другие вещи: размер документа, близость слов запроса в тексте, свежесть документа и т.д. — при условии, что они выражаются числом с плавающей точкой, оценка вычисляется как взвешенная сумма этих признаков:

pythonscore(q, d) = w_1 * f_1(q, d) + w_2 * f_2(q, d) + ... + w_n * f_n(q, d)

Веса w_i позволяют контролировать относительную важность признаков. Например, если вы считаете, что большие документы привлекательнее для пользователя, добавьте «размер документа» как признак с небольшим весом (в сравнении с весом TF-IDF-сходства) — и по обратной связи поймёте, стало ли лучше.

Улучшение с обратной связью: проблема реального примера

Предположим, пользователи начали пользоваться, и собралась обратная связь: для каждого запроса известно, какие пары (документ, оценка) получены, где 0. — нерелевантен, а 1. — релевантен. Теперь текущая система на запрос «кто делает чат-ботов?» возвращает страницу про чат-бот, потому что в ней есть нужное слово, — но по обратной связи пользователи чаще ожидают увидеть страницу About Us. Вот здесь информация обратной связи и должна войти в оценку.

Взгляд машинного обучения: оптимизация весов w_i по обратной связи — это «задача классификации»: разделить документы на две группы «релевантен (R)» и «нерелевантен (N)» по их признакам. Если важен полный порядок, задача превращается в «порядковую регрессию» — а в веб-поиске популярный алгоритм для этого — Ranking SVM.

Но есть практическая проблема: даже простейшие методы ML (например, Naive Bayes для классификации релевантен/нерелевантен) требуют много данных. Если вы только начали собирать обратную связь или у вас мало пользователей, эти методы не работают. Поэтому статья предлагает более простой путь, довольствующийся малым количеством данных.

Решение с малым количеством данных: обратная связь ближайшего соседа как признак

Если запрос пользователя уже задавался, у нас есть его обратная связь: какие документы были релевантны. Логика проста: ранее релевантным документам даём оценку выше, нерелевантным — ниже. Статья определяет это как два признака:

  • Положительная обратная связь: сколько раз этот документ считался «релевантным» для этого запроса.
  • Отрицательная обратная связь: сколько раз этот документ считался «нерелевантным».

Следующий вызов: а если этот запрос никогда не задавался? Например, «кто строит чат-ботов». Решение статьи: найти ближайший соседний запрос — тот, у которого есть обратная связь и чей вектор (TF-IDF, как всегда) ближе к вектору текущего запроса, — и умножить два признака обратной связи на сходство ρ(q, q′) между запросом и соседом. Итог: чем похожее сосед, тем сильнее его обратная связь влияет на оценку; а если похожего соседа нет, признаки почти нулевые, и система возвращается к чистому TF-IDF.

pythondef positive_feedback_feature(query, query_vec, feedback, vectorizer):
    """Признак положительной обратной связи: доля положительной обратной связи ближайшего соседнего запроса, умноженная на сходство"""
    # найдём ближайший запрос с обратной связью
    best_q, best_rho = None, 0.0
    for fb_q in feedback:
        rho = cosine_similarity(query_vec, vectorizer.transform([fb_q]))[0][0]
        if rho > best_rho:
            best_q, best_rho = fb_q, rho

    feature = {}
    judgments = feedback[best_q]          # например {(doc_idx, 1), (doc_idx, 0), ...}
    positives = [i for i, rel in judgments if rel == 1.0]
    for doc_idx in positives:
        feature[doc_idx] = best_rho * (len([i for i in positives if i == doc_idx]) /
                                       max(1, len(positives)))
    return feature  # вектор признаков: вывод из релевантных документов похожего запроса

Класс Scorer: объединение TF-IDF и обратной связи

В конце статьи всё собирается в класс Scorer, который знает набор документов и умеет настраивать оценку по положительной обратной связи:

pythonclass Scorer:
    """Оценщик, ведущий себя по-разному «до показа обратной связи» и «после неё»."""

    def __init__(self, docs, weights=None):
        self.docs = docs
        self.vectorizer = TfidfVectorizer()
        self.matrix = self.vectorizer.fit_transform(docs)
        # w_tfidf и w_feedback: относительная важность двух признаков
        self.w = {"tfidf": 0.5, "feedback": 0.9} if weights is None else weights

    def scores(self, query, feedback=None):
        q_vec = self.vectorizer.transform([query])
        tfidf = cosine_similarity(q_vec, self.matrix).flatten()
        result = self.w["tfidf"] * tfidf
        if feedback:
            fb = self.feedback_feature(query, q_vec, feedback)   # признак соседа
            for doc_idx, val in fb.items():
                result[doc_idx] += self.w["feedback"] * val
        return result

Эксперимент статьи сравнивает два состояния: до обратной связи запрос «chatbots» возвращает последний документ (потому что слова там); после добавления положительной обратной связи для первого документа первым становится он — а если поднять вес признака TF-IDF, баланс между «содержанием» и «обратной связью» меняется.

Итоги

Посыл статьи укладывается в два предложения: 1) постройте простой текстовый поисковик на основе содержимого документов (TF-IDF + косинусное сходство), 2) научитесь улучшать оценку с помощью обратной связи пользователя — даже при малом количестве данных, через «квантификацию обратной связи похожих запросов». Этот образец лежит в основе систем Relevance Feedback и многих «обучающихся поисковых систем», существующих сегодня в продвинутых формах (Ranking SVM, Rocchio и даже нейросетевые реранкеры).

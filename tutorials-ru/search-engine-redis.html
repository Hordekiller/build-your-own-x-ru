Поисковый движок на Redis

Почему Redis? Почему с нуля?

Большинство поисковых движков опирается на «инвертированный индекс» (inverted index): таблицу, которая для каждого слова хранит список документов, содержащих это слово. Запрос — это пересечение этих списков. Но правильное построение такого индекса требует немалой инженерии: хранение, конкурентность, масштабируемость… Статья Джозайи Карлсона использует умный обходной путь: Redis — это «сервер удалённых структур данных» (remote data structure server), а не просто кэш. Поэтому структуры данных инвертированного индекса (и даже оценки TF-IDF) можно определить прямо внутри Redis, а Python-программу сделать лишь «переводчиком запроса в команды Redis»; конкурентность и персистентность решает сервер.

Ключевой момент: правильный выбор инструмента — половина проектирования. Вместо того чтобы имитировать алгоритмы поиска на реляционной базе, мы используем структуры, «созданные по замыслу» для этой задачи: хеши (Hashes) и сортированные множества (Sorted Sets) в Redis.

Проектирование инвертированного индекса на хешах и сортированных множествах

Схема статьи состоит из трёх частей, каждая отображается на свою структуру Redis:

  • Сами документы: каждый документ хранится в хеше Redis; поля — например, заголовок, текст, адрес и id документа. Теперь «чтение документа» — это один HGETALL.
  • Инвертированный индекс — частота слова в документе (tf): для каждого слова держим хеш, где ключ = id документа, а значение = сколько раз слово встретилось в документе. «Увеличение» атомарно выполняется одним HINCRBY.
  • Статистическая роль слова в документе (idf) и оценки: чтобы вычислить «насколько это слово специфично для этого документа», нужна частота документов: число документов, где слово встречается. Это число хранится в счётчике, а оценки — в сортированном множестве.
pythonimport redis

r = redis.Redis(host='localhost', port=6379, db=0)

def index_document(doc_id, text):
    """Индексация документа: сохранить текст и обновить инвертированный индекс"""
    # 1) сохраняем сам документ
    r.hset('doc:%s' % doc_id, 'text', text)

    # 2) считаем каждое слово и добавляем в инвертированный индекс
    for word in text.split():
        r.hincrby('index:%s' % word, doc_id, 1)

def search(query):
    """Простой поиск: все документы, содержащие все слова"""
    words = query.split()
    if not words:
        return []
    # пересечение множеств документов каждого слова — в Redis через SINTER
    keys = ['index:%s' % w for w in words]
    return r.sinter(keys)

Упрощённая версия выше показывает главную идею; статья наполняет эту оболочку полными деталями (токенизация, нормализация, оценка на основе w(t,d) и сортировка результатов), чтобы поиск действительно возвращал «по релевантности», а не только пустое пересечение.

Оценка TF-IDF в Redis

После простого примера статья переходит к настоящему ранжированию. Для каждого слова и каждого документа вычисляем оценку tf/idf; для «документа-запроса» берём сумму оценок всех его слов. Здесь Redis делает ещё один шаг вперёд: оценки документов хранятся в сортированном множестве (Sorted Set), затем командами ZUNIONSTORE/ZINTERSTORE объединяются оценки нескольких слов, а ZREVRANGE возвращает результаты «по релевантности».

python# Простое вычисление idf: число документов, содержащих слово
doc_count = int(r.get('total_docs'))
for word in words_of_query:
    df = r.scard('docswith:%s' % word)   # число документов со словом
    idf = math.log(doc_count / (1.0 + df))
    # для каждого документа со словом кладём вес w = tf * idf в zset оценок
    for doc_id, tf in r.hgetall('index:%s' % word).items():
        r.zadd('score:%s' % word, float(tf) * idf, doc_id)

# сумма оценок по всем словам запроса
r.zunionstore('result', ['score:%s' % w for w in words_of_query])
# десять лучших результатов
top = r.zrevrange('result', 0, 9, withscores=True)
Напоминание математики: TF (частота слова в документе) говорит, насколько слово заметно в этом документе; IDF (обратная частота документа) говорит, насколько слово «специфично». Их произведение — оценка, которая обесценивает частые бесполезные слова (вроде «и», «в») и усиливает характерные.

Чему вы научитесь

  • Инвертированный индекс означает «от слова к документам», а не «от документа к словам» — ключ к успеху любого поисковика, и здесь он реализован тремя типами структур Redis.
  • Выбор правильной структуры данных: хеш — для ключ-значение документа, zset — для сортируемых оценок, set — для быстрого пересечения. Redis — это ровно тот словарь, который «говорит издалека».
  • Оценка: хороший поиск — это не только «найти», но и «ранжировать». TF-IDF прост и понятен, а в распределённом виде реализуется командами Redis без Python-циклов.
  • Практическая масштабируемость: с Redis индекс и оценки в памяти; миллионы документов и миллионы запросов отвечают без фантазийного перепроектирования.

Итоги

Статья показывает, что построить «по-настоящему рабочий» поисковый движок можно, не написав ни миллисекунды кода управления памятью, — достаточно поместить правильную структуру данных в правильное место. Предложенный учебный маршрут: сначала поймите концепции поиска и TF-IDF (например, по уроку «Поиск важных слов в тексте с TF-IDF» из этого же раздела), затем прочитайте эту реализацию на Redis, чтобы увидеть, как концепции превращаются в архитектуру системы.

Шаблонизатор на JS за 20 строк

⚙ Язык: JavaScript 📁 Шаблонизатор 🌐 Русская страница 🔗 Оригинальный источник
Оригинальный источник: «JavaScript template engine in just 20 lines»
↗ Перейти к оригинальному уроку فارسی — Персидская версия EN — English version

1. Предыстория

Автор строил AbsurdJS — JavaScript-препроцессор, который сначала генерировал CSS, а затем CSS/HTML. Раз он генерировал HTML, естественно было выступать ему и в роли шаблонного движка — то есть своего рода «заполнение разметки данными». Но существовавшие движки шаблонов в основном работали только на NodeJS и не годились для браузера. Он наткнулся на пост в блоге Джона Резига (JavaScript Micro-Templating), немного переделал его и уложился в 20 строк. В этой статье тот же движок восстанавливается шаг за шагом.

Наша цель — функция, которая принимает шаблон и данные и возвращает итоговый вывод:

javascriptvar TemplateEngine = function(tpl, data) {
    // магия вот здесь ...
}
var template = 'Hello, my name is <%name%>. I\'m <%age%> years old.';
console.log(TemplateEngine(template, {
    name: "Krasimir",
    age: 29
}));
// вывод: Hello, my name is Krasimir. I'm 29 years old.

2. Регулярное выражение и поиск всех плейсхолдеров

Первый шаг — найти динамические куски внутри шаблона. Начнём с регулярного выражения — выражения, которое захватывает все части между <% и %>, а с флагом g (глобальным) — все совпадения, а не только первое:

javascriptvar re = /<%([^%>]+)?%>/g;
var match = re.exec(tpl);
// match содержит: "<%name%>", "name", index и input

// для обработки всех совпадений — в цикле while
var re = /<%([^%>]+)?%>/g, match;
while(match = re.exec(tpl)) {
    console.log(match);   // будут видны и <%name%>, и <%age%>
}

3. Почему простой замены недостаточно

Самый простой путь — tpl.replace(match[0], data[match[1]]) — работает, но только для плоских односторонних данных. Если наши данные вложены, например { profile: { age: 29 } }, а в шаблоне написано <%profile.age%>, то получается выражение data["profile.age"], которое даёт undefined. Правильный путь? Помещать между <% и %> настоящий JavaScript-код, выполняющийся на данных; например, <%this.profile.age%>. А для этого нужен new Function — создание функции из строки:

javascriptvar fn = new Function("arg", "console.log(arg + 1);");
fn(2); // вывод: 3  — эквивалент fn = function(arg) { console.log(arg + 1); }

4. Сборка тела функции: циклы ломают шаблон

Теперь нужно «собрать» тело функции. Если просто склеивать строки через +, всё ломается, когда пользователь пишет в шаблоне цикл:

javascriptvar template =
'My skills:' +
'<%for(var index in this.skills) {%>' +
'<%this.skills[index]%>' +
'<%}%>';

Склейка через + даёт return 'My skills:' + for(...) { + ...}, что является синтаксической ошибкой. Решение Джона Резига: складывать все куски в массив и в конце склеивать через join — тогда управляющий код может «напрямую» попасть в тело метода:

javascriptvar r = [];
r.push('My skills:');
for(var index in this.skills) {
    r.push(this.skills[index]);
}
return r.join('');

Чтобы генерировать такой код, используем переменную cursor, которая показывает «где мы в шаблоне», и функцию add, добавляющую строки в code. Плейсхолдеры — это «код» (их не нужно брать в кавычки), остальной текст — «строка» (его нужно взять в кавычки и экранировать "):

javascriptvar TemplateEngine = function(tpl, data) {
    var re = /<%([^%>]+)?%>/g,
        code = 'var r=[];\n',
        cursor = 0, match;
    var add = function(line, js) {
        js ? code += 'r.push(' + line + ');\n'
           : code += 'r.push("' + line.replace(/"/g, '\\"') + '");\n';
    }
    while(match = re.exec(tpl)) {
        add(tpl.slice(cursor, match.index));
        add(match[1], true);            // содержимое плейсхолдера — это код
        cursor = match.index + match[0].length;
    }
    add(tpl.substr(cursor, tpl.length - cursor));
    code += 'return r.join("");';
    return new Function(code.replace(/[\r\t\n]/g, '')).apply(data);
}

Результат new Function создан без аргументов и вызывается через apply(data); «this» внутри тела функции указывает на наши данные — поэтому <%this.name%> работает.

5. Поддержка логики: if/else и циклы

На том же примере с циклом текущий вывод даёт ошибку Unexpected token for; потому что строку for(...) { не нужно оборачивать в r.push(...) — она должна попадать в скрипт «как есть». Решение — второе регулярное выражение, определяющее, начинается ли код внутри плейсхолдера с управляющих ключевых слов:

javascriptvar reExp = /(^( )?(if|for|else|switch|case|break|{|}))(.*)?/g;

var add = function(line, js) {
    js ? code += line.match(reExp) ? line + '\n' : 'r.push(' + line + ');\n'
       : code += 'r.push("' + line.replace(/"/g, '\\"') + '");\n';
}

Теперь в шаблоне можно писать полную логику:

javascriptvar template =
'My skills:' +
'<%if(this.showSkills) {%>' +
    '<%for(var index in this.skills) {%>' +
    '<a href="#">' + '<%this.skills[index]%>' + '</a>' +
    '<%}%>' +
'<%} else {%>' +
    '<p>none</p>' +
'<%}%>';

6. Финальная версия: всего 15 строк

С парой небольших оптимизаций (возврат add для цепочек и пропуск пустых строк) финальная версия — не то что не 20 строк, а всего 15:

javascriptvar TemplateEngine = function(html, options) {
    var re = /<%([^%>]+)?%>/g, reExp = /(^( )?(if|for|else|switch|case|break|{|}))(.*)?/g,
        code = 'var r=[];\n', cursor = 0, match;
    var add = function(line, js) {
        js ? (code += line.match(reExp) ? line + '\n' : 'r.push(' + line + ');\n')
           : (code += line != '' ? 'r.push("' + line.replace(/"/g, '\\"') + '");\n' : '');
        return add;
    }
    while(match = re.exec(html)) {
        add(html.slice(cursor, match.index))(match[1], true);
        cursor = match.index + match[0].length;
    }
    add(html.substr(cursor, html.length - cursor));
    code += 'return r.join("");';
    return new Function(code.replace(/[\r\t\n]/g, '')).apply(options);
}
Обучающий момент: этот движок «переводит шаблон в код» (компилирует), а не разбирает шаблон на лету; та же логика стоит за современными движками вроде EJS — и хочется сделать сноску на микро-шаблонизацию Джона Резига, которая переведена в следующем уроке этого раздела.

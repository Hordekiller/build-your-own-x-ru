Микро-шаблонизатор на JavaScript

Оригинальный источник: «JavaScript Micro-Templating»

Введение: функция, которая всё изменила

В 2008 году Джон Резиг — создатель jQuery — опубликовал функцию из 33 строк под названием JavaScript Micro-Templating, которая совершила переворот в «использовании шаблонов в браузере»: это tmpl(str, data), которая принимает шаблон, компилирует его (переводит в исполняемый код) и кэширует в памяти. В этом уроке мы разберём, как она работает, строку за строкой.

Способ использования:

html<script type="text/html" id="item_tmpl">
  <div id="<%=id%>" class="<%=klass%>">
    <div class="item"><%=name%></div>
  </div>
</script>

<script>
  var results = tmpl("item_tmpl", { id: 1, klass: "item", name: "Иван" });
  document.getElementById("results").innerHTML = results;
</script>

Ядро функции

javascript// Микро-шаблонизация JavaScript, Джон Резиг (лицензия MIT)
(function(){
  var cache = {};

  this.tmpl = function tmpl(str, data){
    // Определяем: это id тега или сама строка шаблона?
    var fn = !/\W/.test(str) ?
      cache[str] = cache[str] ||
        tmpl(document.getElementById(str).innerHTML) :
      new Function("obj",
        "var p=[],print=function(){p.push.apply(p,arguments);};" +
        "with(obj){p.push('" +
        str
          .replace(/[\r\t\n]/g, " ")
          .split("<%").join("\t")
          .replace(/((^|%>)[^\t]*)'/g, "$1\r")
          .replace(/\t=(.*?)%>/g, "',$1,'")
          .split("\t").join("');")
          .split("%>").join("p.push('")
          .split("\r").join("\\'")
        + "');}return p.join('');");
    return data ? fn( data ) : fn;
  };
})();
Ключевая идея: шаблон остаётся «строкой», но с помощью new Function превращается в тело настоящей функции. То есть на выходе — «исполнение кода», а не разбор текста: быстро, просто и очень гибко.

Разбор функции по шагам

  • Определение ввода: если в str нет необычных символов (проверка /\W/), считаем его id тега <script type="text/html">, читаем содержимое и сохраняем в cache — при последующих вызовах уже скомпилированный код берётся из кэша. Иначе сам str — это шаблон.
  • Очистка и разметка: символы [\r\t\n] удаляются, <% превращается в таб \t (чтобы позже стать «закрытием строки»), а апострофы внутри шаблона помечаются \r, чтобы не сломать строку кода при её построении.
  • Превращение меток в код: <%=expr%> превращается в ',$1,' — то есть «добавь вывод этого выражения в массив»; \t становится '); (закрытие push), а %> — p.push(' (открытие push). В итоге получается строка тела функции.
  • Создание функции с with(obj): внутри созданной функции переменные шаблона доступны из объекта данных — with(obj){ p.push('...') } — а массив p собирает фрагменты, чтобы в конце p.join('') дал финальный вывод.
  • Вызов: если переданы data, функция выполняется с данными и выдаёт вывод; если нет — возвращается сама функция (для последующего использования).

Зачем столько кода?

  • Настоящее исполнение JavaScript внутри шаблона: всё, что вы напишете в шаблоне — циклы, условия, вызовы функций — действительно выполняется; например, <% for (var i=0; i<items.length; i++) { %>…<% } %>.
  • Автоматический кэш: шаблоны с id компилируются только один раз; скорость многократного выполнения достигает уровня обычных функций.
  • Без зависимостей: чистая JavaScript-функция, работающая в любом окружении (браузер, Node), — и именно эта простота вдохновила последующие движки (например, движок на 20 строк из этого же раздела).
Замечание по безопасности/практике: использование new Function означает исполнение кода внутри шаблона; в реальной практике (с пользовательским вводом) нужно быть осторожным. Но как «инженерное чудо» эти 33 строки стоит полчаса размышлений.

Итоги

Микро-шаблонизация Джона Резига показала, что «движок шаблонов» не обязательно должен быть большим проектом: строка, регулярное выражение, new Function и кэш — и всё. Поняв эту реализацию, вы легко прочитаете любой JavaScript-движок шаблонов (EJS, Underscore и т.д.), потому что все они питаются одной и той же идеей «шаблон → код».

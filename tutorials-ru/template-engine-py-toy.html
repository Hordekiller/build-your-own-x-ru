Введение и проектирование языка

Этот урок строит простой Python-движок шаблонов и показывает, что у него под капотом — как шаблон «компилируется», а затем «рендерится». В языке шаблонов два вида тегов: переменные через {{ }} и блоки через {% %}:

html<!-- переменные между двумя фигурными скобками -->
<div>{{my_var}}</div>

<!-- блоки через {% %} и закрытие через «end» -->
{% each items %}
    <div>{{it}}</div>
{% end %}

Возможности языка: циклы each, условия if/else (с операторами ==, <=, >=, !=, is, >, <), а также вызовы функций (callables) с позиционными или ключевыми аргументами:

html<!-- цикл по людям; «it» — текущий элемент -->
{% each people %}
    <div>{{it.name}}</div>
{% end %}

<!-- «..» означает доступ к переменной родительского контекста -->
{% each records %}
    <div>{{..name}}</div>
{% end %}

<!-- условие -->
{% if num > 5 %}
    <div>more than 5</div>
{% else %}
    <div>less than or equal to 5</div>
{% end %}

<!-- вызов функции с аргументом и ключевым словом -->
<div class='date'>{% call prettify date_created %}</div>
<div>{% call log 'here' verbosity='debug' %}</div>

Теория: зачем нужно синтаксическое дерево (AST)?

Компиляторы представляют содержимое программы в виде абстрактного синтаксического дерева (AST) — результата лексического анализа текста. У дерева есть преимущество перед сырым текстом: в нём нет лишних разделителей (например, фигурных скобок шаблона), а к узлам можно добавлять свойства, не трогая код. Путь работы нашего движка: токенизация → построение AST → рендер (обход дерева с контекстом).

Токенизация регулярным выражением

Первый шаг — разбить шаблон на фрагменты; каждый фрагмент — либо сырой HTML, либо тег. Используем re.split и ленивое (нежадное) регулярное выражение, которое распознаёт оба вида тегов:

pythonimport re

VAR_TOKEN_START = '{{'
VAR_TOKEN_END = '}}'
BLOCK_TOKEN_START = '{%'
BLOCK_TOKEN_END = '%}'

TOK_REGEX = re.compile(r"(%s.*?%s|%s.*?%s)" % (
    VAR_TOKEN_START, VAR_TOKEN_END,
    BLOCK_TOKEN_START, BLOCK_TOKEN_END
))

# пример:
>>> TOK_REGEX.split('{% each vars %}<i>{{it}}</i>{% endeach %}')
['{% each vars %}', '<i>', '{{it}}', '</i>', '{% endeach %}']

? внутри опций означает ленивое повторение; регулярное выражение должно остановиться на первом совпадении, чтобы, например, теги переменных внутри блоков отделялись правильно. Каждый фрагмент помещается в объект _Fragment, который определяет его тип; четыре типа: VAR, OPEN_BLOCK, CLOSE_BLOCK и TEXT.

Построение AST

Теперь фрагменты становятся узлами. Базовый класс _Node определяет методы process_fragment() и render(), а также имеет хуки enter_scope()/exit_scope(), которые компилятор вызывает при открытии/закрытии области видимости узла. Дочерние узлы хранятся в children:

pythonclass _Node(object):
    def __init__(self, fragment=None):
        self.children = []
        self.creates_scope = False
        self.process_fragment(fragment)
    def process_fragment(self, fragment): pass
    def enter_scope(self): pass
    def render(self, context): pass
    def exit_scope(self): pass
    def render_children(self, context, children=None):
        if children is None:
            children = self.children
        def render_child(child):
            child_html = child.render(context)
            return '' if not child_html else str(child_html)
        return ''.join(map(render_child, children))

# пример: узел переменной
class _Variable(_Node):
    def process_fragment(self, fragment):
        self.name = fragment
    def render(self, context):
        return resolve_in_context(self.name, context)

Тип узла определяется по «команде блока» (первому слову внутри {% %}); например, {% each items %} — это узел each. Узлы, создающие область видимости (циклы/условия), при компиляции добавляются в стек областей, а их дочерние прикрепляются к ним; достижение закрывающего тега закрывает область:

pythondef compile(self):
    root = _Root()
    scope_stack = [root]
    for fragment in self.each_fragment():
        if not scope_stack:
            raise TemplateError('nesting issues')
        parent_scope = scope_stack[-1]
        if fragment.type == CLOSE_BLOCK_FRAGMENT:
            parent_scope.exit_scope()
            scope_stack.pop()
            continue
        new_node = self.create_node(fragment)
        if new_node:
            parent_scope.children.append(new_node)
            if new_node.creates_scope:
                scope_stack.append(new_node)
                new_node.enter_scope()
    return root

Рендер: различение литералов и имён переменных

На этапе рендера нужно понять, является ли выражение «константой» или «именем переменной в контексте» — это делает ast.literal_eval, безопасно вычисляющий строку Python:

pythonimport ast

def eval_expression(expr):
    try:
        return 'literal', ast.literal_eval(expr)
    except (ValueError, SyntaxError):
        return 'name', expr

Разрешение имён: точечные пути и «..»

Финальный кусочек пазла: функция разрешения имени, которая проходит и по точечным именам (it.name) во вложенных словарях, и по префиксу .. возвращается к родительскому контексту:

pythondef resolve(name, context):
    if name.startswith('..'):
        context = context.get('..', {})
        name = name[2:]
    try:
        for tok in name.split('.'):
            context = context[tok]
        return context
    except KeyError:
        raise TemplateContextError(name)

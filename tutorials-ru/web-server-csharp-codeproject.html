О чём это

Статья пошагово описывает создание веб-сервера на C#, чтобы вы почувствовали, как он собирается с чистого листа: все дизайнерские и технические решения — удачные или нет — и весь процесс. Сначала заставляем заработать класс HttpListener, затем добавляем логирование, строим каркас веб-приложения, вводим простой механизм маршрутизации, разбираемся с авторизацией и истечением сессий и выполняем несколько AJAX-запросов.

Что вы узнаете

  • Как устроен HttpListener и зачем он удобнее низкоуровневых сокетов
  • Разделение сервера на модули: Listener, Router и SessionManager
  • Простые стратегии маршрутизации HTTP-методов и путей на обработчики
  • Жизненный цикл сессии: создание, использование, истечение

Основная идея

Сервер реализован как небольшая библиотека: Listener.cs принимает соединения через HttpListener и отвечает на подключения, Router.cs управляет маршрутизацией, а SessionManager.cs хранит состояние сессий подключения. Так как сервер почти не хранит состояния, большинство поведения можно сделать статическими синглтонами.

Начальный эскиз сервера выглядит так:

csharp// Класс Server — статический хост веб-службы
public static class Server
{
  private static HttpListener listener;
  // ... инициализация и цикл приёма соединений
}

Почему это важно

Вы разберёте типичную серверную архитектуру на живом примере: прослушивание, маршрутизация, обработка состояния — и поймёте, что современные веб-фреймворки лишь автоматизируют те же четыре-пять модулей.

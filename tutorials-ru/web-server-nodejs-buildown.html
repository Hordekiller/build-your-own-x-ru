Введение — что это за книга?

Большинство людей ежедневно пользуются HTTP, но мало кто разбирается в его внутреннем устройстве. Эта книга из серии «Build Your Own X» углубляется в предмет и учит основам с нуля, чтобы лучше понять инструменты и технологии, на которые мы полагаемся:

  • Сетевое программирование.
  • Протоколы и коммуникации.
  • HTTP во всех деталях.

Книга в двух частях: часть первая строит базовый HTTP-сервер (7 глав), а часть вторая покрывает приложения и расширения (6 глав: динамический контент, файлы, Range-запросы, кэширование, сжатие и WebSocket).

Обзор HTTP и простой TCP-сервер

Книга начинается с обзора протокола HTTP: запрос и ответ, методы, коды статуса и заголовки — затем переходит к сетевому программированию. Первый проект — сырой TCP-сервер, который просто принимает соединения и принимает/отправляет сырые данные:

javascriptconst net = require('net');

// Простой TCP-сервер: приветствует каждое соединение
const server = net.createServer((socket) => {
    console.log('клиент подключился');

    socket.on('data', (data) => {
        console.log('получено:', data.toString());
        socket.write('Привет от сервера!\r\n');
    });

    socket.on('close', () => console.log('соединение закрыто'));
});

server.listen(8000, () => console.log('сервер на порту 8000'));

Следующая глава — Promise и события: событийная модель Node (Event Loop), колбэки, промисы и async/await — ведь сетевые серверы по своей природе асинхронны. Затем тем же инструментом поверх TCP определяется простой сетевой протокол, чтобы увидеть, как у протоколов есть «формат сообщения» и «конечный автомат».

Семантика и синтаксис HTTP

Прежде чем писать HTTP-сервер, нужно правильно знать HTTP. Эта глава полностью разбирает синтаксис и семантику HTTP:

  • Структура запроса: строка запроса (METHOD path HTTP/version), заголовки (Header: value) и тело (необязательно, с Content-Length).
  • Структура ответа: строка статуса (HTTP/version status reason), заголовки и тело.
  • Методы: GET, POST, HEAD и др.; коды статуса: 200, 404, 301 и др.; ключевые заголовки: Host, Content-Type, Content-Length и др.
  • Поддержание соединения: Connection: keep-alive и точная граница сообщений — место, где ломается большинство начинающих серверов, потому что они не знают, где заканчивается запрос.

Пишем базовый HTTP-сервер

Теперь время реализации: поверх прежнего TCP-сервера садятся парсер запроса, построитель ответа и простая маршрутизация:

javascriptconst net = require('net');

const server = net.createServer((socket) => {
    let buf = '';

    socket.on('data', (data) => {
        buf += data.toString();

        // Запрос завершён, когда видим \r\n\r\n
        const headerEnd = buf.indexOf('\r\n\r\n');
        if (headerEnd === -1) return; // ещё не завершён; ждём

        const requestLine = buf.slice(0, buf.indexOf('\r\n'));
        const [method, path, version] = requestLine.split(' ');

        console.log(`${method} ${path}`);

        const body = 'Hello, World!';
        const response =
            'HTTP/1.1 200 OK\r\n' +
            `Content-Length: ${body.length}\r\n` +
            'Content-Type: text/plain\r\n' +
            '\r\n' +
            body;

        socket.write(response);
        socket.end();
    });
});

server.listen(8000, () => console.log('HTTP-сервер на порту 8000'));

В традиции «строим с нуля» эта реализация отбрасывает сам http Node и использует базовый net, чтобы все слои были сделаны вручную, — затем та же логика сравнивается со стандартной библиотекой.

Часть вторая: расширения

Часть вторая приближает базовый сервер к настоящему, глава за главой:

  • Динамический контент и потоки (Streaming): генерация ответов на лету вместо заранее собранных строк; знакомство со Stream API в Node (как конвейер: readable.pipe(writable)).
  • Файловый ввод/вывод и управление ресурсами: раздача файлов с диска, MIME-типы и правильная обработка ошибок и оборванных соединений.
  • Range-запросы: поддержка заголовка Range и ответа 206 Partial Content — то, на что полагается стриминг видео.
  • Кэш HTTP: заголовки Cache-Control, ETag и Last-Modified, чтобы не пересылать неизменный контент повторно.
  • Сжатие: поддержка Accept-Encoding и ответа gzip через Stream API — сжатие «на лету» без удержания всего файла в памяти.
  • WebSocket и конкурентность: ручное обновление соединения с HTTP до WebSocket (рукопожатие через Upgrade, каркас фреймов с маской) и управление конкурентностью открытых соединений.
javascript// Раздача файла с диска потоком: не занимает память
const fs = require('fs');
const path = require('path');

function serveFile(socket, filePath) {
    const full = path.join(__dirname, 'public', filePath);
    const stat = fs.statSync(full);

    socket.write('HTTP/1.1 200 OK\r\n');
    socket.write(`Content-Length: ${stat.size}\r\n`);
    socket.write('Content-Type: text/html; charset=utf-8\r\n');
    socket.write('\r\n');

    // Стримим файл клиенту кусками
    const stream = fs.createReadStream(full);
    stream.pipe(socket);
}

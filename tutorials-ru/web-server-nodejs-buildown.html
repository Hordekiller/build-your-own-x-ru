Создай свой веб-сервер с нуля на JavaScript

1. Введение — что это за книга

Большинство людей пользуются HTTP каждый день, но немногие разбираются в его внутреннем устройстве. Эта книга из серии «Build Your Own X» копает вглубь и учит основам с нуля — чтобы получить ясное понимание инструментов и технологий, на которые мы полагаемся:

  • Сетевое программирование.
  • Протоколы и коммуникации.
  • HTTP в полных деталях.

Книга в двух частях: первая часть строит базовый HTTP-сервер (7 глав), вторая покрывает приложения и расширения (6 глав: динамический контент, файлы, Range-запросы, кэширование, сжатие и WebSocket).

2. Обзор HTTP и простой TCP-сервер

Книга начинается с обзора протокола HTTP: запрос и ответ, методы, коды статуса и заголовки — затем переходит к сетевому программированию. Первый проект — сырой TCP-сервер, который лишь принимает соединения и шлёт/принимает сырые данные:

javascriptconst net = require('net');

// простой TCP-сервер: приветствует каждое соединение
const server = net.createServer((socket) => {
    console.log('клиент подключился');

    socket.on('data', (data) => {
        console.log('получено:', data.toString());
        socket.write('Привет от сервера!\r\n');
    });

    socket.on('close', () => console.log('соединение закрыто'));
});

server.listen(8000, () => console.log('сервер на порту 8000'));

Следующая глава — Promise и события: событийная модель Node (Event Loop), колбэки, промисы и async/await — потому что сетевые серверы по своей природе асинхронны. Затем теми же инструментами поверх TCP определяется простой сетевой протокол, чтобы увидеть, как протоколы имеют «формат сообщений» и «конечный автомат».

3. Семантика и синтаксис HTTP

Прежде чем писать HTTP-сервер, нужно правильно знать HTTP. Эта глава полностью разбирает синтаксис и семантику:

  • Структура запроса: строка запроса (METHOD path HTTP/version), заголовки (Header: value) и тело (опционально, с Content-Length).
  • Структура ответа: строка статуса (HTTP/version status reason), заголовки и тело.
  • Методы: GET, POST, HEAD и…; коды статуса: 200, 404, 301 и…; ключевые заголовки: Host, Content-Type, Content-Length и…
  • Продолжение соединения: Connection: keep-alive и точная граница сообщений — место, где ломается большинство новичков, потому что непонятно, где заканчивается запрос.

4. Пишем базовый HTTP-сервер

Теперь реализация: на прежний TCP-сервер садятся парсер запроса, конструктор ответа и простая маршрутизация:

javascriptconst net = require('net');

const server = net.createServer((socket) => {
    let buf = '';

    socket.on('data', (data) => {
        buf += data.toString();

        // запрос завершён, когда мы видим \r\n\r\n
        const headerEnd = buf.indexOf('\r\n\r\n');
        if (headerEnd === -1) return; // ещё не полный; ждём

        const requestLine = buf.slice(0, buf.indexOf('\r\n'));
        const [method, path, version] = requestLine.split(' ');

        console.log(`${method} ${path}`);

        const body = 'Hello, World!';
        const response =
            'HTTP/1.1 200 OK\r\n' +
            `Content-Length: ${body.length}\r\n` +
            'Content-Type: text/plain\r\n' +
            '\r\n' +
            body;

        socket.write(response);
        socket.end();
    });
});

server.listen(8000, () => console.log('HTTP-сервер на порту 8000'));

В духе «построй с нуля» эта реализация отбрасывает собственный http в Node и использует базовый net, чтобы все слои были самодельными, — затем та же логика сравнивается со стандартной библиотекой.

5. Вторая часть: расширения

Вторая часть приближает базовый сервер к настоящему, глава за главой:

  • Динамический контент и потоки (Streaming): генерация ответов на лету вместо заранее собранных строк; знакомство со Stream API в Node (как конвейер: readable.pipe(writable)).
  • Файловый ввод/вывод и управление ресурсами: отдача файлов с диска, MIME-типы и корректная обработка ошибок и оборванных соединений.
  • Range-запросы: поддержка заголовка Range и ответа 206 Partial Content — то, на что опираются стриминговые видео.
  • HTTP-кэш: заголовки Cache-Control, ETag и Last-Modified — чтобы не отправлять неизменный контент повторно.
  • Сжатие: поддержка Accept-Encoding и gzip-ответа через Stream API — «потоковое» сжатие без хранения всего файла в памяти.
  • WebSocket и конкурентность: самодельное обновление соединения с HTTP до WebSocket (рукопожатие через Upgrade, кадрирование фреймов с маской и т.д.) и управление многими открытыми соединениями.
javascript// отдача файла с диска потоком: память не занимается
const fs = require('fs');
const path = require('path');

function serveFile(socket, filePath) {
    const full = path.join(__dirname, 'public', filePath);
    const stat = fs.statSync(full);

    socket.write('HTTP/1.1 200 OK\r\n');
    socket.write(`Content-Length: ${stat.size}\r\n`);
    socket.write('Content-Type: text/html; charset=utf-8\r\n');
    socket.write('\r\n');

    // потоковая передача файла клиенту по частям
    const stream = fs.createReadStream(full);
    stream.pipe(socket);
}

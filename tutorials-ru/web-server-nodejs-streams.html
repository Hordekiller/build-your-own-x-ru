Напишем веб-сервер с нуля с помощью потоков NodeJS

⚙ Язык: Node.js 📁 Веб-сервер 🌐 Русская страница 🔗 Оригинальный источник
Оригинальный источник: «Let's code a web server from scratch with NodeJS Streams!»

Введение

В этом посте мы обращаемся к основам и строим простой веб-сервер с нуля на NodeJS. По пути разберём структуру HTTP-запросов и ответов и познакомимся со Stream API Node.

Сначала быстро пройдёмся по встроенному модулю http. Затем рассмотрим общую структуру HTTP-запроса и ответа. Потом на встроенном модуле net построим низкоуровневый TCP-сервер и попробуем превратить его в пригодный веб-сервер.

Стоит отметить: весь код этой статьи никогда не следует использовать в продакшене; он только для обучения.

Краткий взгляд на встроенный модуль http

NodeJS поставляется с простым HTTP-сервером. Он позволяет слушать любой порт и предоставлять функцию-callback, вызываемую на каждый входящий запрос.

Callback получает два аргумента: объект Request и объект Response. Объект Request заполнен полезными свойствами запроса, а объект Response используется для отправки ответа клиенту. Пример «Hello World» на http-сервере Node:

JavaScriptconst http = require('http');
const server = http.createServer();
server.on('request', (req, res) => {
  console.log(`${new Date().toISOString()} - ${req.method} ${req.url}`);
  res.setHeader('Content-Type','text/plain');
  res.end('Hello World!');
});
server.listen(3000);

Это запускает веб-сервер, слушающий порт 3000. Когда приходит запрос, логируется сообщение с текущей датой, затем метод и URL запроса. Эти данные берутся из параметра req — объекта Request, созданного Node. У этого объекта есть и свойство .socket — нижележащий TCP-сокет.

В коде выше доступ к упорядоченному объекту через req.method и req.url означает: кто-то другой потрудился за нас разобрать текст запроса и превратить его в упорядоченный объект. В следующем разделе посмотрим на структуру HTTP-запроса, чтобы получить зацепки для его разбора.

Разбор HTTP

Вот пример HTTP-запроса:

HTTPPOST /posts/42/comments HTTP/1.1\r\n
Host: www.my-api.com\r\n
Accept: application/json\r\n
Authorization: Bearer N2E5NTU2MzQ5MGQ4N2UzNjIxOTY2ZDU1M2YwNjA3OGFjYjgyMjU4NQ\r\n
Accept-Encoding: gzip, deflate, br\r\n
Content-Type: application/json\r\n
Content-Length: 28\r\n
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.13; rv:58.0)\r\n
\r\n
{"text":"this is a comment"}
  • Каждая строка разделяется \r\n.
  • Первая строка называется «строка запроса» (request line); она состоит из трёх разделённых пробелами токенов: метод запроса (POST), URI запроса (/posts/42/comments) и версия протокола (HTTP/1.1).
  • Каждая следующая строка — заголовок запроса; она состоит из поля и его значения, разделённых :.
  • Строка только с \r\n отмечает конец заголовков. Всё после неё — тело запроса.
  • В этом запросе тело — JSON-документ, согласованный с заголовком Content-Type, а его длина 28 байт соответствует заголовку Content-Length.

А вот пример HTTP-ответа:

HTTPHTTP/1.1 200 OK\r\n
Server: nginx/1.9.4\r\n
Date: Fri, 20 Apr 2017 16:19:42 GMT\r\n
Content-Type: application/json\r\n
Content-Length: 141\r\n
\r\n
{
  "id": "8fh924b42o",
  "text": "this is a comment",
  "createdAt": "2017-04-20T16:19:42.840Z",
  "updatedAt": "2017-04-20T16:19:42.840Z"
}
  • Как и в запросе, каждая строка разделяется \r\n.
  • Первая строка называется «строка статуса» (status line): версия HTTP, код статуса (200) и фраза-причина (OK).
  • Каждая следующая строка — заголовок ответа с той же структурой, что у заголовков запроса.
  • Пустая строка отмечает конец заголовков и начало тела.
  • Тело — JSON-документ на 141 байт, согласованный со значениями заголовков.

Приём и разбор HTTP-запроса

NodeJS предоставляет встроенный модуль net для построения потокового TCP-сервера. «Потоковый» значит, что сервер может отправлять и получать данные во времени и использует Stream API Node.

Там, где http-сервер испускал событие request с объектами Request и Response, TCP-сервер испускает событие connection с объектом Socket. Объекты Socket — Duplex Streams: их можно и читать, и писать.

Если отправить HTTP-запрос нашему TCP-серверу, чтение из Socket вернёт текст запроса. Есть два способа читать из readable-потока: подписаться на событие data или вызвать метод .read(). Сначала посмотрим на первый:

JavaScriptconst net = require('net');
const server = net.createServer();
server.on('connection', handleConnection);
server.listen(3000);

function handleConnection(socket) {
  socket.on('data', (chunk) => {
    console.log('Received chunk:\n', chunk.toString());
  });
  socket.write('HTTP/1.1 200 OK\r\nServer: my-web-server\r\nContent-Length: 0\r\n\r\n');
}

Положите этот код в файл server.js и запустите из командной строки: node server.js. В другом терминале отправьте простой запрос через cURL:

Bashcurl -v localhost:3000/some/url

Подробный вывод cURL показывает заголовки запроса и ответа, а в терминале Node видно что-то вроде:

ConsoleReceived chunk:
GET /some/url HTTP/1.1
Host: localhost:3000
User-Agent: curl/7.54.0
Accept: */*

Отправим POST-запрос с данными:

Bashcurl -v -XPOST -d'hello=world' localhost:3000/some/url

Если бы тело запроса было длиннее, вы получали бы его несколькими кусками (chunks). Но веб-серверу не всегда нужно обрабатывать тело запроса. Часто заголовков достаточно, чтобы начать обработку. Поскольку мы пишем общий веб-сервер, нужно найти способ останавливать приём данных из сокета, как только во входе встретилась строка \r\n\r\n.

С методом .read() сокета это сделать проще, потому что мы сами решаем, когда прекратить вытягивать данные из потока. Код:

JavaScriptconst net = require('net');
const server = net.createServer();
server.on('connection', handleConnection);
server.listen(3000);

function handleConnection(socket) {
  // Один раз подпишемся на readable, чтобы можно было вызывать .read()
  socket.once('readable', function() {
    // Буфер для входящих данных
    let reqBuffer = new Buffer('');
    // Временный буфер для чтения кусков
    let buf;
    let reqHeader;
    while(true) {
      // Чтение данных из сокета
      buf = socket.read();
      // Нет данных — стоп
      if (buf === null) break;

      // Добавляем новые данные в буфер запроса
      reqBuffer = Buffer.concat([reqBuffer, buf]);

      // Дошли до \r\n\r\n? Это конец заголовка
      let marker = reqBuffer.indexOf('\r\n\r\n')
      if (marker !== -1) {
        // Дошли — за маркером могут быть данные; запомни их
        let remaining = reqBuffer.slice(marker + 4);
        // Заголовок — всё прочитанное до \r\n\r\n
        reqHeader = reqBuffer.slice(0, marker).toString();
        // Возвращаем лишние данные в поток сокета
        socket.unshift(remaining);
        break;
      }
    }
    console.log(`Request header:\n${reqHeader}`);

    // Отправляем общий ответ
    socket.end('HTTP/1.1 200 OK\r\nServer: my-custom-server\r\nContent-Length: 0\r\n\r\n');
  });
}

Код стал длиннее, потому что нужна логика решения, когда прекращать читать из потока. Это позволяет отделить заголовок от тела. Ключевая строка — socket.unshift: она возвращает в readable-поток все лишние прочитанные данные, так что при необходимости тот же сокет можно отдать пользователю для чтения.

Полный код базового веб-сервера

Вот полный код нашего базового веб-сервера, собирающий всё, что мы видели. Сервер предоставляет функцию createWebServer(requestHandler), принимающую обработчик вида (req, res) => void — точь-в-точь как базовый веб-сервер Node. Комментарии в коде объясняют каждый шаг:

JavaScriptconst net = require('net');

function createWebServer(requestHandler) {
  const server = net.createServer();
  server.on('connection', handleConnection);

  function handleConnection(socket) {
    // Один раз подпишемся на readable, чтобы можно было вызывать .read()
    socket.once('readable', function() {
      // Буфер для входящих данных
      let reqBuffer = new Buffer('');
      // Временный буфер для чтения кусков
      let buf;
      let reqHeader;
      while(true) {
        // Чтение данных из сокета
        buf = socket.read();
        // Нет данных — стоп
        if (buf === null) break;

        // Добавляем новые данные в буфер запроса
        reqBuffer = Buffer.concat([reqBuffer, buf]);

        // Дошли до \r\n\r\n? Это конец заголовка
        let marker = reqBuffer.indexOf('\r\n\r\n')
        if (marker !== -1) {
          // За маркером могут быть данные; запомни их
          let remaining = reqBuffer.slice(marker + 4);
          // Заголовок — всё прочитанное до \r\n\r\n
          reqHeader = reqBuffer.slice(0, marker).toString();
          // Возвращаем лишние данные в readable-поток сокета
          socket.unshift(remaining);
          break;
        }
      }

      /* Работа с запросом */
      // Начинаем разбор заголовка
      const reqHeaders = reqHeader.split('\r\n');
      // Первая строка особенная
      const reqLine = reqHeaders.shift().split(' ');
      // Остальные строки — заголовки; строим из них объект
      const headers = reqHeaders.reduce((acc, currentHeader) => {
        const [key, value] = currentHeader.split(':');
        return {
          ...acc,
          [key.trim().toLowerCase()]: value.trim()
        };
      }, {});
      // Этот объект отправляется в callback обработчика запроса
      const request = {
        method: reqLine[0],
        url: reqLine[1],
        httpVersion: reqLine[2].split('/')[1],
        headers,
        // Пользователь этого веб-сервера может читать тело запроса прямо из сокета
        socket
      };

      /* Работа с ответом */
      // Начальные значения
      let status = 200, statusText = 'OK', headersSent = false, isChunked = false;
      const responseHeaders = {
        server: 'my-custom-server'
      };
      function setHeader(key, value) {
        responseHeaders[key.toLowerCase()] = value;
      }
      function sendHeaders() {
        // Делаем это только один раз :)
        if (!headersSent) {
          headersSent = true;
          // Добавляем заголовок даты
          setHeader('date', new Date().toGMTString());
          // Отправляем строку статуса
          socket.write(`HTTP/1.1 ${status} ${statusText}\r\n`);
          // Отправляем каждый из следующих заголовков
          Object.keys(responseHeaders).forEach(headerKey => {
            socket.write(`${headerKey}: ${responseHeaders[headerKey]}\r\n`);
          });
          // Финальный \r\n, отделяющий заголовки от тела
          socket.write('\r\n');
        }
      }
      const response = {
        write(chunk) {
          if (!headersSent) {
            // Если content-length нет, указываем Transfer-Encoding chunked
            if (!responseHeaders['content-length']) {
              isChunked = true;
              setHeader('transfer-encoding', 'chunked');
            }
            sendHeaders();
          }
          if (isChunked) {
            const size = chunk.length.toString(16);
            socket.write(`${size}\r\n`);
            socket.write(chunk);
            socket.write('\r\n');
          }
          else {
            socket.write(chunk);
          }
        },
        end(chunk) {
          if (!headersSent) {
            // Полную длину ответа мы знаем; установим её
            if (!responseHeaders['content-length']) {
              // Считаем, что chunk — буфер, а не строка!
              setHeader('content-length', chunk ? chunk.length : 0);
            }
            sendHeaders();
          }
          if (isChunked) {
            if (chunk) {
              const size = (chunk.length).toString(16);
              socket.write(`${size}\r\n`);
              socket.write(chunk);
              socket.write('\r\n');
            }
            socket.end('0\r\n\r\n');
          }
          else {
            socket.end(chunk);
          }
        },
        setHeader,
        setStatus(newStatus, newStatusText) { status = newStatus, statusText = newStatusText },
        // Удобный метод для отправки JSON через сервер
        json(data) {
          if (headersSent) {
            throw new Error('Headers sent, cannot proceed to send JSON');
          }
          const json = new Buffer(JSON.stringify(data));
          setHeader('content-type', 'application/json; charset=utf-8');
          setHeader('content-length', json.length);
          sendHeaders();
          socket.end(json);
        }
      };

      // Отправляем запрос обработчику!
      requestHandler(request, response);
    });
  }

  return {
    listen: (port) => server.listen(port)
  };
}

const webServer = createWebServer((req, res) => {
  // Это наш исходный код на модуле http :)
  console.log(`${new Date().toISOString()} - ${req.method} ${req.url}`);
  res.setHeader('Content-Type','text/plain');
  res.end('Hello World!');
});

webServer.listen(3000);

Как сказано в начале поста, этому серверному коду не место в проде; он только для изучения потоков и буферов.

Большая часть кода самоочевидна: разбираем запрос по правилам предыдущего раздела и отправляем ответ. Единственная новинка — Transfer-Encoding: chunked, нужная, когда длину ответа заранее не знаешь. Подробнее о chunked transfer encoding в Википедии.

Заключение

Используя низкоуровневые строительные блоки вроде net, Stream и Buffer, мы смогли собрать зачаточный HTTP-сервер на основе TCP-сервера и небольшой логики разбора. По пути немного узнали о том, как работают HTTP-запросы и ответы, а также об основах readable/writable-потоков и буферов.

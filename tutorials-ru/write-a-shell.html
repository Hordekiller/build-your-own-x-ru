Введение

Вы когда-нибудь задумывались, как работает этот терминал? (Точнее: как работает шелл?) Автор задался тем же вопросом и после «нескольких поисков и большого количества чтения» понял: сначала он написал базовый шелл на C, а затем навесил на него ещё несколько возможностей. Шелл, простыми словами, — «инструмент, через который вы взаимодействуете с операционной системой» — определение расплывчатое, но верное. Требования: знание C, gcc и текстовый редактор.

Основной цикл шелла

Эта функция — движущий мотор цикла. Прежде всего приглашение (>) сообщает пользователю о готовности шелла:

cvoid loop() {
    char *line;
    char **args;
    int status = 1;

    do {
        printf("> ");
        line = read_line();
        args = split_line(line);
        status = dash_execute(args);
        free(line);
        free(args);
    } while (status);
}

status хранит возвращаемое значение функций выполнения команд и определяет конец цикла: когда пользователь вводит exit, функция exit возвращает 0, и цикл разрывается. Две последние строки do-while через free() освобождают память двух указателей — явное освобождение памяти в C необходимо и является хорошей привычкой.

Чтение команд — read_line

Поскольку заранее нельзя знать длину команды пользователя, статическое выделение лишено смысла: память выделяется динамически и при необходимости увеличивается:

cchar *read_line() {
    int buffsize = 1024;
    int position = 0;
    char *buffer = malloc(sizeof(char) * buffsize);
    int c;

    if (!buffer) {                          /* malloc не удался */
        fprintf(stderr, "dash: Allocation error\n");
        exit(EXIT_FAILURE);
    }

    while (1) {
        c = getchar();
        if (c == EOF || c == '\n') {
            buffer[position] = '\0';
            return buffer;
        } else {
            buffer[position] = c;
        }
        position++;

        if (position >= buffsize) {         /* рост буфера */
            buffsize += 1024;
            buffer = realloc(buffer, buffsize);
            if (!buffer) {
                fprintf(stderr, "dash: Allocation error\n");
                exit(EXIT_FAILURE);
            }
        }
    }
}

При достижении EOF или \n возвращается строка с нулевым завершающим байтом; проверки if(!buffer) гарантируют, что в случае сбоя выделения (NULL от malloc/realloc) мы получим ошибку.

Токенизация ввода — split_line

Прочитанную команду разбиваем на токены (куски), чтобы её легко было выполнить. Работа строится на стандартной функции strtok: первый вызов возвращает первый токен, а каждый последующий вызов с аргументом NULL продолжает с того же места:

cstr1 = strtok("this is it!", " ");
// str1 -> "this"
str1 = strtok(NULL, " ");
// str1 -> "is"
str1 = strtok(NULL, " ");
// str1 -> "it!" 
c#define TOK_DELIM " \t\r\n"
#define TK_BUFF_SIZE 1024

char **split_line(char *line) {
    int buffsize = TK_BUFF_SIZE, position = 0;
    char **tokens = malloc(buffsize * sizeof(char *));
    char *token;

    if (!tokens) {
        fprintf(stderr, "dash: Allocation error\n");
        exit(EXIT_FAILURE);
    }
    token = strtok(line, TOK_DELIM);
    while (token != NULL) {
        tokens[position] = token;
        position++;
        if (position >= buffsize) {
            buffsize += TK_BUFF_SIZE;
            tokens = realloc(tokens, buffsize * sizeof(char *));
            if (!tokens) { /* ... */ }
        }
        token = strtok(NULL, TOK_DELIM);
    }
    tokens[position] = NULL;
    return tokens;
}

Выход — dash_exit и выполнение команд — dash_execute

Тривиальная функция, возвращающая 0, чтобы закрыть цикл; а в dash_execute сначала проверяется, является ли команда exit (для читаемости выделена отдельная функция). Если нет — fork() копирует текущий процесс («дочерний», идентичный родительскому, кроме идентификатора), и возвращаемое значение говорит, где мы: 0 — дочерний, pid дочернего — родительский:

cint dash_execute(char **args) {
    pid_t cpid;
    int status;

    if (strcmp(args[0], "exit") == 0) {
        return dash_exit(args);
    }

    cpid = fork();

    if (cpid == 0) {
        /* Дочерний: execvp заменяет образ процесса нужной программой;
           при неудаче возвращает -1 */
        if (execvp(args[0], args) < 0)
            printf("dash: command not found: %s\n", args[0]);
        exit(EXIT_FAILURE);

    } else if (cpid < 0) {
        printf("Error forking\n");
    } else {
        waitpid(cpid, &status, WUNTRACED);
    }
    return 1;
}

int dash_exit(char **args) {
    return 0;
}

waitpid гарантирует, что дочерний процесс завершится до того, как шелл вернётся к приглашению.

Полный код и результат

Весь код выше — вместе с прототипами, определением TOK_DELIM, цветными макросами ошибок и main(), который просто вызывает loop() — образует полноценный базовый шелл. Это упражнение «для обучения», а не продукт: «вероятно, вы никогда не захотите пользоваться таким примитивным шеллом, но теперь вы знаете, как работают под капотом ваши любимые шеллы».

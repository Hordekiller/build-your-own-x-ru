Что такое шелл и как он работает?

Простыми словами: «шелл — это интерфейс, который позволяет вам взаимодействовать с ядром операционной системы». Рабочий цикл шелла таков: запуск ← ожидание ввода пользователя ← разбор ввода ← выполнение команды и возврат результата ← возврат к шагу 2.

Но есть один важный момент: процессы. Шелл — родительский процесс (главный поток, ожидающий ввода), но команду нельзя выполнять в самом main; потому что (1) сломанная команда обрушит весь шелл — этого хотим избежать; и (2) независимые команды должны иметь собственный процессный блок — эта «изоляция» часть отказоустойчивости.

Понимаем fork на четырёх строках кода

Автор говорит: «я думал, что понимаю fork, пока не написал с ним четыре строки кода». fork создаёт копию текущего процесса (называемую child), и у каждого процесса есть уникальный идентификатор (pid):

c#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    pid_t child_pid = fork();

    if (child_pid == 0) {   /* дочерний процесс */
        printf("### Child ###\nCurrent PID: %d and Child PID: %d\n",
               getpid(), child_pid);
    } else {                /* родительский процесс */
        printf("### Parent ###\nCurrent PID: %d and Child PID: %d\n",
               getpid(), child_pid);
    }
    return 0;
}

Системный вызов fork возвращается дважды — по разу для каждого процесса! Это кажется противоречивым, но за кулисами всё просто: fork создаёт копию текущего процесса, и в родителе значение child_pid — это pid только что созданного дочернего; в самом же дочернем оно равно 0, потому что у дочернего нет детей. Сразу после fork оба процесса выполняются одновременно, и порядок выполнения зависит от планировщика ОС. Пример вывода:

text### Parent ###
Current PID: 85247 and Child PID: 85248
### Child ###
Current PID: 85248 and Child PID: 0

(Примечание: pid дочернего обычно больше, но это не гарантировано — ОС может переиспользовать старые идентификаторы.)

Определённость с wait, а не со sleep

С sleep(1) в родительском блоке дочерний почти всегда выполняется первым, и вывод становится определённым; но sleep — плохое решение: (1) какая гарантия, что ожидаемое завершится за n секунд? (2) если оно завершится раньше, мы зря простаиваем. Правильный путь — системный вызов wait, а лучше waitpid с тремя параметрами: pid ожидаемого процесса, переменная, заполняемая статусом завершения, и настраиваемые флаги:

c#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t child_pid, wait_result;
    int stat_loc;

    child_pid = fork();
    if (child_pid == 0) {
        printf("### Child ###\nCurrent PID: %d and Child PID: %d\n",
               getpid(), child_pid);
        sleep(1);
    } else {
        wait_result = waitpid(child_pid, &stat_loc, WUNTRACED);
        printf("### Parent ###\nCurrent PID: %d and Child PID: %d\n",
               getpid(), child_pid);
    }
    return 0;
}

Родитель ждёт завершения дочернего процесса, а затем выполняет свои команды.

Выполнение команд с execvp

Семейство exec включает execl, execv, execle, execve, execlp и execvp. Мы берём execvp: «vp» означает, что он принимает имя файла и ищет его в переменной $PATH системы, вместе с массивом аргументов. Выполнение ls -l -h -a:

c#include <unistd.h>

int main() {
    char *argv[] = {"ls", "-l", "-h", "-a", NULL};
    execvp(argv[0], argv);
    return 0;
}

Три замечания: первый аргумент — имя команды; второй — имя команды вместе с её аргументами и должен заканчиваться NULL; и execvp заменяет образ текущего процесса нужной программой — при успехе никогда не возвращается.

Разбор ввода и основной цикл

Ввод разбивается через strtok по разделителю-пробелу и строится массив, заканчивающийся NULL; затем в бесконечном цикле: ввод получаем через readline, делаем fork, дочерний вызывает execvp, а родитель — waitpid:

cchar **get_input(char *input) {
    char **command = malloc(8 * sizeof(char *));
    char *separator = " ";
    char *parsed;
    int index = 0;

    parsed = strtok(input, separator);
    while (parsed != NULL) {
        command[index] = parsed;
        index++;
        parsed = strtok(NULL, separator);
    }
    command[index] = NULL;
    return command;
}

int main() {
    char **command, *input;
    pid_t child_pid;
    int stat_loc;

    while (1) {
        input = readline("unixsh> ");
        command = get_input(input);

        child_pid = fork();
        if (child_pid == 0) {
            execvp(command[0], command);   /* при успехе не возвращается */
            printf("This won't be printed if execvp is successful\n");
        } else {
            waitpid(child_pid, &stat_loc, WUNTRACED);
        }
        free(input);
        free(command);
    }
    return 0;
}

Замечание: fork вызывается только после ввода команды; значит, родительский процесс — тот, что показывает приглашение. С этим кодом (компиляция через gcc -g -lreadline shell.c) у вас есть рабочий минимальный шелл, выполняющий pwd и ls -lha.

Обработка ошибок

  • fork — если система исчерпала память или достигла предела числа процессов, возвращается -1: perror("Fork failed"); exit(1);
  • execvp — возвращается только при неудаче: if (execvp(...) < 0) { perror(command[0]); exit(1); } — этот exit убивает только дочерний процесс.
  • malloc — может вернуть NULL: ошибка и выход.
  • Буфер аргументов — всего 8 блоков; команды длиннее восьми слов работают неправильно (упражнение для читателя).

Дополнительные упражнения: если дать дочернему sleep, вывод родителя печатается немедленно, а потом вывод дочернего вываливается в середину терминала — потому что родителю после printf больше нечего делать, и он умирает.

Встроенные команды — история cd

Выполнение cd в новом шелле даёт ошибку «No such file or directory»; потому что cd — не системная программа вроде ls. Допустим, она была бы: происходит fork, команда выполняется в дочернем и завершается, а рабочий каталог родителя остаётся нетронутым — то есть cd, хоть и успешный, не даёт желаемого результата! Поэтому реализуем его сами и выполняем напрямую, без fork:

cint cd(char *path) {
    return chdir(path);
}

/* в цикле main */
if (strcmp(command[0], "cd") == 0) {
    if (cd(command[1]) < 0) {
        perror(command[1]);
    }
    continue;   /* не делаем fork */
}
